# Isolated shared-point tensor candidate

Root has since adopted these exact candidate bytes in the research branch.
See the [adoption record](../../docs/research/100bit-spend-path-20261013/evidence/shared-point-adoption-20261015/README.md).
The preparation and measurement notes below describe the isolated experiment.

This directory contains an isolated candidate for `crates/aspis-r1-cost-probe/src/weights.rs`.
It is not installed in the runtime crate. It has been compiled and measured in a
separate NUC workspace; the complete local evidence is in
`docs/research/100bit-spend-path-20261013/evidence/shared-point-contraction-v152-20261015/`.

`weights.baseline.rs` is the pinned source copy (SHA-256
`eb55a5a954f611828f03615a837a9298352a44a1c799a3e7726f8e1421c8d81a`).
`weights.candidate.rs` (SHA-256
`68c9087712ff6bfb08c7ed41a1281798466e6671800761c80f83126963262f63`) is the
proposed replacement. `weights-shared-point.patch` (SHA-256
`ad920d72daf96fc26e896badc9f4e5ac5234e8d77f92f191aeb1d5932cd5392f`) records
the complete diff.

The candidate activates only for `Variant::S2`, two folds, and equality of the
`d2` and `d3` factor vectors for point rows 0 and 2. Under that explicit guard,
it contracts the common 16-entry `d2/d3` tensor once per each of four `d4`
slices, then contracts those four partials separately with each row's `d4`
factors and applies that row's existing `d0/d1` scalar factors. The existing
per-row computation remains active whenever the guard is false, including for
other variants/fold counts and arbitrary constructed `Weights` with unequal
high factors.

The isolated native differential and SBF/LiteSVM cost measurements are recorded
in the linked evidence directory. They do not establish protocol correctness,
general semantic equivalence, or production readiness. Root review is required
before runtime use.

A transient rustfmt-only rewrite of the live `weights.rs` was found during
follow-up work. The exact rewritten bytes are retained as
`weights.rustfmt-drift.snapshot.rs` (SHA-256
`17eb6eea970aa4e7cda9b50ba0212c636f51e108bc0f655a81be8e252c963bc0`). The
live file was restored byte-for-byte to the pinned baseline; the candidate was
regenerated by applying the recorded patch to that baseline.

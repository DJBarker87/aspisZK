# R427 launch-gated diagnostic runner (prepared only)

This directory contains an unlaunched runner and a saved-output auditor. Neither a build nor an extraction was run while preparing it.

The runner is derived from the saved R396 invocation. It loads R396's exact `start_from`, ordered `include` list, Rust flags/hash, Cargo flags/features, and frozen source hashes from `.r21-scratch/r396-private-batch-unmonomorphized-plan/extract-command.json`. It changes the Charon executable to the observer candidate wrapper, sets `ASPIS_R427_OBSERVE_MIR=1`, and uses a new destination `R427RawMirCapture.llbc`. It does not add `--print-original-ullbc` or change the source root, monomorphization mode, include ordering, or Cargo release/offline/locked/jobs1 settings. R396 baseline SHA is pinned as `399020435e94aaa7135c06d68445e9b936bd22fe6d1e1d197ee708d448d584ae`.

Before any launch, the runner requires both `R427_ALLOW_LAUNCH=1` and an exact reviewed build receipt path+SHA. It fails closed unless the receipt says build exit 0, `reviewed=true`, the pinned Charon source commit and rustc commit, the unchanged wrapper SHA `b2b0961a3c55aca64752b2fa4a4701ba0c06b860236979e5727c07de8ac2310c` at `observer-bin/charon`, plus the candidate driver at `observer-bin/charon-driver`, original driver SHA `4cb603ad51132f298a63a9c2a8cc8c629c73edeff22516fbf56ba5decee70938`, and pinned Cargo.lock SHA. It also requires the candidate driver and exact candidate `get_mir.rs` SHA `246d1fec2223d8ad5755e4aa9f24e647af7c16a18a8a2d893d9085213bf8a9ab` and reviewed patch hash. The local R396 `toolchain.txt` is the original-driver hash authority; the pinned rustc binary and commit are checked locally against that saved R396 record and remotely by the wrapper-reported toolchain and `rustc -Vv`. The build receipt schema is stated in `build-receipt-required-fields.json`; no receipt exists yet, so the gate cannot currently pass.

At launch, the remote script rechecks all seven selected-source hashes, R396 baseline hash, observer wrapper+driver hashes, rustflags, pinned Cargo.lock, and host reservations. It confirms the exact R396-pinned rustc binary by running `rustc -Vv` and checking its commit hash. It requires no active `aspis` slice processes, no other running `aspis*` user services (excluding the current capture unit), and no heavy build/translation processes, at least a 24 GiB post-job memory reserve, and runs in `systemd-run --user --wait --collect --pipe` with `MemoryHigh=5G`, `MemoryMax=7G`, `MemorySwapMax=0`, and `TasksMax=128`. The payload records its own effective cgroup path and actual memory/pids limits, events, current/peak/swap counters before and after. Original Charon binaries are copied and hashed remotely; the large binaries are not transferred to the workstation. The SSH command passes the multiline Python payload as one shell-quoted remote command.

Remote preflight/extraction failures retain launch status, SSH output hash and any partial remote files that exist. The one-shot runner refuses to launch if a prior local saved-output directory exists. The saved-output auditor writes a failure report when required saved inputs are absent and permits exactly two field-specific normalizations: `translated.options.dest_file` (the sole options difference) and the order of `translated.short_names` after checking exactly 347 unique entries with identical key/value mappings. All other native fields, lists, types, bodies, and order must compare exactly. It rejects any other options delta. It also checks actual `/proc/self/cgroup` high/max/swap/task settings, event counters, and peak values against the requested scope; it verifies GNU-time metrics, `has_errors=false`, and candidate-build/stdout/stderr checksums. Missing outputs produce an audit failure report instead of an uncaught file read. It also requires exactly one complete stderr frame for `core::iter::traits::iterator::Iterator::try_fold`, matching begin/end DefId, and the explicit statement-source, Use-retag, terminator-source, and call-argument markers. It writes the full frame and JSON report while leaving the original logs untouched.

This is a preparation artifact only. The raw MIR capture, equality audit, resource receipt and error/result inventory remain future outputs. No MIR/source correspondence theorem or other proof claim is implied.

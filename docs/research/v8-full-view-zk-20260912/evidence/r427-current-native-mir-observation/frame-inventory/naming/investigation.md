# Attempt-B zero-marker naming investigation

## Finding

Attempt B completed Charon successfully (`result_exit_status: 0`, GNU-time exit 0), but the saved-output audit reports `begin_count: 0`, `end_count: 0`, and no statement-source, Use-retag, terminator-source, or Call-argument markers. The capture output is therefore a valid LLBC extraction with no selected diagnostic frame. No `def_path_str` value for the candidate item was recorded on the failed exact-name branch, so the precise runtime mismatch is not established by this run.

The pinned rustc pretty-printer source establishes a concrete potential formatting hazard: `TyCtxt::def_path_str` is expressly documented as a string suitable for user output; its formatter may trim paths and choose visible public reexports when arguments are empty. The same source provides the scoped controls `ty::print::with_no_trimmed_paths!` and `ty::print::with_no_visible_paths!`. The current canonical-selector draft applies both and checks the expected full path. This is a source-supported selector normalization, but the no-frame attempt alone does not prove trimming/visible-path substitution was the actual cause.

The Hax `ItemRef` representation does not store a display-name string. It stores a `DefId`, generic args, trait proofs, optional in-trait proof, and parameter flags. In pinned `get_mir.rs`, the MIR lookup branches on the `DefId` base, then for a real definition queries `tcx.optimized_mir(rust_def_id)`; when monomorphization is disabled, it returns the body without substituting `item_ref.rustc_args`. Thus the observer's Rustc `DefId` formatter and LLBC/Hax declaration naming are separate representations. The saved source does not show that the LLBC path string must equal the formatted Rustc path string.

The wrapper path check is orthogonal: the pinned `toolchain.rs` computes `driver_path` with `current_exe().with_file_name("charon-driver")`, so running the candidate wrapper uses its adjacent candidate driver. Attempt-B result confirms the candidate wrapper/driver paths and hashes. This pairing does not explain the absent name-match markers.

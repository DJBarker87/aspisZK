# R349 / R351 evidence bundle

This bundle combines the exact R349 build receipt and R351 translation failure with the final independent source-tree and inode audit. `audit.json` is the compact result. The original preparation-era `candidate-audit.json`, `structural-check.json`, `README.md`, manifests and clone inventories are retained under names ending in `prebuild` or otherwise called out as historical; those files predate the successful build and must not be read as the final run status. `r349-build/build-result.json`, `r349-launch-history/launch-result.json`, and `r351-translation/result.json` are the run records.

`r349-parent-current-source-manifest.json` and `r349-candidate-current-source-manifest.json` were captured after the build. `r349-postbuild-tree-comparison.json` compares the final patched pre-build tree with the post-build tree: 119 changed paths, all in `_build`, zero source changes. `r349-postbuild-source-inode-audit.json` records the final parent/candidate shared regular-file inode count. Exact parent and candidate `TranslateCore.ml`, the preparation script and root launch log are included. `formatting-diff-check-audit.json` records no whitespace findings for the source diff or the copied logs; source-diff exit status 1 means the files differ, not that a whitespace issue was found.

R349 was only a compiler build. R351 is an incomplete translation failure and the partial output is preserved byte-for-byte. Neither run is a Lean result or a source-semantics/security conclusion. The R347 caveat is retained: the Charon symlink in an isolated tree was dangling and the Charon library linked by the earlier binary was not identified.

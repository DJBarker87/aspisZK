# Proposed next pointer proof route (unverified)

The missing R193 load premise cannot be introduced as an oracle assumption. The actual constructor is now exposed in R431, output df9180ee7c9959a7840d6edac0b756f007ef33ed0bd88bb36faf57a3e18f2358, functions43/86, actual fold70. R430's constant graph can supply the selected non-ZST branch only within its explicit source/primitive boundary.

Proposed proof scope is a typed immutable allocation fragment with thin pointers carrying both address and allocation/byte-offset provenance, stride16 and alignment4 from the selected target layout. Pointer equality compares addresses; it must not compare allocation IDs. Addition scales the element count by16 and preserves provenance. Unsigned pointer difference must admit equal-address zero distance as well as the same-allocation nonnegative difference case. Loads require initialized readable cells; a one-past pointer is valid for arithmetic but not loads. Heap immutability during the counted callback needs a source frame/borrow argument, not an assumed arbitrary load function.

Empty slices are a required case. They may have a non-null aligned dangling pointer and no live allocation. Addition by zero must preserve that pointer without requiring an allocation. The constructor obtains identical start/end, and the fold returns init without loading, differencing, or invoking the closure. Do not rule these slices out by a strengthened premise.

For nonempty slices, a shared slice validity relation must identify the actual initialized cell range in one live allocation, with no address wrap and total allocation extent within signed pointer offset bounds. It must be connected to the existing source shared-slice/Vec interpretation, not left as an unexplained whole-fold premise. From this relation derive every in-bounds source load equals its corresponding list cell and every source pointer/index UB precondition holds. Preserve primitive diagnostic/unsupported cases separately from actual Rust Error/abort outcomes; do not invent failure semantics outside a proved fragment.

The proposed fragment is not yet implemented, compiled or shown to match Rust/LLBC. No pointer contract is released or assumed. Before claiming source execution, bind the exact native constructor and fold AST operations to the interpreter, justify its primitive rules from the pinned source/compiler boundary, prove the closure restores captured power and does not mutate slice storage, prove drops/checks/unwinds unreachable where justified or model them explicitly, and discharge the actual unchecked_add rule. Reuse existing arithmetic/closure/control proofs without unchanged replays. Vec::extend and Domain inverse remain independent gaps.

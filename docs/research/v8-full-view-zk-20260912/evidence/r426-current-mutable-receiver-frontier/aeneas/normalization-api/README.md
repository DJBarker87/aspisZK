# R426 normalization API inventory (read only)

This report inventories pinned AST constructors and existing transformation utilities relevant to a possible call-receiver normalization. It makes no repair choice and contains no source edit, build, or premise decision. A receiver rewrite must preserve source local reuse and borrow lifetime; this inventory does not justify replacing Copy with Move.

## Input occurrence and MIR phase boundary

The exact R419 call operand is recorded in the companion `.r21-scratch/r426-mutable-borrow-copy-frontier/llbc/R419-selected-functions.json`: FunDecl 58, loop top-level statement 6 / loop statement 1 (statement id 4440), call arg 0 is Copy(Local 1). Local 1 is the input `self : Ref(Body 1, Deduplicated 10, Mut)`. The translator span points to the Iterator::next trait method declaration, not the try_fold body. The R396 analog has the same operand shape. r241's report notes that R396's `--mir built` command/log did not retain a Rustc MIR dump, so neither capture identifies the upstream MIR temporary.

Pinned Charon source answers the `--mir built` question. In `get_mir.rs`, requested `MirLevel::Built` is dispatched only for `rust_def_id.as_local()`. For a non-local standard-library method, Charon checks `tcx.is_mir_available`; if true for a function, it calls `tcx.optimized_mir(rust_def_id)` (lines 89–115). The source comments that standard-library MIR is available only for const items and generic or inlineable functions; the captured Iterator::try_fold LLBC body being structured confirms a body was available, though the artifact has no MIR dump. Thus `--mir built` does not imply this foreign body came from `mir_built`.

Pinned Charon's driver sets `always_encode_mir=true`, `mir_opt_level=0`, and `mir_preserve_ub=true`. Pinned Rustc nightly source shows optimized MIR starts from drop-elaborated MIR, and runtime lowering calls EraseDerefTemps. That pass converts `CopyForDeref(place)` to `Use(Copy(place), WithRetag::No)`, with a comment that this temporary read may copy a mutable reference that cannot actually be copied. The exact source also shows an `InstSimplify` pass that, when enabled, rewrites `&(*a)` to `Use(Copy(base), WithRetag::Yes)` except two-phase borrows (`instsimplify.rs:144–168`). `InstSimplify` is disabled when `mir_opt_level` is zero, but a foreign sysroot method is queried through `optimized_mir`, not a local `mir_built` query; the precise R419 predecessor is unavailable without its MIR dump. Both compiler idioms are documented, neither is attributed to the captured operand.

The pinned Rust core source confirms the relevant source expression: `try_fold` requires `Self: Sized` and its loop calls `self.next()` at `iterator.rs:2486–2494`. That is consistent with an implicit mutable receiver reborrow candidate. This source expression plus LLBC type/path is not a substitute for the missing exact MIR. The source hash is recorded in `source-hashes.txt`.

## Existing allocation and statement-sequence APIs

Aeneas has two current `PrePasses.ml` passes that construct `RvRef` assignments while introducing locals.

- `decompose_str_borrows` (lines 2590–2734) allocates IDs using `LocalId.mk_stateful_generator_starting_at_id (LocalId.of_int (List.length body.locals.locals))`, appends local records `{ index; local_ty; name=None; span=f.item_meta.span }`, and inserts an assignment with original `st.span`, `statement_id=StatementId.zero`, and `comments_before=[]`. It constructs `RvRef(place, bkind, metadata)`, where `bkind` is selected from the original reference mutability, then passes `Move new_ref_local` to the replaced operand. Its documented use is string-literal references; this is an existing construction idiom, not an implemented call-receiver normalizer.
- `decompose_global_accesses` (lines 2853–2970) makes `TRef(RErased, ty, RShared)` locals, builds `RvRef(global_place, BShared, Constant mk_unit_const)`, and rewrites globals as `PlaceProjection(local_ref, Deref)`. Its statement visitor visits regular-call args too and inserts the required borrow assignment before the original statement.

Both use `map_statement` to replace one source statement with a statement list; Charon `LlbcAstUtils.map_statement` maps nested statements and flattens each replacement list in block order. Both append generated local declarations to `body.locals.locals`. Aeneas `refresh_statement_ids` later replaces every statement ID with a fresh one. In the pipeline it occurs last among function-level passes, after these temporary-generating passes. Existing passes use zero IDs for fresh statements; they do not preserve duplicate IDs.

The relevant Charon AST shapes are explicit: `Place={kind; ty}`; `PlaceProjection(place, Deref)` is a legal deref place; `RvRef(place, BorrowKind, ptr_metadata_operand)` carries three fields; `BorrowKind::Mut` maps to Aeneas `BMut`. A call record contains `func`, `args`, and `dest`; an LLBC statement carries `span`, `statement_id`, `kind`, and comments. Local records use local ID, optional name, span, and type. `LocalId.mk_stateful_generator_starting_at_id` returns a stateful ID generator initialized to its supplied ID.

Aeneas `eval_rvalue_not_global` matches `RvRef(p, bkind, _)` and discards `ptr_metadata`, then calls `eval_rvalue_ref` with only place and borrow kind. `eval_rvalue_ref` implements `BMut` by reading the place with write access, creating `VMutBorrow`, and replacing the source place with `VMutLoan`. Thus the ordinary reference-rvalue evaluator ignores the metadata operand. Separately, an attempted `PtrMetadata` place projection has no matching case in `InterpPaths.project_value`; it reaches the generic Inconsistent projection error. The narrow metadata-only slice prepass removes one specific shared-slice pattern before evaluation; it is not general pointer-metadata evaluation.

## Distinct Rust lowering patterns

The two relevant Rustc transformations are distinct. `deref_separator.rs` may introduce a temporary with `CopyForDeref` when a place contains an intermediate dereference; `erase_deref_temps.rs` later turns that assignment into a no-retag `Copy`. Separately, `InstSimplify::simplify_ref_deref` rewrites a reference/raw-pointer rvalue shaped like `&(*a)` to `Use(Copy(base), WithRetag::Yes)` (or `No` for a two-phase mutable borrow). That pass is gated by `mir_opt_level() > 0`, while the pinned Charon driver sets the session MIR optimization level to zero. However, the foreign method is obtained using `optimized_mir`, and there is no saved MIR dump or query result recording the exact pre-query optimization history for this declaration. Therefore this inventory cannot attribute R419's Copy operand to either pattern, nor identify a different source MIR predecessor.

## Scope and limits

A source search over R425 `PrePasses.ml` finds only the string-literal and global-access passes inserting `RvRef`; no current pass inserts a mutable receiver reborrow into a call argument. Charon call argument lowering and MIR selection excerpts, Rustc MIR excerpts, exact R425 constructor/pass excerpts, and the exact `try_fold` source excerpt are preserved alongside this README. This is an API inventory only: it does not specify which mutability/metadata/span should be used for a new temporary, whether a local copy is a reborrow, how liveness is preserved, or which source semantics a future transform should implement.

# R327 focused source extraction preparation

This directory contains a prepared, unlaunched runner for the lead-selected source extraction. It clones the R297 monomorphized private-batch extraction configuration, retains its frozen source hashes, root, security-feature set, RUSTFLAGS, offline/locked release Cargo options, one job, and `--monomorphize`, then adds only the four narrow include patterns preserved in R322's candidate inventory: `Iterator::try_fold`, `ControlFlow::branch`, `ControlFlow::from_output`, and the selected `ControlFlow::from_residual` family.

The runner uses a fresh output directory, `aspis-r327-private-batch-source-try-fold-20261002-a`, and a fresh named systemd unit/slice with MemoryHigh 5G, MemoryMax 7G, MemorySwapMax 0, and TasksMax 128. It retains the frozen-file checksum preflight, host-memory/reservation snapshot, source `RUSTFLAGS` validation, complete Charon stdout/stderr timing log, result census, and after-run cgroup metrics. The source revision is read with `git rev-parse HEAD` at actual launch because the frozen remote source snapshot has no `.git` directory.

The toolchain receipt now records Charon's version, embedded toolchain channel and resolved sysroot, selected nightly rustc and Cargo versions, Charon and `charon-driver` hashes, and the selected `librustc_driver` hash/resolution. It asserts the pinned Charon SHA256 from R323, channel `nightly-2026-06-01`, and the observed selected rustc commit `14210df0e27ccd7d9e6a05b8085cbd438e4bbc65`. It does not record the host's stable-default rustc as the selected compiler.

The runner has an explicit `R327_ALLOW_LAUNCH=1` gate and was not run. `validate_plan.py` parses the runner and its embedded remote script, checks the four added include values appear with their `--include` flags, confirms the prior include sequence and required command flags, and writes `launch-plan.json`. Static validation does not test the Charon selection or assert an extraction outcome. Lead review is required before launch.

The extraction LLBC inputs, full logs, command receipts, runners, postflight diagnostics, rejected first attempts, and signature-failure source excerpts are retained.

The available R295 signature-failure inventory is included at `artifacts/r295-signature-failure-inventory/`; it retains the pinned Aeneas implementation file, Rust `iterator.rs`, and remote source excerpts. No Lean target was compiled in any archived stage, so every `#print axioms` field is `NOT APPLICABLE`.

R280 `decoded.json` was 34,987,246 bytes, SHA-256 `e28ef338…`. R280's compact `R280PrivateNormBatch.llbc` is retained. The standalone `tools/expand_r280_hashcons.py` reproduces the omitted pretty decoded view from that LLBC. I verified byte-for-byte reconstruction: 673 hash-cons table entries, zero cycles, zero missing IDs, identical byte length and checksum. The temporary reconstructed output was removed; it is not included in this candidate.

R283 is the valid source extraction, and its original Charon declaration order is already structurally usable. R292 emits the actual batch definition but still has six external template holes. The R293 and R295 failure artifacts remain intact; no failure is hidden or replaced. All batch/source execution, privacy, and security statements remain unproved. The first missing work is faithful concrete library traversal, followed by the shared inverse batch. This archive makes no generic semantic replacement or security/release claim.

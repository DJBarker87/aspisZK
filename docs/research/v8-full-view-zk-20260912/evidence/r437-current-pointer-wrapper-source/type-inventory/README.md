Selected declarations are exact native rows 58, 59, 69, 72, and 73 from both captures. The type-argument checks resolve declaration 58 as `NonNull<QM31>` (QM31 is type declaration 2), declaration 69 as `NonNull<[QM31]>`, and declaration 59 as `PhantomData<&QM31>`. The full rows retain their instantiated arguments, field type nodes, `Pattern` nodes, and attributes. In R437, the `pointer` field of type 58 is a `NotNull` pattern around a shared raw pointer to QM31; type 69 has the same pattern around a shared raw pointer to a QM31 slice. The type-59 struct has no fields. The complete hash-cons-expanded forms are included beside the exact encoded rows.

R437's recorded target is x86_64 with 8-byte pointers. Its layout metadata reports type 58 as size 8, alignment 8, field offset 0, transparent; type 69 as size 16, alignment 8, field offset 0, transparent; and type 59 as size 0, alignment 1, with no field offsets and nontransparent. These are the LLBC capture's layout records, not a separate ABI validation. R434 records the corresponding NonNull declarations as opaque. No field pattern has been discarded or treated as an unconstrained raw pointer.

`function-body-comparisons.json` compares full Fun70 and Fun86 rows after independently expanding each capture's hash-cons and deduplicated type references. It ignores only source span fields and statement IDs on recognized statement records. Both comparisons are equal with zero differences; no declaration-ID remapping or additional ignored field was needed. The exact selected function rows are also retained from both inputs.

This is an inventory of compiler-emitted declarations and layouts only. It makes no pointer validity, provenance, ABI theorem, or Rust semantic correspondence claim, and it performs no compilation or extraction.

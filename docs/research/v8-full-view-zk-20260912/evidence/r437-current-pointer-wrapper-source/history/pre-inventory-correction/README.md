# R437 pointer-wrapper source evidence

This package preserves the R437 focused LLBC capture, exact extraction/runner receipts, and the completed source and type inventories. The LLBC is stored as deterministic lossless gzip; `materialize.py` verifies and restores its exact original bytes in a fresh destination. `compression-manifest.json` records both hashes and byte counts.

The new capture is `R437PointerWrapperLayout.llbc` (SHA-256 `bafe9c1297a8ea92eaea3c37c685da3f5d3fe2e04c335ac9f1f4d64c4312386c`), captured at revision `77857d6028d1b4016949aa14b19c17282e2cec0c`. Its saved receipt reports Charon exit 0, `has_errors=false`, 15.09 seconds GNU wall time, 630164 KiB GNU peak RSS, zero swap, and terminal cgroup memory peak 495079424 bytes (the saved interim result records 397131776 bytes) with MemoryHigh 5368709120, MemoryMax 7516192768, MemorySwapMax 0, and TasksMax 128. The saved compiler/toolchain and source hashes are in `root-launch-a/saved-output/result.json`, command and runner files.

`type-inventory/selected-type-and-function-rows.json` retains the exact old R434 and new R437 rows and their independently expanded hash-cons types. Captured layout metadata reports NonNull<QM31> as size 8/alignment 8/field offset 0/transparent; NonNull<[QM31]> as size 16/alignment 8/field offset 0/transparent; and PhantomData<&QM31> as size 0/alignment 1 with no fields. The NotNull pointer patterns are retained. `function-body-comparisons.json` reports strict normalized equality of Fun70 and Fun86, expanding capture-local hash-cons/dedup data and ignoring only spans and statement IDs on statement records.

The prior R434 input and its hash are recorded in `input-references.json`; its exact selected rows are included in the type inventory. The completed `inventory/` directory also carries the bounded R430 primitive and source-support records. Formal proof axioms are not applicable to this diagnostic extraction. The imported Charon OCaml schema and JSON/Postcard decoders recognize and construct `TPattern(..., NotNull)`; the pinned Aeneas pure-type translator has no `TPattern` case and falls through to its unsupported-type branch. The layout rows are compiler metadata, not an ABI theorem, pointer validity/provenance result, cast theorem, source-execution proof, or security claim.

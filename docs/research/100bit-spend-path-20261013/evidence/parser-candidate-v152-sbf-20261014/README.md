# Candidate parser SBF rebuilt with pinned v1.52 toolchain

This is a focused rebuild of the candidate source using the Solana 3.1.13 `cargo-build-sbf` executable and cached platform-tools v1.52. The prior candidate build used the active-release v2.3.0 / platform-tools v1.48 installation. The toolchain change was identified after comparing the historical verifier artifact. The ELF-level comparison against the historical artifact is recorded in [`elf-versus-historical.json`](elf-versus-historical.json).

Before the build, only `source/crates/aspis-core/src/field.rs` was restored to the candidate bytes (SHA-256 `28df5a1a…f1baea`). The 751-entry candidate source manifest passed completely. The baseline/control field hash is `3046536d…453c68`. Build options matched the prior candidate run: features `pool-adapter,private-leaf-salts`, `--locked`, jobs 2. A new `cargo-target-v152` and `bin-v152-candidate` were used.

The focused release build exited 0 in 46.04 seconds, at the 4 GiB / 6 GiB / 0-swap cap, with cgroup peak 1,225,867,264 bytes and sampled aggregate RSS 1,266,700,288 bytes. The resulting ELF is 1,219,640 bytes, SHA-256 `fca47fb4…c56bea8`. At the time of this build, no LiteSVM cost gate had run. The later, separately scoped reuse gate passed; its stage-one and terminal measurements and settlement flags are recorded in [`parser-candidate-v152-cost-20261014`](../parser-candidate-v152-cost-20261014/README.md).

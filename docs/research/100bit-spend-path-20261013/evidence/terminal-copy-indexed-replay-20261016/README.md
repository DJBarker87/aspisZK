This bundle records an isolated source candidate at base revision `a8930e677bc745854b9f693b5628c8a8bd2ac848`, its newly built SBF, and LiteSVM R18 verifier-only comparisons against the retained baseline ELF. The candidate is not adopted in production.

The candidate SBF SHA-256 is `d346de4aa5a122f7ad0d2dde819ec416d2e479065490e5a84f970c534ea4220d`; the baseline SBF SHA-256 is `2c031d0040a3bf739b58591b2a20dc68f04722550fd49b79d4fd7eb8e5dfee9f`. Candidate sources are pinned in `evidence-export/candidate-source-pin-manifest.json`; the original 508-path NUC source snapshot manifest is preserved in `candidate-input-manifest-508.json`. The candidate overlay changes exactly three listed Rust source files.

The separate baseline manifest `baseline-source/after-manifest.json` pins 504 files at revision `42e5ca2011c39ee9770afc798282ff861b092428`. `source-manifest-git-comparison.json` and its script verify all 504 entries against Git objects. They also check all 508 entries from the candidate NUC source manifest against base revision `a8930e6…`: 505 match the base Git bytes and exactly the three declared candidate overlays differ.

The one-case transfer-1023 replay and four additional P3 cases use the current R18 3-account `[3,10]` verifier call followed by the 7-readonly-account ASQ8 call. Each fixture is hash-pinned and variant/index-pinned. For all four additional cases, both baseline and candidate accepted the pair; initial account images, checkpoint, and ASR8 bytes are equal. Stage2 CU is unchanged. Candidate stage1 deltas are −580 CU (transfer-13), −581 (transfer-255), −585 (withdrawal-255), and −591 (withdrawal-1023). The one-case transfer-1023 comparison is retained separately with −583 stage1 CU and no stage2 change.

These are verifier-only, preloaded-state comparisons. This harness does not execute the Pool CPI/settlement lifecycle. It does not measure registration/setup or establish a general compute bound. The branch already contains the current Pool checkpoint feature; end-to-end Pool integration remains outside these receipts.

The successful candidate SBF build ran with MemoryHigh=8 GiB, MemoryMax=10 GiB, and zero swap (the raw preflight and receipt are included); the harness binary build ran in a 6 GiB/zero-swap scope. The one-case and four-case verifier replays ran sequentially in 10 GiB maximum scopes with 8 GiB high watermark, zero swap, and 128 task limit. Its cgroup peak was 28,790,784 bytes and swap remained zero. Per-run `/usr/bin/time -v` logs are included. Baseline `/usr/bin/time` peak RSS was 673,404 KiB; candidate SBF peak RSS was 674,144 KiB. These are measurements of the recorded invocations only.

Reproduction inputs include the exact candidate base and overlay Rust files, three overlay patches, source pin manifest, source preparation script, Cargo manifest/lock, isolated verifier replay source, checkpoint comparator, and candidate runner. The candidate SBF runner is also preserved with its recorded command and full 508-path input manifest. The exact P3 proof/public files, complete public account images, `request-asq8.bin`, `expected-asr8.bin`, runtime feature list, stage instruction/result bytes, receipts, time logs, runner source, and input manifests are included. Keypairs are intentionally excluded; generated payer/checkpoint keys remain retained on the build host. The remote export used `--exclude='*.key' --exclude='*keypair*'`; `verify.py` additionally rejects any key-like files in this bundle.

Attempt history is retained separately: harness build attempts a and b failed before compilation (systemd scope invocation errors); attempt c succeeded. A first four-case script launch failed before replay because of a heredoc typo; the corrected script succeeded. An earlier native-gate attempt ended with `honest acceptance: Parse` for a fixture/profile mismatch and is not evidence about this candidate's R18 behavior.

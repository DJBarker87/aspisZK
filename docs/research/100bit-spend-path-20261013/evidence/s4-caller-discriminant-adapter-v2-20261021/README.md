# Caller discriminant adapter v2

This source-only candidate isolates the duplicate Aeneas-generated global discriminant instance names that appear when current-caller and finish-relation types are imported together. It removes `@[discriminant isize]` from seven discriminated caller enums and defines the same constructor-order-to-`isize` map explicitly. Each replacement instance is qualified beneath `_root_.AspisR1CurrentCaller.<type>.instDiscriminant`; the constructor declarations and other generated definitions remain unchanged. `check_adapter.py` reconstructs the original `AspisR1CurrentCaller.Types` source and verifies exact equality, constructor order, and ordinal mappings.

The missing formal-release metadata justified one focused replay of the adapted Types owner, its five dependent owners, and a combined import probe. The exact launch revision, Lean 4.32 binary hash, selected object pins, `LEAN_PATH`, argv, source-before/after hashes, object hashes, wall time, peak RSS, swap, and lock inode are in `evidence/complete-replay.json`, with per-target logs beside it. All seven targets exited 0, all source hashes remained unchanged, and swap was zero. The combined probe imports the adapted caller types, `S4TenQueryFieldResultsRootV1`, and `S4ConcreteKernelOpsRootV1`; its audited theorems depend only on `[propext, Classical.choice, Quot.sound]`.

Earlier uncaptured receipts and failed partial-adapter/import attempts remain in `evidence/` as diagnostics; they are superseded by the captured replay and are not used as proof receipts. `check_packet.py` validates the captured receipts, current source and external object pins, and that no compiled object is part of the packet. Local `.olean` outputs remain under ignored `objects/` for parent integration; do not commit them.

# Counted production pivot scan, verified on NUC

The counted fold returns exactly the pivot selected by both the existing list-form scan and the production in-place findPivotRowData. It visits exactly rows-start candidate rows, hence at most rows. This is an executable refinement and a concrete iteration count. It does not establish the whole dense elimination cost, field operations, cell accesses, array-copy behavior or bit complexity.

Lean4.32 checked the changed source on the dedicated Linux NUC using the pinned native CompPoly cache, with no dependency builds. Exit0; wall0.769s; process peakRSS1,632,415,744B; swap0. All three target theorems print only standard axioms. The cgroup had MemoryHigh6G, MemoryMax8G and MemorySwapMax0; the fresh admission inventory and exact command/preflight are retained. The sampled cgroup peak differs from process peakRSS because sampling missed this sub-second process peak; it is not a replacement peak measurement.

The source, original raw manifest/receipts/logs and full resolved native import closure are retained. Native object hashes are pinned but compiled binaries remain in the original task cache rather than Git. V1 failed only at a small additive induction equality; V2 fixes that proof and its superseded evidence is retained. No unchanged replay or full package build was performed.

This is the first cost component, not a proof of expected polynomial time for the complete spend extractor or of100-bit spend soundness. Full elimination/scalar root-finding/decoder/hash lookup and bit-cost composition remain open alongside the protocol and release obligations.

## Empty-root table

The frozen Rust table is `POOL_V1_PAIR_EMPTY_ROOTS_V1`, 21 rows, defined in [`pair_forest_semantic_terminal_constants.rs`](../../../crates/aspis-statement/src/pool_v1/pair_forest_semantic_terminal_constants.rs). Its corresponding Lean declaration is `R0P.emptyRootsNat` in [`EmptyRoots.lean`](../../../docs/research/v8-r0-sem-proof-20261008/lean/R0P/EmptyRoots.lean:9). That Lean file explicitly says the table is transcribed as Nat literals and proofs keep it opaque (lines 3–5; `emptyRootsNat` is marked irreducible at line 34). It has no theorem proving these rows are generated by iterated `nodeCompress`.

The Rust generator [`generate_pool_v1_pair_empty_roots.rs`](../../../crates/aspis-statement/examples/generate_pool_v1_pair_empty_roots.rs:7) defines `zero` as the all-zero eight-limb digest, sets row 0 to `pool_v1_tree_parent(&zero, &zero)` (line 10), then generates each of the 20 following rows by self-parenting (lines 11–12). `generated_pair_empty_roots_replay_exactly` in [`pair_forest_semantic_terminal.rs`](../../../crates/aspis-statement/src/pool_v1/pair_forest_semantic_terminal.rs:1462) repeats those equations and compares the result with `empty_root` (lines 1464–1470). This is a Rust generator/test correspondence, not a Lean theorem.

Consequently, the table's row 0 is a compressed pair of zero digests, not the all-zero digest itself. The pair-leaf model also treats slot zero as occupied by construction; see `PairLeaf` and `first_slot_is_spendable` in [`V7PairLeafOccupancy.lean`](../../../AspisFormal/AspisFormal/Pool/V7PairLeafOccupancy.lean:30). This occupancy statement does not prove a hash-table recurrence.

The R0P model defines `nodeCompress` in [`Semantics.lean`](../../../docs/research/v8-r0-sem-proof-20261008/lean/R0P/Semantics.lean:53) and the table-derived `emptyRootRightTarget` in `EmptyRoots.lean:36–43`. `digest_holds_iff` in [`Digest.lean`](../../../docs/research/v8-r0-sem-proof-20261008/lean/R0P/Digest.lean:222) relates a trace opening to that table-derived target. It does not establish that `emptyRootsNat` equals repeated `nodeCompress`. No such theorem was found in the inspected source snapshot.

## Append at capacity

The Rust `ValidatedIncrementalMerkleTreeV1::append_one` entrypoint rejects when the current `next_leaf_index` already equals capacity (`incremental_merkle.rs:181–184`). Otherwise it starts carry at level 0 and carries while the corresponding source-index bit is one (`:185–193`). If `leaf_index = 2^20 - 1`, all 20 bits are one: the loop reaches `carry_level == POOL_V1_TREE_DEPTH`, and the function sets the new root to the carry (`:194–197`) and returns success (`:211–225`). Thus the production append path includes the full-capacity append transition, with carry depth 20.

The older pair transition predicate `ExactPairAppendTransition` in [`V7PairAppendAfterstateCorrect.lean`](../../../AspisFormal/AspisFormal/Pool/V7PairAppendAfterstateCorrect.lean:57) specifically requires `appendCarry ... = .more result.frontier` (`:70–71`). That predicate does not describe the `.full root` outcome. The generic model separates cases: `append_correct` handles `.more` in [`IncrementalMerkleV1.lean`](../../../AspisFormal/AspisFormal/Pool/IncrementalMerkleV1.lean:735), while `append_terminal_correct` handles `.full root` (`:746–774`), proving full length and the padded-root equation from its invariant and carry premises. These are distinct theorem interfaces; this inventory does not assert a vulnerability or add a source constraint.

# Canonical Merkle causal recovery interfaces

Inspected at source revision `ce1fb7255213f5b390048d1ca709fea99176ae62`. This is a theorem-interface inventory; it makes no source-refinement, rank, probability, or security-closure claim.

The fixed tree model is [Merkle32Path.lean](lean/Merkle32Path.lean), SHA-256 `93ef63727b5fc596eec0084ec737e921d54719e8a87d276cc151b3e8b2c28270`: a digest is 32 bytes, each node input is `0x18` followed by 256 child bytes (257 total), and an authentication path has arbitrary indexed shape `Path slots`. [Merkle32Leaf.lean](lean/Merkle32Leaf.lean), SHA-256 `2d1f9ff2dc19bae994abbeda18ec96ae2654fecb1bc4873f2b3c4ae763f85ae8`, defines leaves as `0x10 || tag || packed || salt`; it proves byte-list injectivity for fixed packed width and the C1/C2/folded lengths (514, 162, 162 bytes respectively).

[CanonicalMerkleRecovery.lean](lean/CanonicalMerkleRecovery.lean), SHA-256 `5c5346a8b2dbe4b037adc63e37fad7a8ac360bbd63c68c15fbe518d86a9a5c79`, proves `recover_or_events` for an arbitrary consistent prior trace and accepted literal opening program. Recovery of `(packed,salt)` from the canonical Merkle log is the first disjunct; alternatives are a cross-trace collision, a root preimage absent from the prior trace, or a child-target first-read event. The bound is on `firstReads` over prior reads plus the opening-program reads.

[CanonicalFullTraceRecovery.lean](lean/CanonicalFullTraceRecovery.lean), SHA-256 `f612504e7662b3fb04232ea96f764a98e9ab30a321634284dcc9ed3f151a0dfd`, extends the interface to a consistent `pre ++ post` trace. `recover_or_events` assumes the commitment address is read in `pre`, a target predicate maps it to the root, the accepted opening program ends at that root, every opening read occurs in `pre ++ post`, and the trace has the stated first-read bound. It returns exact byte recovery or one of: `badColl`, a child-target hit, or a hit for the supplied root predicate. `recover_of_no_events` turns the corresponding three exclusions into equality with `some (packed,salt)`.

[CommitmentRootFrames.lean](lean/CommitmentRootFrames.lean), SHA-256 `840c8c75656a4c28aa65e72c42e524e53cb4952a728df76daac7c5e85302cd6d`, gives the concrete root frame readers:

- C1 uses `PublicInitFrame.addr`: initialization prefix plus the 32-byte root, total length `75 + pubBytes.length`; `pred_c1` establishes the commitment target there.
- C2 is `bytes state || [0,0xa2,1,32,0,0,0] || bytes root`, length 71; `pred_c2` identifies the root.
- Folded is `bytes state || [0,0xbe,0,1,0,0] || bytes root || tail`, with 224-byte tail and total length 294; `pred_folded` parses at fixed offset 38.

[ThreeCommitmentFullTrace.lean](lean/ThreeCommitmentFullTrace.lean), SHA-256 `bb7536019a5bf78a1f014bf39c8862b64b06846fd85d2ff2f42d44f64975e9ae`, specializes the no-event theorem for all three frames. `c1_recover_of_no_events` has leaf tag `0x71`, width 480, salt width 32; `c2_recover_of_no_events` uses tag `0xf1`, width 128, salt width 32; `folded_recover_of_no_events` uses tag `0x72`, width 128, salt width 32. Each keeps the path, accepted opening, trace coverage, consistency, query bound, and no-collision/no-child-hit/no-root-predicate-hit as explicit inputs. The folded 128-byte payload must be interpreted separately from the C2 model: Rust emits four consecutive `WideExact` values (32 bytes each), whereas the model C2 type is four slots each containing two `QM31Exact` values. Although both total 128 bytes/eight QM31-sized coordinates, this inventory does not assert that their typed meanings are interchangeable. [CanonicalC1Recovery.lean](lean/CanonicalC1Recovery.lean), SHA-256 `be0eb17ab0106a76daa08f0f313fe9f6ffddd2a6ff9960d9cf5e8e33c75a4627`, also provides the C1 event disjunction with the public-init parser target as its root predicate.

The causal and table representation links are separate. [CanonicalRecoveryStability.lean](lean/CanonicalRecoveryStability.lean), SHA-256 `1c3087658c794a0cec4fe8ae738281988a8d0da893f6230669f90882f4897545`, proves `recover_stable` / `earlier_of_later`: a recovery for a root already named in the prefix persists back to the prefix outside the same collision, child-target, and root-predicate events. [CanonicalTableRecovery.lean](lean/CanonicalTableRecovery.lean), SHA-256 `7e62ac6515d0a21addbbf213323e80a6265e8747e4a6a61e89174ffea0e3e5ee`, proves `represented_before_cut`: when a consistent represented trace replays to `tableBefore emptyTable (pre ++ (a,value)::post) a`, the cut address is fresh, and the collision/query/consistency conditions hold, recovery from `pre` equals recovery from that represented trace. [CanonicalLogSeparation.lean](lean/CanonicalLogSeparation.lean), SHA-256 `709f4f45baae1e2a291f27d2b8a9110a2dc0c486f2d0807eeeb7ba6ccdc0e5bc`, derives canonical-log hash separation from the full-trace collision exclusion. `InitialFrameNoMerkle.lean` and `FixedFrameNoMerkle.lean` show the literal initialization/root frames do not add canonical Merkle nodes or leaves.

These interfaces recover byte lists and permit a caller to relate the recovered log to a causal table cut. They leave the trace split, frame state and tail, path slots/siblings, root, packed bytes/salt, first-read and replay facts as parameters. The theorem interfaces do not identify the recovered bytes with Rust typed words or protocol slot/query indices.

## Folded payload decoder reuse (source inventory)

Current Rust emits `encoded(folded_word[4*(u/4)..4*(u/4)+4])` for a folded Merkle leaf in `crates/aspis-r1-cost-probe/src/prover.rs:251–255`. The verifier takes exactly `q[INITIAL_QUERY_BYTES..INITIAL_QUERY_BYTES+128]` for that leaf and uses `field(&q[INITIAL_QUERY_BYTES..], s)` for `s=0..3` (`verifier.rs:254–262, 268–271`). The local `field` helper in `weights.rs:10` parses each 32-byte block as one `WideExact`; hence the order is four sequential 32-byte wide values, with query selection `u % 4`. The leaf uses folded logical index `u/4` and tag `0x72`.

Existing formal representation APIs are `StrictWideByteCodec.WideBytes`, `.WideLimbs = QM31Limbs × QM31Limbs`, `.decodeWideLE`, and `.encodeWideLE_of_decodeWideLE` ([StrictWideByteCodec.lean](lean/StrictWideByteCodec.lean), SHA-256 `2920218159bd1eb149ef588a5d2b5dcfc6ec7b6e53e06a8a03cf5150b50a9713`); the halves are the first/second 16-byte QM31 coordinate blocks. `WideExactLimbCodec.pairToExact` / `.pairToExact_eq_digitsField` ([WideExactLimbCodec.lean](lean/WideExactLimbCodec.lean), SHA-256 `7fdbbd8da262ec8c7dbe539bb13b76af6c7ce7f91ae5e52cfdcf3327aa020dd6`) maps the two canonical four-limb QM31 coordinates into `WideExact` and the ordered eight-digit field representation. `UnrolledWideParserRefinement.limbs_refine`, `.source_refines`, `.fixed_success`, and `.source_eq_half_parser` (SHA-256 `e057b44f28ffb7b398c9439c6945ce7ab05537053f956dd4c70b28016cc00aa6`), together with `WideParserArrayHalves.arrayBytes32`, `.half0_bytes`, and `.half1_bytes` (SHA-256 `12e7c7ce74d2a88437075c141099f1669f6a31afa0c772fff1b54c3015016039`), give the fixed 32-byte Rust parser refinement and successful-byte reconstruction. These apply per WideExact block.

There is not yet a named `List Byte → Option (Fin 4 → WideExact)` decoder or theorem for the 128-byte folded payload. The mechanical composition would need a list/fixed-32 conversion around `decodeWideLE`/`pairToExact`, then a `FixedWidthDecoder.decode` over four 32-byte blocks (or the equivalent per-offset statement). `FixedWidthDecodedSlices.decode_eq_some_iff` (SHA-256 `5e85cf56efaf066c38d1f596ca053d2edf4dec18c5ff9331481418ce06a07212`) supplies the generic fixed-width list theorem once that block codec and its roundtrip/reconstruction facts are exposed. C2 remains modeled by its own `C2 := Fin 4 → (Fin 2 → QM31Exact)` decoder; no C2-as-folded semantic equality is asserted.

# V10 transparent carrier map (checked, 2026-10-21)

This packet proves a fieldwise, bijective carrier map between the transparent V10 `M31`, `CM31`, `QM31`, and `WideExact` structures emitted by the corrected-opacity extraction and the accepted `EbyKPushCutV3` carriers. The map preserves all eight nested U32 coordinates. The Lean target compiled with Lean 4.32, and `#print axioms` reported no axioms for the wide carrier equivalence or coordinate-preservation theorem.

The generated V10 `TypesExternal_Template.lean` declares `fast_pairing.EbyKDot` as an axiom. This packet does not compile that template. Its `dependencies/AspisR1FastDotsMinimalFixedCallsV10/TypesExternal.lean` is an explicit type-only adapter: it defines `fast_pairing.EbyKDot` as an abbreviation for the already accepted `AspisR1EbyKPushCutV3.fast_pairing.EbyKDot`. This removes the arbitrary carrier type without making any claim about Dot methods or their implementations. The generated `Types.lean` source is copied byte-for-byte from the Aeneas output; both dependency sources and their output object hashes are listed in `manifest.json`.

The adapter is local to this proof packet. It is not a source change to V10, the frozen production source, or the generated output. No V10 `Funs.lean` or `FunsExternal_Template.lean` was compiled. No method-level correspondence for V10 `add`, `from_limbs`, `to_limbs`, callback operations, or complete `four_dots` was established. The `core::array::from_fn`/P6 correspondence and adoption remain open.

The Aeneas `Aeneas.olean` and accepted EbyK type owner were reused from existing selected caches. Exact object hashes are in the manifest; the Aeneas source itself is not vendored in the earlier accepted producer packet, so this packet does not invent a source hash for it. Compiler source revision was not captured at launch; the exact compiled source hashes are authoritative and this limitation is recorded in the manifest. The packet contains no `.olean` binaries.

cardinality assertion for every source execution. QV-STAGE2's 566 consists

### Padding backend obstruction and countermodel

The retained `Funs:1499` invokes
`core.iter.traits.iterator.Iterator.any.default`. This is not defined in
the retained emission or the checked Aeneas interface (the diagnostic
receipt reports `lean.unknownIdentifier`). There is no retained
`AspisR1Stage2.FunsExternal` body in this extraction packet: generated/
contains only Types.lean and Funs.lean. Thus a direct whole-padding-scan
theorem against that checked interface is not yet well-typed. It must
first receive a pinned implementation/library model and its correctness
argument; substituting an arbitrary false-returning function is unsound.

`Padding.uninterpreted_scan_countermodel` (`Padding.lean:60`) proves the
countermodel: scan := constantly false, bytes := [1], so a false result
holds while zero padding does not. This is an interface countermodel,
**not** a counterexample accepting execution of the frozen Rust verifier.
The zero-check item stops at that boundary. The independently proved
chunk/prefix facts do not assume away the missing scanner or its little
endian word-decoder correspondence.

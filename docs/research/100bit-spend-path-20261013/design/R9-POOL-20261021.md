## Stage 3: runtime binding, R20 and false subclaims

`R9PoolRuntimeBinding.P2Prime` is quoted verbatim:

```lean
def P2Prime (hash : Bytes → State) (written current : Inputs) : Prop :=
  digestMatches hash written current →
    current.proof = written.proof ∧ current.pub = written.pub
```

`accepted_same_inputs` proves equality of the complete input records;
`nested_execution_same` transports any deterministic execution/output type
through that equality. Both have no axioms. This is the precise runtime
input boundary, distinct from persistence of the checkpoint itself.
`pool_common_from_r20` explicitly consumes R20's `sameSnapshot` and its
proved common-field agreement; it does not manufacture that runtime fact.

Three checked counterclaims delimit the construction:

- With a constant digest, different public buffers have the same digest.
  Therefore digest equality alone cannot replace P2′. This is a model
  counterexample, not a claim of a SHA-256 collision in the frozen binary.
- P2′ itself is false in that constant-digest instance.
- The R16 first-matching checkpoint can resume successfully while an
  unrelated `current` public buffer differs from `written`, because that
  submodel has no public field or digest check. It cannot be used as the
  complete Pool caller. This is not an attack on Rust's actual hash binding.

## Constant and derivation

The stage-1 **upper bound on distinct first reads is 595**. It is obtained
by bounding every digest invocation, retaining repeats. This is not a claim
that every execution has 595 distinct inputs, nor that hash-input addresses
are injective. For a ten-query batch:

| Component | Calls bounded |
|---|---:|
| Transcript: 1 + 27*3 + 1 + 4*3 + 17 + 3 | 115 |
| Salted leaves: 10 queries * 3 trees | 30 |
| Binary occupied parents, including three root hashes | 447 |
| Whole compact proof + verbatim ASF8 + checkpoint checksum | 3 |
| Total | **595** |

The 31-site inventory in `design/WIRE-TX1-20261020.md:52` counts syntactic
sites, not dynamic calls. Semantic rows are triplets; eight unrolled query
pairs contribute sixteen calls plus their absorb. The actual S2 opening
constructor is `crates/aspis-r1-cost-probe/src/verifier.rs:72`, rows 27--32
at lines 74--84. Whole-proof/ASF8 bindings are the **two** digest calls at
`verifier.rs:274`; checksum is at line 284. Omitting checksum would give
594, an incorrect invocation bound for the measured worst-case tx1.

`candidate.rs:193` requires split 10, and line 204 authenticates batch A.
`candidate.rs:124` hashes each leaf **before** folded-index deduplication
at line 125. Thus 30 leaf calls is valid even when fewer than 30 distinct
leaf positions are opened. `query_values`, lines 152--173, contains no
additional digest invocation. Each occupied parent emits one call at
`multiproof.rs:139`, 146 or 148; supplied siblings are input bytes.

For each full-range tree, the occupied-parent profile at levels 1--18 is
bounded by fourteen levels of ten followed by 8,4,2,1: **155** parents.
For the folded range `u/4` (`candidate.rs:105`), twelve levels of ten are
followed by 8,4,2,1,1,1: **137** parents. The last two unary levels are
required because this tree is padded to the same depth. Therefore
`2*155 + 137 = 447`. These are short symbolic profiles, not enumeration
of a concrete `Fin (2^18)` universe.

`lean/QvStage1Count.lean` proves the generic plateau/crown sum bound,
the three-profile bound, and the binary-trie identity
`parents + 1 = supplied + distinctLeaves`. With ten distinct leaves in
each tree, supplied counts are 146,146,128, totaling 420; parents total
420 + 30 - 3 = 447. For fewer distinct leaves use the occupied-level bound,
not the ten-leaf identity specialization. The report's 914 is the supplied
sibling bound over **both** batches, not a stage-1 hash count
(`evidence/proof-size-20261019/REPORT.md:93`). No 914-node term is added to
stage 1. The symbolic parameterized expression is

`stage1Budget k = 115 + 3*k + 2*(14*k+15) + (12*k+17) + 3 = 43*k+165`.

Only the adopted k=10 has been source-reviewed here. For other k the same
formula needs its own range/profile premises; it is not an arbitrary-batch
source theorem.

## Actual privacy read-set definitions

`docs/research/v8-r0-zk-20261009/lean/R1Z/LayoutR1P3Bin.lean:255`
defines `openedQ` as all three roots, selected leaves, and each selected
leaf's non-root ancestors. `R1Z/EventsR1PBin.lean:45` defines
`batchReadSet = univ.filter openedQ`; `batch_length:72` proves equality
of its cardinality with a **Nodup**, covering batch log's length.
Supplied siblings and padding are not separate positions. Roots are the
last parent hashes, not three extra digest calls.

Consequently the intended cardinality expression is the sum, over the
three trees, of distinct leaves plus occupied parents (including roots).
At batch A this is at most **30 + 447 = 477** commitment positions. To
transport this to actual bytes one still needs `ROpen` coverage/Nodup and
`RComLog`'s equality of addresses **and answers**, plus the carrier map.
These are source-refinement premises (`EventsR1PBin.lean:54,111`), not
consequences of merely calling `batch_length`. In particular the existing
`batchReadSet_card_le:78` is only the coarse **2,359,298** universe bound;
it does not already prove the ten-query 477 bound. This packet does not
claim to have kernel-checked that privacy-set/profile transport.

The new count theorem instead conservatively bounds the actual repeated
leaf calls by 30 and obtains distinct first reads from the existing,
actual `FS2.distinctFirstReads` definition through
`VerifierCallBudget.distinctFirstReads_of_totalCalls:87`. It does not
assume answer distinctness, successful acceptance, or deduplication of
source callbacks. `CountedTrace` explicitly requires complete prefix-call
coverage. Its category accounting uses a permutation because leaves and
parents interleave once per tree; the execution embedding keeps the original
ordered trace. The occupied-level/cardinality bridge and that coverage are
named remaining obligations, not hidden axioms.

## SourceSimulation obstruction and retained extraction

`lean/VerifierPhaseCost.lean:232` defines `SourceSimulation` into its
fixed `Route`/`ModelPrefix`. `preservesPrefix:235` preserves the **whole**
call trace. Its ten-query route costs 328 (`VerifierCallBudget.lean:55`),
and even its global route maximum is 472. The measured binary tx1 traces
have 595 calls. Thus reusing that structure with `.stage1Ten` is false:
`QvStage1Bridge.old_stage1_model_excludes_595` proves that a trace of
length 595 cannot have that model-prefix certificate. Measurements provide
two actual count witnesses below. This item stops here; the old model is
not silently reinterpreted or edited.

The new `BinaryCountSimulation` reuses the existing `Step`/`Exec` hash
semantics at `.checkpoint (stage1Budget 10)`. Its name describes a cost
embedding: it preserves every call pair but **forgets termination labels**.
`simulation_of_coverage` constructs it from named `SourceCoverage`, and
`source_count_of_binary_simulation` proves the all-prefix 595 bound.
`distinct_firstReads_bound` proves the 595 bound for the actual FS2 view
under `CountedTrace`. These are conditional theorems, not an unconditional
instance for the current Rust entrypoint. Encoding the 595 potential as
`checkpoint` does not assert that the source is executing checkpoint code.

The actual old extraction is
`lean/bridge-tx1-e5c186ba3-20261016/ExtractedTx1Model.lean:111`;
it dispatches through arbitrary `B.verify` and `PreparedModel.prepare`
and then opaque **`B.finish` at line 147**. It neither implements the
current compact `candidate::batch_merkle` nor its checkpoint. The current
source also requires `k == 10`, whereas that old outer extraction only
rejects `k > 22` (line 118). It cannot discharge full binary source coverage.

`QvStage1Retained` adds a concrete retained-extraction result: successful
parsed `begin` yields **45 ordered digest-equation witnesses**, obtained

`begin_typed:103`. The proof constructs the witness list in run order, containing hash
object, input slices and returned digest. The theorem conclusion states
length and pointwise digest-equation validity; it does not characterize
a unique log or assert a runtime effect trace. It covers rows 0--14, without initializer;
it is not a runtime logging/completeness theorem. This is the extraction
fragment instantiated here, rather than manufacturing a whole-tx1 instance.

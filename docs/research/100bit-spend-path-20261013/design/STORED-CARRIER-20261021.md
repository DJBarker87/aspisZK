## Exact endpoint obligation

`OraclePortRuntimeBindingC7.StoredCarrierBinding` says:

```lean
∀ H : Bytes → State, ∀ run : RunView,
  (eval H runtime).2 = some run → run.2.2 = true →
    run = eval H (annotatedWith D rust (canon P))
```

For every oracle world, every accepted designated runtime observation must
be exactly the annotation compiler's run on the canonicalized prover in that
same world. `RunView` contains the full ordered oracle log, the `Input`
(statement, abstract proof and stored bytes), and the Boolean verdict.
It is stronger than persistence of proof bytes between two transactions.
It says nothing about rejected observations. The equality concerns the
*returned designated run's* log, not the outer `eval H runtime` log.

## First source correction

The frozen release does **not** use the legacy ASPU lifecycle loader.
`programs/r1-cost-probe/src/lib.rs` checks `pool_route::admitted` before any
account inspection. Only `[3,10]`, `[3,11]` and the `ASQ8` prefix pass.
Tags 4/5/6 (initialize/write/finalize) cannot enter their retained helpers.
The admitted proof account is a raw candidate-afterstate followed by proof;
its owner is unrestricted and it has no ASPU header or embedded checkpoint.
The separate checkpoint must be verifier-owned. Both proof readers require
readonly, non-signer, non-executable metadata. Pool's
`pair_forest_dispatch::proof_transport_verifier` under `r1-split-checkpoint`
explicitly omits proof ownership and sealed-header checks.

Therefore a proof that legacy finalisation seals the admitted proof account
would be about the wrong route. Upload writes can be adversarial. P2′, plus
the accepted digest checks, binds the buffers used across transactions.

## Interface obstruction (stage 1)

`StoredCarrierBindingObstruction.same_bytes_insufficient` constructs two
accepting designated observations with the **identical complete Input** and
different logs. At least one cannot equal the fixed annotated run. This holds
for arbitrary `D`, `rust` and `P`, hence also when `AcceptedRunJoin` is given.
It uses no digest collision and claims no runtime attack.

`BoundaryStatements.P2/P2_prime/P3/P4` are arbitrary `Prop` fields, with their
interpretations documented in comments. `BoundaryEvidence` supplies those
propositions, not a theorem interpreting `runtime`. Setting those four slots
to `True` cannot determine an arbitrary runtime observation; the companion
countertheorem records this. Restating the original premise as proved local
layout facts conjoined with these opaque slots is therefore not a valid
universal implication. The requested arbitrary-runtime deletion is stopped
at this false interface; independent source/component work continues.

A full-source transaction/observation join is still required. This is a
source refinement obligation (including ghost annotation and log provenance),
not a new cryptographic/runtime assumption and must not be relabelled P2.

# J1 trace witness extractor reuse inventory (2026-10-15)

This is a source/API inventory only. It does not establish source refinement, efficient full-log decoding, or a security conclusion. Paths are relative to `docs/research/100bit-spend-path-20261013/lean/` unless stated otherwise.

## Executable selector and premises

`TraceWitnessExtract.extract` (`TraceWitnessExtract.lean:17–22`, SHA-256 `58779035a5b808e52d831337aecacf0903de327bac4b4ce45b5b153bc2c38f6c`) first matches `TraceValueDecode.decode A`; a failed decode returns `none`. On success it constructs `ComputableTraceWitness.fromTrace` and returns `some w` only in the `checkM31 pub w = true` branch. There is no `Classical.choose` in this definition and it is not marked `noncomputable`. The selector is executable with an `Option` result; it can reject either invalid/out-of-range values or a failed witness check.

The checked facts are exposed as `returned_checked` and `returned_valid` (`TraceWitnessExtract.lean:24–38`): successful extraction implies `checkM31 = true`, then `SpendRelation.check_eq_true_iff` yields `Rspend`. The check is the exact finite Bool checker in `InputWitnessCheck.check_eq_true_iff` (`InputWitnessCheck.lean:55–83`, SHA-256 `15e062731eb903b431fddfcf3bbeaf7cb289c2f95aa4211a8720053f4cd10b60`) together with `PublicOptionShape.check_eq_true_iff` and the balance/variant checks in `SpendRelation.check_eq_true_iff` (`SpendRelation.lean:59–88`, SHA-256 `ef80726d48b31e834a1fe040e304b1efe40eabf4681acbcae3cf36154765a9ae`). Its contract is `Rspend`, whose input-membership part is the six-field `InputWitnessCore.Relation` (`InputWitnessCore.lean:13–22`, SHA-256 `fec688b4ae7650f4ba4c266613853eb9f858aabd5d36f2d8a5f4d01107a85d5d`).

Completeness is conditional, not an extractor theorem for arbitrary byte/log input. `complete_of_production` (`TraceWitnessExtract.lean:43–87`) assumes canonical public options, `BaseTyped embed.fieldRange A`, and production plus copy-link facts on that trace. `complete_of_candidate` (`:89–102`) additionally assumes membership in `ConcreteBinding.candidates (TypedRecoveredWords.word ...)` and the production/copy-link facts for the corresponding semantic rows; it obtains base typing from `CandidateBaseProjection.rows_base_typed`. Neither theorem constructs the candidate list or proves efficient list decoding.

## Fixed work visible in definitions

`TraceValueDecode.decode` reads exactly three selected trace cells, at `(10,1008)`, `(10,1010)`, and `(10,1012)`, projects each to M31, and checks each canonical representative is below `2^30` (`TraceValueDecode.lean:19–31`, SHA-256 `8f1c6d5f66a7ca7940cdbf3b2ffe517dbe8c6e867077c43d4b07e1133d9308a9`). `decode_of_values` proves the matching embedded-value round trip (`:34–39` onward).

`ComputableTraceWitness.pathFromTrace` has a `Fin 24` result. At each level it selects one branch by a projected zero test and constructs an eight-lane sibling digest from columns `0..7` or `8..15` of the successor row (`ComputableTraceWitness.lean:22–34`, SHA-256 `2025bc75176168fcfb738453effcad4a506e561e97c27b9105ffd302dc00e0e1`). `pathFromTrace_eq` proves agreement with the prior path selector only under `BaseTyped`; `fromTrace_eq_projected_existing` proves the whole witness record agrees with the projection of the older witness (`:53–108`). The concrete witness mapping selects the existing key, salt, pair, and output-note coordinates and maps digest lanes pointwise; `SpendDataMap.witness_id` and `witness_comp` are structural identity/composition laws (`SpendDataMap.lean:12–55`, SHA-256 `0f606c08fa0d796d4e36a9e46d225e71be2094184ba29eb8dd510ddc2de22813`).

The finite checker does expose iteration shape: `allFin8` is `List.ofFn` followed by `List.all` (`InputWitnessCheck.lean:13–25`); digest equality checks eight lanes (`:27–39`); pair validity includes another eight-lane check (`:41–53`). The input relation checks the path membership using `merkleRoot` over `Fin 24` (`InputWitnessCore.lean:21–22`). In `R0P.Semantics.lean:54–71` (SHA-256 `9309c5faa3de30d4f35bfe46509fe335a821d89a43051201a97232c0b89dc615`), `merkleRoot` is `merkleRootAux ... 24`; the recursion performs one `merkleStep` per level 0 through 23, and each step calls `nodeCompress` with a Poseidon permutation. This is a structural count of path levels, not a measured or formalized cost bound.

## Count/cost theorem status

The inspected extractor, value decoder, witness mapping, input checker, and spend relation modules contain correctness/equivalence theorems, but no operation-count, runtime, CU, or asymptotic-cost theorem for these operations. The concrete structural counts available directly from the definitions are three value-cell selections, 24 path entries/steps, eight digest-lane comparisons per `digestEqCheck`, and eight lane tests in each `allFin8` use. They do not account for field-operation cost, Poseidon evaluation cost, branching, compiler behavior, or the cost of obtaining `A`/the candidate trace. No generalized cost theorem for mapping a complete witness or running the finite checker was found in these modules.

The extractor therefore supplies a checked, computable **trace-to-witness selector** once a trace is available. It is separate from efficient candidate generation, full-log parsing, and any cost claim for those stages.

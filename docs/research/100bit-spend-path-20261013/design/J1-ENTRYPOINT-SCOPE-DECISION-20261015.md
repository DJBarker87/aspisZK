# Superseded interim entrypoint decision

> Note (2026-10-19): the R1 proof format is now the compact binary-multiproof format, fixed length 57,607 bytes (`../evidence/format-adopt-20261019/REPORT.md`); 124,343 bytes below is the retired eight-way format.

The binding [lead review](LEAD-REVIEW-J1-R4-20261015.md), commit `f5a04e0bb`, supersedes the interim decision below. The soundness oracle is over **all finite byte strings**; no global input-length cap or empty-address fallback belongs in the soundness theorem. The all-input query-count obligation remains. Pool release builds must reject the legacy `[1,k]` and `[2]` routes before account access. Lifecycle routes are retained for proof/public-account preparation and will be brought into the state-transition/immutability theorem under J1.R8.3(b); that obligation remains open. Verifier-side PDA hash calls must be counted unless the required byte-format separation is proved. The source guard is being implemented as G_R1.7; it is not yet a checked release artifact.

The checked bounded literal sampler components remain reusable mathematical results. Their transport to the full byte-string oracle is now a required adapter; the existing cap is not silently retained as an adversary restriction. No source/all-program query bound, compiler theorem, or final security claim follows from this note.

## Historical interim decision (superseded)


The first source hash-input theorem covers the pinned Pool verification routes of `process_r1_cost_probe_instruction`: exact stage-1 instructions `[3,10]` and `[3,11]`, and every stage-2 instruction whose bytes start with `ASQ8`. The latter includes malformed, truncated and overlength requests; successful request decoding is not an admission premise. The configuration is S2, P3 profile/release bindings, `pool-adapter`, `private-leaf-salts`, default custom heap and the pinned transitive feature closure. This accepts the route boundary proposed in `J1-CONFIG-BOUNDARY-PROPOSED-20261015.txt`, with the qualifications below.

The theorem quantifies arbitrary raw account contents and metadata and every finite execution prefix, including rejection, panic and allocation failure. It records the concatenation supplied to every designated verifier `HashFn` call before address encoding. It must prove the input-length bound from route guards and source semantics. Authentic checkpoints, successful parsing, honest statements, acceptance and attacker-supplied length promises are not premises for this theorem. The candidate maximum of 124343 bytes remains unproved source arithmetic until that argument is complete. `CanonicalByteHash` mapping an overlength input to the empty address is not a replacement for the source bound.

This is an entrypoint-scoped lemma, not an all-exported-functions claim. The unrestricted library APIs (`checkpoint`, `resume`, `Prepared::new`, transcript payload methods, and raw tx1/tx2 public-byte arguments) remain outside it. They may receive separate theorems with explicit pre-execution length premises. No source guard is added or inferred by this decision.

Legacy `[1,k]` and `[2]` and lifecycle instructions 4/5/6 remain externally callable in the current binary. They are not silently treated as disabled. Their invocations outside the two selected verifier calls belong to the surrounding adversary/runtime experiment and its query accounting. Before using the checkpoint trust premise for Pool soundness, source correspondence must establish that these other routes cannot create or mutate a checkpoint accepted by the Pool path except through its authorized strict-parse transition. In particular, the whole-account checkpoint size guards on legacy writes and the Pool proof-account layout must be checked together; runtime account ownership alone does not prove this. Finalized proof immutability and lifecycle authorization remain explicit integration/release obligations.

SDK PDA derivation inside stage 2 is not a supplied verifier `HashFn` call. It must not disappear from the eventual shared-oracle budget: record a separate runtime/PDA trace and query bound, and include those calls when the claimed experiment models their SHA calls in the shared oracle. The designated-call length lemma alone establishes neither an all-program hash bound nor the final `QV`. Runtime ownership/write enforcement remains the trusted precondition already fixed by the lead; this decision adds no new PDA collision or authorization assumption. Legacy and runtime hash calls are charged once in the applicable verifier or adversary portion, never dropped or double-counted.

For the bounded-address oracle adapter, any adversary input-length restriction must be stated in its experiment. An unbounded-byte random-oracle extension may instead be proved, with long inputs treated as their own independent addresses. No claim equates unrestricted SHA queries with the current empty-address fallback.

The next source tasks are: pin the exact feature closure and callsite inventory; prove Pool-route guards and slice/accumulator bounds on every prefix; prove the runtime/PDA and other-route interaction obligations; then instantiate the source-to-address correspondence and all-input distinct-read bound. J1.R4 remains open. The seven reviewed public/prefix modules and source-pin repair are accepted as reusable components and merged at `3944eaa5cfdcfff8867d8a46437c02613366e201`; they do not close these source obligations.

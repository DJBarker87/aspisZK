## Ordering and privacy interpretation

`tx2_common` resumes, checks next=10, decodes inactive/folded root, then runs
`batch_merkle` for batch 1 (`Funs:4035`). Its three tree calls are ordered C1,
C2, folded (`Funs:1583,1589,1595`). Each consumes twelve sorted query entries
from positions 10..21 (`probe/candidate.rs:180`). Leaf hashing happens **before**
folded-index deduplication (`probe/candidate.rs:185`–194); thus 36 source leaf
calls, including repeated addresses, on a successful batch. Parent count depends
on the selected indices. The twelve-query arithmetic loop follows this batch;
it does not contain the Merkle hashing (`Funs:4051`, existing
`Stage2ContinuationFacts.stage2_twelve_ordered_calls`). Finally the relation
checks consume round0, round1 and final_message (`Funs:4078`). Calling these
“hashes in the twelve-query loop” would misdescribe the frozen control flow.

## Remaining carrying obligation

A theorem about **every tx2 execution-log entry** is not yet proved. Compose the
entry parse-size result, admitted ASF8 serializer, concrete S2 checkpoint-size
operation and checkpoint provenance with the retained resume. Instantiate the
leaf tag/conversion/backend operations. Lift helper-level digest equations
through the binary multiproof loops and ordered batch calls, proving preservation
of `Arity::Two`, then through tx2_common and the entrypoint. Transport the
Digest32 calls to one consistent oracle log, including responses and rejected
prefixes, and normalize repeated leaf/node reads to the required per-batch list.
The extracted Digest32 type (`Types.lean:60`) returns only `Result Bytes32`,
not an instrumented call log. Success inversion and source call inventory alone
cannot supply that global-log correspondence. The generic concatenation lemma
is usable once those site traces are connected; it is not that connection.

Thus the bounded claim proved here is: the successful retained resume calls
under named caller widths, the successful occupied/sibling helper calls under
their actual slice operations, and batch-leaf calls under named backend
correspondence have typed D79 inputs. No new record class, whole tx2 refinement,
`eCm`, `ROpen` or `RComLog` closure is claimed. No verifier edit is needed for
these results. All R14/R10/R15/ROM/ELF and privacy premises outside these focused
facts remain as in the gap map and addenda.

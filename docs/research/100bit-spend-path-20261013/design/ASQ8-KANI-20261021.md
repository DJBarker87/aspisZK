## Stage 2: extraction and Lean

Pinned Charon and Aeneas both pass for the final reference encoder, parser
and fused normalizer (extraction v6, `has_errors=false`). The generated
`lean/AspisR20Request/{Types,Funs}.lean` are byte-identical to that output.
`aspis_core::field::M31`, its two byte conversion methods and `P` are
transparent; `P` is extracted from Rust, not supplied as a library axiom.
The unused external template is retained by hash/size only.

`lean/ASQ8Normalization.lean` proves:

- `success_bytes`: every successful execution of the extracted fused
  normalizer returns exactly its original 320-byte input;
- `transfer_bytes` and `withdrawal_bytes`: successful reference decoding of
  the respective complete variant makes normalization return those exact bytes.

`lean/ASQ8PoolHandoff.lean` composes these with the **actual pinned extracted**
Pool suffix-strip theorem. `handoff_bytes`, `transfer_handoff` and
`withdrawal_handoff` prove that the stripped body of `ASQ8 || four hints`
is precisely the byte array preserved for the verifier input. Arbitrary hint
bytes are parsed, not certified as authenticated.

There is no generic deterministic encoder parameter, codec-inverse premise,
or supplied encoder-equality hypothesis in these Lean theorems. Successful
decoding/normalization is the admitted execution condition. The proof split
is explicit: Kani proves the full shipped decode/encode pipeline equivalent
to the fused reference; Lean proves the extracted fused reference's byte
identity and its composition with the extracted Pool strip. A separate Lean
inverse proof for every unfused scalar/payment codec is not the basis of this
result. The whole-pipeline Kani harness is essential named **P6** evidence.

## Diagnostics and verification cadence

All stopped extraction attempts are preserved as diagnostics:

1. v1 reshapes the request match; Aeneas then exposes the transitive digest
   iterator loop-collapse failure. A Translate-log diagnostic identifies
   that declaration; the source replacement is the fixed-eight-word copy.
2. v2 requires M31's data layout; v3 includes it and the byte methods, then
   reaches the constructor-coercion name collision. The changed
   `-impl-namespace` diagnostic does not resolve that collision.

   template identifies slice/array equality and P as unresolved interfaces.
4. v5 directly includes Rust std equality and P; Aeneas stops at std's
   unsupported `as_array` pointer cast. v6 retains the source-extracted P

   extraction tools then pass, and the resulting Lean modules compile.

Scope and source boundary

Extract the real r1_wire::row_shape first, then r1_wire::parse_record.
The new kit copies exact declaration spans from r1_wire.rs and the current
M31/CM31/QM31/WideExact sources into namespace-only layouts. No runtime source
is changed and no field parser or error check is replaced by a handwritten
model. Each stage has its own source manifest, dependency-free Cargo input,
module extraction root, and generated-declaration presence check.

The local Charon/Aeneas binaries and their source-provenance limitations are
the same as the public-serializer extraction. Runs use separate targets,
offline release compilation, one Cargo job, and a process-group RSS guard
below 3.5 GiB. No broad crate or Lean dependency build is requested.

Next source proposal and remaining obligations

OPEN proposal: move the existing field-validation loop into a private
validate_record_fields(row, payload) -> Result<(), Error> with final Ok(()),
then call it under row >= 14. This could isolate the loop's early errors from
the borrowed payload return. It is not applied or asserted sufficient.
The iterator operations already have Aeneas builtin mappings; replacing the
parser by an opaque function or changing canonicality checks is unnecessary.

Successful row_shape generation is not its specification theorem. Prove its
exact result for all U8 inputs, including None for 27..255 and the checked
usize computations. For a future generated parse_record, prove framing,
canonical limbs, zero high component, returned-payload identity, and the
actual Error branches before relating rows 0..24 to SemanticRecordCodec.decode.
Rows 25/26 additionally need their own opening-claim payload codecs.

SemanticPrefixCodec's existing decode/re-encode and prefix-stability theorems
remain byte-model theorems: this kit does not extract Prefix::parse, link its
27 exact record boundaries to those typed values, or link ValidatedRecord to
successful runtime parsing. SemanticTranscript challenge frames, row sigma
maps, first-read/commitment-cut timing, all 33 UnifiedProtocol rows, and the
Rust execution/refinement boundary remain separate OPEN obligations. No Lean
compilation, axioms audit, or source-to-specification proof is claimed here.

Nested timers overlap and must not be added together. These are sub-profile measurements, not gate medians.

The candidate tiles contiguous image/product coordinates eight at a time. Builder multiplication and emitter row subtraction use exact two-fold Mersenne reduction. For arbitrary u64 x, the first fold is at most 5P+3 and the second at most P+7; one subtraction produces x mod P. Multiplication of arbitrary u32 operands fits u64. The checker enables tiled summation only for at most 2^20 terms: each reduced term is below P and the entire sum is below 2^51. Larger shapes retain the old checked-accumulator code. Converter image updates reduce after every term and preserve the unreduced initial source when the coefficient list is empty. No probabilistic checking, changed source descriptors or protocol bytes.

The original no-feature extraction path remains; native kernels are enabled explicitly by the host z4 dependencies. Existing extracted Lean artifacts are not a formal refinement of the new native path. Kani proves five local obligations (all-u64 reduction, subtraction after product, image update after product, fixed worst-case accumulator step and tile index order). Arbitrary-product reduction composes with the u32-to-u64 multiplication bound; this avoids treating a sampled multiplier check as a proof. Tile traversal is bounded in Kani (up to 17 coordinates); the general traversal and independent-coordinate argument are analytical. Release differential testing compares 10,000 malformed/noncanonical tile cases with the frozen checker, normalizing panics to rejection.

## Stage 3: bounded workers (prepared; gates pending)

The worker design partitions source indices into sixteen adjacent ranges using q = n / 16 and r = n % 16. Range k starts at q*k + min(k,r), with length q + [k<r]. Consecutive endpoints agree, the first starts at zero and the last ends at n. Spawn order is k=1..15; the caller executes k=0. Handles are joined and chunks appended in source order, regardless of completion order. Each range catches panics; every handle is joined before the first source-order panic is resumed to the existing P_R1 rejection boundary. A TLS nesting guard prevents inner work from launching another team. Sixteen means fifteen spawned workers plus the caller.

Planned parallel units: the three emitter certificate families (lifts, QPrime, BCondG), target-expression rows, converter images, checker entries/product rows, and extracted own/relation/round/G-batched columns. The emitter families share only immutable public input and prebuilt lane tables. Their elimination loops and pivot selection order stay serial and unchanged within each family. The transport OnceLock is initialized before workers. Successful family outputs merge as lifts, QPrime, BCondG in the same certificate-field order. Failures or panics normalize to rejection; independent work may run beyond an earlier rejected family. That new public-challenge-dependent trace needs the D166 joint simulation transport.

The new nesting/quiet TLS belongs to public P_R1 work, not the production secret-operation recorder. The quiet panic hook must suppress worker panics too; recorder TLS stays gated off as in v2. `std::thread::scope`, allocator/resource availability, joining, panic unwind and the OS schedule remain explicit native trust boundaries. Partition/merge reasoning is not a formal Rust concurrency-memory-model proof. No new cryptographic assumption or changed checker predicate is intended.

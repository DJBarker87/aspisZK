## Stage 2: private arithmetic leaves

The isolated tool crate copies the frozen private canonical module and instruments
each explicit wrapping add/subtract with checked_add/checked_sub plus an assertion.
Other arithmetic retains Kani's default overflow and memory checks. The external
from_wide constructor is excluded, and its canonicality is a caller boundary.
prepare.py --check verifies generated source and declaration hashes. Shipped files
are unchanged. The host uses Kani 0.67.0 / CBMC 6.8.0, optimized tool-crate profiles,
MemoryHigh=6G, MemoryMax=8G, MemorySwapMax=0, TasksMax=64, sequential jobs.

Twelve safety harnesses pass: unrestricted reducer, canonical scalar addition,
packed addition/subtraction, half/half_pow, unrestricted widened U32 multiplication,
raw partial bounds, all four raw coordinates and a dot prefix induction step.
Packed results and half results are additionally proved canonical. Raw-coordinate
harnesses overapproximate products by independent values <=(P-1)^2 and partials
<=3P; these are range proofs, not an inlining of eight correlated multiplications.
The dot proof assumes the prior count/partial-sum invariant. No assertion reachability
or unwinding-safety check is confused with these caller obligations.

Attempts 01/02 are rejected setup/diagnostic attempts: 01 lacked rustc on PATH;
02 passed safety checks but failed Kani's separate assertion reachability diagnostics.
The replacement fixes PATH, disables assertion reachability diagnostics only, and
uses opt-level=3 with overflow-checks=true. Default arithmetic, memory, undefined
function and loop-unwinding checks stay enabled. Receipt parsing initially looked
for the wrong success spelling; harvest.py derives normalized status from retained
logs without rerunning proofs. Every attempt includes source/dependency fingerprints,
exact command, exit, wall, RSS, swaps and the N/A Lean-axiom field.

Full node_count unwinding (attempt 14, even one symbolic leaf) expanded nested
infeasible paths during symbolic execution. It was stopped and will be replaced by
separate control/group proofs; it is not rerun unchanged or with a larger cap.
The two-leaf follow-up was cancelled before launch. This is a proof-engineering
obstruction, not evidence of source overflow.

## Stage 3: splitting the concrete control bodies

The failed monolithic node_count check is replaced by a checked copy of its
single parent-group scan on arbitrary sorted 16-entry U32 arrays, both arities,
any i<n<=16, and w<=i. This proves group width, all indexing/shifts/counters,
nonempty progress and the output-write bound. Separate checks prove binary
progress, the conservative 2,304-node sibling budget's byte arithmetic,
and the exact insertion-sort inner body at every legal position. These are
body/induction-step checks; sorting/frontier invariants still have to be
propagated through the full concrete loops. extend.py checks their fragments
against the frozen Rust, including the abstract raw-coordinate expressions.

Actual frozen slot_offset, candidate opening/slot and Reader.raw bodies are
copied unchanged. All six compact slots and all 22 openings pass the offset,
index and slice checks. Reader.raw<4> and <16> pass under cursor<=4880-N
using a 4,880-byte buffer. Contents are fixed zero: the range/access result is
content-independent, but this is not a parser or arbitrary-buffer refinement.

Attempts 22, 25 and 28 fail only loop-unwinding assertions: memcmp compares
32 bytes, and the batch-key harness assumes all 22 query bounds in a loop.
Default unwind 20 was inadequate. All reported scalar arithmetic properties
pass. Replacement targets will keep unwinding checks enabled and state a
sufficient finite loop bound, or split away the irrelevant content comparison.
No memory cap is raised; these were completed verification failures, not stalled
or memory-killed jobs. The cancelled node-pair and sort-four full checks never ran.

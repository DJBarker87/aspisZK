## Classification and scope

TOTAL means outer Aeneas success for every value of the stated input type,
with a model value equation when available. An inner Rust `Err` or `Option.none`
is allowed: rejecting malformed data is normal execution, not Aeneas failure.
ACCEPTED-ONLY includes every explicit range, canonicality, callback or success
premise, even in a theorem named `total`. OTHER includes complete-result
transport (which may transport failure), algebra alone, inventories and failed
extractions. Typed `Fin`/fixed-array domains are stated explicitly; they do not
cover arbitrary machine indices or arbitrary slices.

## General corollary and P6 boundary

`R22TotalCheckedComposition.success_noOverflow_agrees` proves by structural
induction on a finite operational tree that checked success gives safety at
every reached primitive and the identical wrapping result. Ret/bind, failure,
divergence and value-dependent continuation are explicit. `total_refinement_R22`
lifts this to every input; `reached_refinement_R22` gives the conditional
version; `extracted_total_R22` joins an actual extracted function to the tree.
These audit to `[propext]`. No arbitrary Rust source is identified with this
tree by fiat. For recursive/loop functions, the tree is their finite successful
execution, with each reached iteration included; proving that interpretation
is the translation boundary, not an assumption that the desired R22 conclusion
already holds.

`R22TotalUnsignedPrimitives` discharges the primitive success law for the actual
Aeneas unsigned scalar operations, generically over machine width:

* `+`: success implies `x.val + y.val < 2^numBits` and equality to wrapping add.
* `-`: success implies `y.val ≤ x.val` and equality to wrapping subtraction.
* `*`: success implies `x.val*y.val < 2^numBits` and equality to wrapping multiply.
* Rust unsigned `as` casts are **modulo conversions**, not overflow failures.
  `cast_mod` proves that semantics; `cast_exact` requires the explicit destination
  range bound. A total theorem alone does not imply a cast loses no bits.

Precisely what P6 must preserve: the pinned Rust/Charon/Aeneas source identity;
integer widths and signedness (including the SBF usize width); emitted checked
ordinary arithmetic; failure propagation with no recovery into outer `ok`;
complete executed-operation coverage including loops and transparent children;
identical non-arithmetic control/memory/branch effects on successful runs; and
correct runtime models for casts and external primitives. Signed arithmetic,
shifts, division and indexing need their corresponding success laws if present;
they are not established by the three unsigned laws. Explicit `wrapping_*`,
`overflowing_*` and `checked_*` APIs use their actual semantics and are not
proofs of mathematical non-overflow merely because their outer Result is ok.
Truncating casts can be perfectly faithful to SBF while not lossless.

The `Translation f` argument of each concrete corollary is quoted as a named
P6 residual, not declared to be an axiom and not silently discharged. This
avoids treating an extensional result equation as a source-to-SBF simulation.
A literal `ret` containing a model result would not prove source-operation
coverage; the trust boundary requires the actual emitted execution tree.

The checked proof of `wrapping_success_is_insufficient` exhibits U8
`255 + 1`: wrapping returns 0 while the checked add cannot return `ok 0`.
Thus an accepted wrapping run cannot by itself discharge a checked-success
premise. Upstream validation must establish the checked domain independently,
or supply an execution simulation up to each guarded operation. Totality does
not claim that untaken branches never overflow if executed on other inputs.

Focused receipts are under `evidence/r22-total-20261021/`. The first generic
attempt failed on conjunction association (exit 1, 2.224 s, 2.238 GB, zero swap);
the corrected proof passed (exit 0, 1.933 s, 2.259 GB, zero swap). Unsigned
primitives passed first attempt (3.146 s, 2.246 GB, zero swap). Failed output
contains Lean's error-recovery `sorryAx`; it is excluded from accepted evidence.

`R22TotalReducerExecution.reducer_R22` and `multiply_R22` are stronger:
**no Translation argument**. The new `reduceCode` and `multiplyCode` explicitly
represent the emitted checked shifts/additions/subtraction/multiplication;
`checked_reduceCode` and `checked_multiplyCode` prove equality to the actual
extracted functions. Masks, casts and comparison use the actual Aeneas runtime.
The general corollary then supplies safety and wrapping equality.
`wrapping_multiply_exact` preserves the exact modular result and canonical
output for every stored U32 pair. There is no manually assumed arithmetic
bound and no opaque arithmetic callee. P6 still identifies these machine
operations, widths and source pins with the frozen SBF implementation; Lean
does not verify a native binary by loading it.

The fixed-parser, sampler, row and conversion corollaries deliberately keep
that operational interpretation visible. They do not assert that arbitrary
functions with equal final results have equal internal execution traces.

The upstream canonicality question has a checked positive example:
`sampledProduct_total` obtains canonical current-carrier values from both
samplers, then calls the previously conditional QM31 multiply theorem. This
is total on both block arrays and uses no success premise. It establishes the
local composition pattern; it is not a claim that every frozen `Prepared`,
Libra, pairing or checkpoint operand came from these samplers.

Actual extracted record-field validator

Target: lean/ExtractedRecordValidator.lean. It composes the actual attempt-F
validator loop/body with the checked byte decoder and high-zero comparison.
The core contract is successful-return partial correctness: for arbitrary
initial Enumerate count and ChunksExact remainder, success implies every
remaining chunk decodes successfully and its returned high component equals
the actual QM31.ZERO. No allocation/termination/counter-bound premise is
added; an overflowing checked enumeration increment cannot satisfy success.

Proof: unfold one actual loop step and induct on the remaining chunk
list length. ChunksExact.next removes exactly the head; Enumerate.next
performs its actual checked increment. Decode failure, noncanonical result,
and nonzero high component contradict successful return. The accepted head
uses the checked comparison equivalence and the recursive tail uses the
strictly shorter list. This is symbolic list induction, not unrolling any
concrete payload or replaying a field recurrence.

The wrapper relates actual chunks_exact output to the complete chunks
in List.toChunksExact32, then use the byte theorem to expose an equal
32-byte array, all eight canonical LE4 words and exact packing with zero
high component. No claim applies to the ignored remainder. Row-table
divisibility and exact chunk/remainder partition are separate coordinator
lemmas; full-payload coverage requires explicit composition with them.
Rust/source refinement, prefix state, challenges and first reads remain
separate boundaries. No production source is modified here.

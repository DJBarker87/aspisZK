## Stage 1: source audit and obstruction

`evidence/s2d-20261023/source-audit.json` inventories every lexical `?`,
`map_err`, explicit error, Box allocation, PDA derivation, clock read and
return-data syscall in 22 release-reachable adapter functions. The generator
`audit.py --check` verifies source hashes and the verbatim observer extraction.
This is a source inventory, not a control-flow or totality proof. Imported
children retain their separate refinement obligations.

The requested universal statement "each allocation failure rejects with cleanup"
is not justified for this source. `decode_public_statement_box`,
`decode_master_box`, `decode_checkpoint_box`, `scan_proof_buffer`,
`asq8_common`, transfer/withdrawal constructors and the live snapshot use
`Box::new`, without fallible allocation or a mapped ProgramError. OOM can
abort; Rust does not promise normal unwinding/Drop for that path. This is a
source-level obstruction, not a demonstrated SBF execution or SDK bug.
Fallible verifier `Error::Allocation` is different: `first_decoded` and stage2
map it through `error`, which logs before returning InvalidInstructionData.
No release change is authorized here. A total experiment needs an explicit
abort outcome with its actual prefix, or a separately proved runtime allocation
admission bound. Neither may be silently replaced with successful cleanup.

Stage2 clears return data after its initial shape guard and before validation.
Later validation/Clock/PDA/verifier errors retain this earlier syscall and any
hash/query/log effects. `emit_result` runs only after verifier success; it can
still fail after all verifier queries. A checkpoint length mismatch in stage1
likewise occurs after TX1 effects. No rejection permits deleting those prefixes.

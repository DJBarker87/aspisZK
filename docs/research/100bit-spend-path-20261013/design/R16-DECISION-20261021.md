## Scope and result

The requested R19 specialisation has an additional constructor-erasure
obstruction, beyond the free-decision problem already recorded in R15.
An erased decision cannot distinguish a row-31 `.payload bytes` from
`.second bytes word` (or `.c2 bytes word`). `InstanceFields` requires
`LiteralTranscript.valid 31 m31`, which accepts only `.payload` at that row.
The binary compiler replaces word metadata but preserves constructors.
Consequently **every non-vacuous erased decision has an accepted prover for
which no SourceInputs satisfies R16**. This is a counterexample to the
requested universal model specialisation, not a reachable Rust attack.

No existing module, concurrent-worker module, protected lean-candidate,
M10 instrumentation, Rust source, wallet or key is changed. No premise is
silently repackaged as a new source/model join.

## Required repair

The protocol must own the literal constructor schedule before R19 can be
specialised. `CanonicalLiteralProof.liftProver` is an existing candidate:
it constructs messages by row from a decoded wire proof and proves their
validity. R19 currently quantifies over arbitrary `RawCutProverCompiler.Prover`,
not only such canonical outputs. Restricting that quantifier, replacing the
protocol/message carrier, or canonicalising in the verifier/compiler is a
further model change; it is not merely specialising d while carrying every
other parameter/premise verbatim. Existing Lean modules may not be edited by
this worker. A new endpoint with a canonical prover carrier would need an
explicitly reviewed signature specialisation and its byte-to-data and
sampler/refinement proof, not a claim that arbitrary P satisfies R16.

The checkpoint model is deliberately typed storage. It does not claim a
frozen byte serializer, authenticated runtime persistence, complete verifier
acceptance, R13/R14/R3, or an honest complete spend proof. Its non-vacuity
covers exactly the construction-owned first-match checks.

## Limits of the counterexample

`accepted_without_instance` proves failure of the construction-only R16 law
for arbitrary P. It does **not** assert that the retagged prover also meets
R13, R14, R3, R-wire or every other C3 hypothesis. For example R13's strict
`LiteralOpeningStages.readAt` checks the constructor at row 31. Thus the
result does not refute R19, nor rule out a different conditional endpoint
that derives part of R16 using retained hypotheses. The requested law has
only BoundaryEvidence and acceptance as its antecedents; the compiled
counterexample targets exactly that law, with no extra source assumptions.

## Type audit and the precise false inference

All paths in this section are relative to
`docs/research/100bit-spend-path-20261013/`.

- `lean/RawCutProverCompiler.lean:25` defines `RunView` as an ordinary
  recorded `View` with `(public, proof)` and a Boolean. There is no dependent
  certificate of verifier acceptance or input-size bound in that type.
- `lean/RawExtractorCostComposedV2.lean:45` defines numeric parameters.
  The comment at `:47` calls `logSize` an actual log-length bound, but the
  structure has no proposition linking it to an input.
- `LedgerRefinement` at `lean/RawExtractorCostComposedV2.lean:85` fixes `p`
  outside `∀ run coins`; its only run restriction is `run.2.2 = true`.
  In particular the read obligation at `:89` contains neither
  `run.1.length ≤ p.logSize` nor membership in a size-restricted experiment.
- `lean/RawCutRecordedWordsExecutable.lean:21` is the actual recursive scan;
  `cutBeforeExec` at `:34` uses it. The C1/C2/folded maps at `:56`, `:61`,
  `:66` call that cut. `lean/RawCutWordsFromRunExecutable.lean:28` supplies
  `frameFromView run 0` as the C1 frame.

The false inference is **stored acceptance implies a fixed log-size bound**.
For any seed view, frame F and natural bound B, retain the seed's public/proof,
set the acceptance bit to true, and use a log of B+1 copies of
`(F ++ [0], default)`. Since `length (F ++ [0]) = length F + 1`, every input
misses F. The actual first-index recursion inspects exactly B+1 entries.
No concrete long list is evaluated: induction proves this symbolic shape.

`RawRecordedLogCostObstruction.accepted_log_unbounded` refutes the size
inference. `RawRecordedInitialCutObstruction.accepted_initial_cut_unbounded`
(`lean/RawRecordedInitialCutObstruction.lean:23`) specializes the example to
F = the actual initial commitment frame. The frame is independent of the log
at row zero (`:11`), so the example preserves the public/proof, not just a
freely chosen frame. In particular B can be `7*p.n*p.logSize`.

**Limits of the counterexample.** This does not prove these views arise from
an accepting frozen experiment. It also does not prove that a parse failure
or rejected private tape evaluates a word/cut. The exact no-ledger theorem
at `lean/RawRecordedInitialCutObstruction.lean:42` explicitly assumes that
an instrumented implementation charges this demanded initial scan on every
accepted-tagged view. Under that adequacy premise, the fixed-parameter read
obligation contradicts the example. We do **not** assert an unconditional
`¬ ∃ e p, LedgerRefinement e p`: the interface alone does not constrain
resource labels to actual work. Nor do we claim a full-extractor lower-bound
proof for every branch. What is refuted unconditionally is the missing
size invariant needed to apply the advertised finite-log accounting on
this domain. A full extractor ledger is not obtained here.

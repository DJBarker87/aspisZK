# J1 public parser reuse inventory (2026-10-15)

Base source revision: `c7b5a949e2274b15ac91a6299fbbc3da691aeb3c`. This is a declaration/API inventory, not a public-byte source-refinement claim.

## Existing Lean model and codecs

- `R0P.Public` is a typed record, not a byte parser: `Variant`, two `Fin 8 → K` digests, `assetId : K`, optional recipient/withdrawal values, change digest, `nextPairIndex : Nat`, and two `Fin 20` frontiers (`v8-r0-sem-proof-20261008/lean/R0P/Core.lean:34–56`, SHA-256 `eba6bb784803b5f00922724efc9997a8d5ab6bc55cd8c100bffd8a397dabe1f9`). `PublicOptionShape.canonical`/`check_eq_true_iff` (`PublicOptionShape.lean:14–27`, SHA-256 `0fb33426084f3452a53dec73cf7c982e447a4c671e4bdf029807fbdc51232ae2`) checks only variant/Option shape and nonzero withdrawal amount. It does not consume bytes, enforce a public layout, canonicalize fields, or decode index/frontier integers.
- `PublicInitParse.parse_addr` and `parse_sound` (`PublicInitParse.lean:15–36`, SHA-256 `cd7137ec47e4374dc3e776ab01638b12cc7a842920a38980f6fccdb9dbdf775a`) validate/describe the framed initialization address. The public byte list remains opaque: successful parse yields the exact frame `domain ++ [0] ++ lengthBytes pubBytes.length ++ pubBytes ++ bytes c1`. `PublicInitFrame.lengthBytes` is connected to four-byte little-endian words by `RecordLengthCodec.lengthBytes_eq_encodeWordLE` and `decodeWordLE_val_eq_iff` (`RecordLengthCodec.lean:14–46`, SHA-256 `b08edaad871aa12ddd7b0b0e158525246a43aac5c3045817b15f34b7d4b298ba`); these facts concern the length prefix, not the internal public payload.
- `RetainedFieldByteCodec` provides `RawWord := Fin (2^32)`, `encodeWordLE`, `decodeWordLE`, exact u32 round trips, and canonical M31 codecs (`RetainedFieldByteCodec.lean:12–78`, SHA-256 `d29e2d982954b31fc3c68d225df3aa78124f153e9e2fcc99ffddca14f65fc18b`). It has no u64 decoder. `M31ParserRefinement.from_le_bytes_refines` relates the retained four-byte canonical M31 decoder to the retained Aeneas field parser (`M31ParserRefinement.lean:35–61`, SHA-256 `ba8e2b3be28c8bdfa2e4e7a35895c951225ec650aa9be3171d6b2f6e68c6d4d1`); `ExtractedM31Parser.field.M31.from_le_bytes` is the translated method (`ExtractedM31Parser.lean:24–39`, SHA-256 `04626b750f04f7567d3bec71e380fd8a8cc6a4462762881c588b83b179820371`). The retained/candidate QM31 parser modules similarly establish four-limb order and successful canonicality (`CandidateQM31Parser.lean`, `CandidateFieldCanonicality.lean`); these are field parsers, not public-structure parsers.
- `AeneasWordCodec.aeneasWord_val_eq` supplies a U32/value relation. In the inspected current Lean artifacts, I found no extracted or retained U64 `from_le_bytes` declaration and no theorem mapping the R1 public `next_pair_index` eight-byte encoding to `R0P.Public.nextPairIndex`.

## Rust public wire surfaces

- `payment_relation.rs` specifies 216-byte ASCP/ASWP payment records (`:28–43`, SHA-256 `8b543d3de5aa29d1e510e8ca18bd2bc6dae6c405b7d6f97402c572dfdbab2588`). `decode_pool_v1_private_transfer_public_v1` (`:376–413`) and `decode_pool_v1_withdrawal_public_v1` (`:415–449`) enforce exact length, header/version/kind/digest-encoding/reserved bytes, canonical digest decoding, canonical asset id (`decode_common`, `:337–374`), and variant-specific fields. ASCP requires fee/reserved bytes 148–152 to be zero; ASWP reads those bytes as a little-endian u32 amount. Sequence is little-endian u64 at bytes 72–80. These are concrete Rust APIs, but no corresponding Lean public-record parser/refinement was found.
- `decode_pool_v1_pair_forest_terminal_statement_v1` parses an 1880-byte ASF8 envelope (`pair_forest_terminal.rs:29–41,386–415`, SHA-256 `becc01f162f23cd9b4a7fd3780be5a441c9b7265f3078282244cc938da63a16c`), dispatching to the lane-transition and ASCP/ASWP decoders. The file’s module header (`:1–5`) marks the terminal format inactive for the production `aspis-pool` path. That header does not describe the separate experimental R1 cost-probe acceptance path: `programs/r1-cost-probe/src/lib.rs::first` directly calls this decoder at line 25, converts the result to `r0::Public`, and calls `verifier::tx1` at lines 26–27 (SHA-256 `294546036e6cf8bb8dcc1f1f4a65c5e0887ac04593cdda801f58c75a284d582a`). With the `pool-adapter` feature, `r1_pool_adapter::stage1` accepts `[3,10]` or `[3,11]`, validates the statement, and reaches `super::first` at `r1_pool_adapter.rs:867–935` (SHA-256 `b2adab8610189a5031fc6f28a7cdeef12c01aa292423743cb4696aa3ee1590a4`). Therefore ASF8/ASCP/ASWP parsing is an actual acceptance surface of the experimental R1 verifier, while the production-inactive module comment remains accurate for the mainline Pool route. This inventory does not claim that the experimental path is deployed or prove byte-to-Lean refinement.
- The R1 semantic verifier itself receives an already-typed `Public<'_>` argument. Its R1 wrapper reaches it only after `lib.rs::first` parses the ASF8/ASCP/ASWP bytes as described above. `r1_semantic::verify_observed` then calls `public.public_bytes()` and initializes the semantic transcript with those serialized bytes and the C1 root (`crates/aspis-r1-cost-probe/src/r1_semantic.rs:58–76`, SHA-256 `964f008a0841246fe3638ce2e492d12d18d78302565aa57f8c7df4d079579ce3`). The typed public’s `public_bytes` serializer is in `pair_forest_semantic_terminal.rs:1989–2040` (SHA-256 `2bb7db64dc53c8a268e42b0fe46da64ab1afcb03d28bbec2569b2abc30cbc074`): it serializes variant, anchor, nullifier, asset, optional recipient, change, optional withdrawal amount, source `next_pair_index`, source frontier, next root, and next frontier; it checks each M31 limb `< P`. The serializer does not itself parse input bytes into `Public`; that parse is performed by the R1 wrapper.

## Reuse boundary and missing adapter

Existing reusable pieces are (a) exact-u32 little-endian arithmetic and M31 canonicality, (b) retained M31/QM31 parser refinement and limb order, (c) initialization-frame prefix/suffix parsing with opaque `pubBytes`, and (d) a typed `PublicOptionShape` checker. The missing bridge is a Lean parser/refinement over the actual R1 accepted public wire surface that establishes the exact `R0P.Public` fields, option/variant conditions, fixed digest lane values, and index/frontier interpretation from bytes. In particular, no reusable Lean theorem currently covers ASF8/ASCP/ASWP headers and offsets; no u64 little-endian lemma feeds `nextPairIndex`; and the existing opaque `PublicInitParse` does not fill that gap. The experimental R1 Rust decoder provides a concrete accepted byte path to formalize. This inventory does not establish a byte-to-Lean refinement or production deployment status.

## Exact ASF8 nested-decoder and validator conditions

This supplement separates byte decoding from later validation/binding; it is still source inventory only. Current source hashes at the time of this inspection:

- `pair_forest_terminal.rs`: `becc01f162f23cd9b4a7fd3780be5a441c9b7265f3078282244cc938da63a16c`
- `pair_tree_profile.rs`: `8a7a4c7bdd3fe0ecd14d6fc920182be434ab92536924de22d269d906be3387b2`
- `pair_terminal.rs`: `820710b2284ea967bb4b9a6d2ceb6cb171ac185b01df816db99db6ea78e629a3`
- `payment_relation.rs`: `8b543d3de5aa29d1e510e8ca18bd2bc6dae6c405b7d6f97402c572dfdbab2588`
- `pair_forest_semantic_terminal.rs`: `2bb7db64dc53c8a268e42b0fe46da64ab1afcb03d28bbec2569b2abc30cbc074`

The top-level `decode_pool_v1_pair_forest_terminal_statement_v1` (`pair_forest_terminal.rs:386–415`) requires exactly 1880 bytes, ASF8 magic, the supported terminal version, a recognized transfer/withdrawal kind, and the supported digest-encoding version. It decodes the common block and nested 1520-byte late statement, chooses ASCP or ASWP from the outer kind, then calls `validate_pool_v1_pair_forest_terminal_statement_v1` before returning. The statement validator (`:227–276`) additionally requires nonzero master/checkpoint/selected-lane account keys and an output lane below the lane count; validates the chosen payment record; binds payment pool to master, payment deployment domain to the late snapshot domain, late snapshot pool to master, payment anchor sequence to checkpoint sequence, payment anchor root to the historical global anchor, and output lane to the nullifier-derived lane; and re-encodes the late statement to exercise its validators.

Nested payment checks are in `payment_relation.rs`:

- Both ASCP and ASWP decoders require exactly 216 bytes and check their expected magic, version, transition-kind byte, digest-encoding byte, and reserved byte (`:314–334`, `:376–449`). Common fields require nonzero pool and deployment-domain identifiers; anchor sequence at most `POOL_V1_LEAF_CAPACITY` (2^20); canonical anchor and nullifier digests; and asset ID `< P` (`:182–195`, `:337–374`).
- ASCP checks bytes 148–151 against the canonical fee, which is exactly zero (`:28–43`, `:376–391`), then requires canonical recipient and change digests (`:220–229`, `:392–412`).
- ASWP reads the amount as little-endian u32 and includes a 32-byte destination account (`:415–449`). Validation requires `0 < amount < VALUE_LIMIT` with `VALUE_LIMIT = 2^30`, a nonzero destination account, and canonical change digest (`:232–245`; value limit at `spend.rs:9`).

The late public statement decoder (`pair_tree_profile.rs:583–638`) requires exactly 1520 bytes and checks magic, version, item count, header length, snapshot length, afterstate length, total length, and zero reserved tail; it decodes the nested snapshot and afterstate and requires `snapshot.next_pair_index + 1 == afterstate.next_pair_index`. The 768-byte snapshot decoder (`:443–526`) checks exact length, magic/version, zero reserved bytes, tree-format binding, nonzero pool/domain, `sequence == next_pair_index`, `next_pair_index < 2^20`, and canonical current root/frontier digests. The 688-byte afterstate decoder/validator (`pair_terminal.rs:122–195`) checks exact length, magic/version, pair format, digest format, success code `1`, `0 < next_pair_index <= 2^20`, and canonical next-root/frontier digests. Thus the on-wire integers are u64, but the decoded pair index has narrower capacity constraints.

The full host-side `validate_accounts` path is separate from the ASF8 parser (`pair_forest_terminal.rs:671–734`, called by the host verifier at `:736–742`). It validates master/checkpoint/lane account encodings; binds master account and identity pool, deployment domain, and asset; binds checkpoint account/master/sequence/global root; binds selected-lane account/master/id and initialized-lane bit; requires the runtime withdrawal-destination account to be zero for transfers or equal to the ASWP destination for withdrawals; and compares snapshot sequence/index/root/frontier against the selected lane's live tree. The returned-result validator (`:539–559`) separately binds transition kind, accounts, output lane, nullifier, and verified afterstate to the statement. These host/account bindings should not be attributed to `decode_pool_v1_pair_forest_terminal_statement_v1` alone.

For the semantic `public_bytes` boundary: its serializer validates each emitted M31 `< P` (`pair_forest_semantic_terminal.rs:2002–2040`), but does not itself enforce withdrawal positivity/range or transition validity. The ASF8 ASWP decoder's public validator does enforce `0 < amount < 2^30`; the semantic terminal's own `composition_parts` independently rejects zero or amounts `>= 2^30` and calls `validate_transition` (`pair_forest_semantic_terminal.rs:1234–1240`). `validate_transition` checks source pool/domain, `sequence == next_pair_index`, source index `< 2^20`, increment by one, and active/inactive frontier equations (`:180–209`). The Lean `SemanticPublicWire.parsePublic` only enforces canonical M31 decoding and variant/option shape with nonzero withdrawal; it does not model the broader ASF8 envelope, account bindings, amount upper bound, or transition checks. This is the exact scope boundary visible from the inspected definitions, not a conclusion about any refinement theorem.

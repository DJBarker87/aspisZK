# R16 canonical-prover reduction — 21 October 2026

Branch `codex/cx-r16-canon-20261021`, base `2f021de67`.

## Result and stages

The universal schedule-valid erasure-preserving reduction requested in the
latest C3 addendum is false at this interface. This packet separates the
useful erasure congruence from the missing admission condition. A proof can
contain `.initial root word` at row 31; its erasure is `.initial root`, while
all valid row-31 messages erase to `.payload bytes`. This is a distinction
in the erased carrier itself, rather than erased word metadata.

1. `R16CanonReduction`: total erasure-preserving constructor retagging,
   unchanged prover query log, verifier program congruence, unchanged
   original experiment log/public/acceptance; conditional schedule validity
   and a counterexample to total valid lifting.
2. `R16CanonExtractor`: executable commitment replay, extractor output,
   returned relation and failure mass factor through the actual observations.
3. `R1FinalSoundnessBinPerQueryCanon`: endpoint obstruction and independent
   checkpoint composition, with an honest unchanged headline signature.

Compilation results, exact theorem statements and remaining joins are added
below as each stage completes. No existing Lean module is edited.

## Why rejection does not repair the stated reduction

`UnifiedSampler.samp` explicitly totalizes a misplaced initial message using
`UnifiedSampler.invalid`; it does not itself reject. `RawCutProverCompiler.verifier`
passes the final erased prefix/message to arbitrary `d`. In particular,
`d := fun _ _ => true` accepts malformed schedules. Parsing and rejecting a
misplaced `.initial` would change that acceptance. The new endpoint module
proves this on actual 33-row erased transcripts, not only individual rows.

An erased decision *can* reject an initial-versus-payload mismatch. This
packet does not claim every erased decision has the stronger obstruction.
It refutes the requested exact reduction for every P at the existing
arbitrary-d interface, including a reduction only on accepted runs. A
future endpoint specialising d to an admission-checking decision could
make `Shape` a consequence of acceptance. That is an additional model
construction, not a consequence of retagging or byte persistence.

The useful total `R16CanonReduction.canon` preserves all erased messages,
including malformed initial placement. Its canonical schedule is proved
under exactly this condition (verbatim):

```lean
def Shape (pf : LiteralProtocol.Proof) : Prop :=
  ∀ i, i < 33 → UnifiedSampler.messageValid i (LiteralTranscript.erase (pf i))
```

This is a sufficient condition for schedule validity, **not** a claimed
strictly weaker replacement for R16: R16 also needs public parsing, successful
query scanning, and exact query/rho placements. `CanonicalLiteralProof.liftProver`
expects a different input program returning `DecodedInput`; it does not
supply this condition for arbitrary `RawCutProverCompiler.Prover`.

## Extractor and failure transfer

`RawCommitmentFrameReplay.frameFromView` uses the recorded log, public
statement, and proof to replay commitment frames. Equal logs alone are
insufficient evidence for this implementation. The symbolic factorisation
uses equal logs, equal public statements and pointwise equal erased messages.
`frameAt_congr`, `successor_congr`, `stateBefore_congr` and
`frameFromView_congr` prove replay congruence without enumerating field or
leaf universes. The same recovered words give equal ordinary extractor
outputs for every private tape. Successful returned witnesses satisfy the
unchanged public relation. With equal acceptance, `failureMass` is equal.

The cost wrapper's `value` field transfers the witness value, but its
arbitrary resource annotations are not asserted equal. No M10 ledger or
instrumentation file is edited, and no new cost-refinement claim is made.

## Constructed checkpoint and R16/R15 status

`writer_premise_of_checkpoint_acceptance` composes the existing strict query
reader with `R16DecisionCheckpoint`'s typed saved-ten/resumed-twelve state.
It proves the exact R15 conclusion for arbitrary P provided accepted runs
reach that checkpoint decision on the same `source.data` and query bytes.
That model-admission implication is explicit. It is not discharged here,
and it is not renamed as a Rust byte-layout or P2′ persistence join.

The checkpoint model only owns first matching. It has no complete
`ErasedPrefix → ErasedMessage → Bool` decoder/decision implementation that
constructs public parsing, query scan success and exact rho placement.
Consequently it cannot supply R16 merely by being paired with canonical
message syntax. The requested h_R16_instance and h_R15_writer deletions
are not claimed. The headline remains R19.

## Scope of the obstruction and possible repair

The counterexample is not a refutation of R19, nor of every conditional
premise-reduced endpoint. It does not claim the malformed prover meets R13,
R14, R3 or R-wire. It targets the unconditional same-erased-transcript,
schedule-valid lift proposed for arbitrary P, and the accepted-only version
at the still-arbitrary d interface.

A refined reduction can leave malformed erased shapes untouched and prove
canonical validity only on executions accepted by an explicitly constructed
shape-checking decision. `canon`, `verifier_congr` and `valid_of_shape`
already provide that part of such a repair. This requires a concrete
admission theorem; none is inferred from the first-match-only checkpoint
model. Constructing the rest of the decoder/decision and transporting all
retained R19 premises to it remains open. No theorem here rules out that
future construction, and no additional assumption is silently introduced
as a premise deletion.

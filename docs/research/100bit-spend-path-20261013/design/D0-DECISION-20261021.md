## Demonstrated obstruction: erased input versus recovered words

The proposed direct composition has two different carriers:

```lean
-- Endpoint decision input:
ErasedPrefix → ErasedMessage → Bool
-- Reader/checker input:
LiteralAcceptanceTerminal.TranscriptRounds → SourceInputs → Bool
```

Erasure removes the C1/C2/final word metadata. The compiler fills that
metadata using `BinCompiledRunWordStability.wordsFromRun D`, a function of
the **complete recorded oracle log**, not merely the erased prefix.
`R16CanonRecorded.recorded_observations` preserves that log under retagging;
it does not reconstruct it from a decision input.

`D0ErasedWordObstruction.no_erased_final_reader` is a compiled counterexample
to an exact reader on all typed inputs: two prefixes have equal erasures
and final words constantly 0 and 1. `LiteralTranscript.vAt` distinguishes
them. This is a representation theorem, not a frozen accepting-run attack;
the witness prefixes are not claimed to be complete valid executions.
`checkpoint_separates` proves that the actual constructed checkpoint
accepts honest first-fold data and rejects fold+1 data. The alternative of
checking the checkpoint for every possible hidden word is vacuous
(`universal_checkpoint_vacuous`).

The opening identification also requires a **mathematical**, rather than
Rust-source, condition. The existing
`BinThreeCommitmentTypedOpening.typed_opening_at_cut` explicitly assumes:

```lean
(hout : ¬ hitsBad (AllAddressCollision.bad iv BinRawByteCollisionTargets.pred Q)
  emptyTable tr)
```

`D0OpeningRecoveryObstruction.depth18_counterexample` supplies an oracle
constantly equal to the zero digest, two different packed C1 leaves of
width 480 and salt width 32, a concrete eighteen-slot binary path, and a
single consistent log containing every opening read and a commitment-root
frame. Both openings succeed at the same root. One deterministic cut
recovery cannot return both packed leaves. The counterexample is proved
symbolically for every path before instantiating the eighteen-slot shape;
no depth-18 tree or leaf universe is normalized. `log_consistent`,
`frame_read`, `frame_target`, and `opening_reads` verify the other relevant
trace/target obligations; take Q to be the log's first-read count for its
budget inequality. The strengthened counterexample concerns recovered
**packed bytes**, so it also applies to the identity typed decoder, not
only to salt recovery.

This refutes dropping collision exclusion from that opening-to-word
sub-claim. It is not a complete countermodel satisfying all R19 premises,
and it does not prove every possible erased d₀ construction impossible.
It does demonstrate why the supplied pieces do not discharge the current
unconditional R13/R15 implications simply by composing their named checks.

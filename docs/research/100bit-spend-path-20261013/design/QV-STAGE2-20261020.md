and retained `evidence/stage2-continuation-20261020/generated/AspisR1Stage2/Funs.lean:2613,2625,2649`.

equation witnesses from the successful complete retained resume body. An

`candidate.rs:294` resumes, checks `next == SPLIT` and calls batch B at
`:303`. `batch_tree` uses query positions 10..21 (`:174`), and hashes each
leaf at `:185` before duplicate folded-index handling (`:186`). There are
three explicit tree calls (`:165`–167), hence 36 leaf calls even with
repeated folded leaves. Full-range indices are u; folded indices are u/4
(`:92`–104). The subsequent twelve-query arithmetic loop (`:307`) does not
perform Merkle hashing. The retained ordered-loop theorem is
`lean/Stage2ContinuationFacts.lean:13`.

Each occupied binary parent uses one digest, whether both children were
computed or one sibling was supplied (`multiproof.rs:155`–169). Siblings
are input bytes, not extra digest invocations. Root hashes are included
among parents. The full-range profile is fourteen levels bounded by k,
then 8,4,2,1: `14*k+15`. The folded tree has twelve such levels followed
by 8,4,2,1,1,1: `12*k+17`. The final two levels are present because the
folded tree is padded to the full depth. Thus for k=12 the parent bounds
are 183,183,161, totaling 527; the generic expression is

`stage2Budget k = 3 + 3*k + 2*(14*k+15) + (12*k+17) = 43*k+50`.

As with stage 1, other k need their own source/profile premises. The
algebraic formula is not an arbitrary-batch source-execution theorem.

The format's six slot capacities (`compact.rs:54`) are
[146,146,128,172,172,150], totaling 914. Batch B has capacity 494, and
`parents + 1 = supplied + distinctLeaves` in each occupied trie. Therefore
with twelve distinct leaves in each tree, B's parent bound is
494+36−3=527. More generally, commitment positions satisfy
`reads+3 = supplied+2*distinctLeaves`, so 494 supplied nodes and at most
36 distinct leaves give at most 563 positions. The Lean trie identity and
slot bound handle fewer distinct folded leaves. It would be invalid to
derive actual B consumption by subtracting A's maximum from an arbitrary
actual six-slot total; the separate B slot caps justify 494.

`finish_relation` has no Digest32 parameter or direct digest calls:
`verifier.rs:310`–322; retained `Funs.lean:3208`. Its callees perform round,
polynomial, weight/pairing and dot arithmetic. The source audit checks the
weight/fast-pairing/fast-dot files contain no Digest32 or sha256 invocation.
This is a designated verifier-core inventory. Arbitrary observer callbacks,
opaque backends, trace hooks and runtime helpers are not thereby proved
SHA-free. Their effect correspondence is part of R10/R14/R16.

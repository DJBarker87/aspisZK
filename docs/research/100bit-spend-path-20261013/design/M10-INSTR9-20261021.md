## Stage 1: executed public-parser allocation counters

`ListConstructorAllocationM10` counts constructor/result groups at take,
drop, append and equality recursion sites. `PublicCursorAllocationM10`
counts prefix copying, suffix traversal, bounded scalar decoding and
`Fin.cons` captures in the repeated fixed-width decoder. Scalar constructor
budgets are independent of decoded values (64 groups for M31, 128 for index).
`PublicParserAllocationM10` composes those counters through every public
parser branch, including failed prefixes. Its erasure theorem preserves both
the old value AND the old work, and its allocation-carrying StageSpec proves
`bits ≤ 1024 * parser work`. Counters are attached to operations and branches,
not to the parser's numerical upper work bound.

These are logical fixed-slot constructor groups, not macOS/Lean allocator
bytes. Instrumentation/proof bookkeeping is erased from the cost model.
Source allocation adequacy outside these described operations is not inferred
from returned-value equality.

Focused accepted attempts: list 1, cursor 3, parser 3. Peak accepted RSS
2886926336 bytes; zero swap. All current theorem audits use standard axioms.
Diagnostics and exact targets, argv, revisions, source/dependency hashes,
exit, wall time, RSS, swap and complete axioms lines are retained per attempt.
Failed proof attempts are retained and never retried with unchanged inputs.

No endpoint premise is removed at this stage. Continuation work follows in
subsequent commits.

## Stage 2: frame/recovery and typed-cache composition

`FrameConstructorAllocationM10` and `FrameReplayAllocationM10` attach counters
to serialization, cumulative append copies, last-write lookup, payload replay,
state recursion and final frame construction. Their erasure equalities preserve
the original work as well as values. `RecoveryParserAllocationM10` and
`RecoveryWalkAllocationM10` count failed and successful leaf/node parsing,
table construction, digest comparison buffers, path lookup, prefix cuts,
state reconstruction and slot-list construction. `TypedCacheAllocationM10`
counts cached indexing and all C1/C2/folded fixed-width decoding operations.

`AllocationBatchM10` sums element counters and batch constructor groups.
`PublicRecoveryAllocationM10.spec` composes these through the actual three
frame/recovery batches and typed caches. It proves
`stageCells run ≤ (BinPublicRecoverySharedStageM10.stage run).2` and carries
`1024*stageCells run` bits in the same extended StageSpec. No caller-selected
heap or allocator function is used for this public/recovery stage.

All seven stage-2 modules passed individually; accepted peak RSS
3417161728 bytes and zero swaps. Every theorem has a standard-axiom audit.
The full extractor endpoint remains unchanged pending GS and postprocessing.

## Stage 3: interpolation, polynomial rows, RR traversal and bank

`InterpolationAllocationM10` counts matrix constraints/cells and Hasse
arithmetic with degree-capped constructor tariffs, the existing exact kernel
backing-copy allocation events, vector normalization, and polynomial fold
construction. `RRRowAllocationM10` follows Taylor/fuel operations, every
row grid, scanner result and normalized reconstruction. `RRTraversalAllocationM10`
sums these on actual reached RR nodes/cursors, including aborted walks and
candidate-prefix copies. `GSScalarConstructorAllocationM10` uses the actual
raw gcd/division/binary-power operand schedules, with separate degree-capped
normalization and result groups. `GSBankAllocationM10` composes interpolation
and recovery through the proof-dependent bind and sums the 29+5 calls.
Basis construction and state setup are paid separately from matrix/kernel work.

All six stage modules and their generic fold/proof-bind dependencies passed
individually. Standard axioms only; zero swap; accepted GS-stage peak RSS
3431219200 bytes. A dependent-bind proof needed its additive inequalities
composed before simplification, to avoid treating definitionally equal
proof-indexed counters as unrelated arithmetic atoms. No limit was raised.

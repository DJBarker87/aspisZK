## Stage 1: allocation-carrying interface

`AllocationStageSpecM10.StageSpec` extends the existing stage interface with
an allocation field indexed by that stage's exact work counter. Each annotation
carries separate `width_law : bits ≤ W*elements` and
`creation_work : elements ≤ work` obligations. The sequence constructor sums
executed allocations; failed prefixes keep their allocations and skip later
stages. Its one option-result cell is charged to bind's existing work unit.
Both allocation bounds are proved without axioms.

Attempt 1 passed: exit 0, wall 16.55 seconds (time -l), peak RSS 2863366144
bytes, zero swaps; exact revision, hashes, argv, dependency fingerprint and
axioms output are in its receipt. This is a generic interface, not a claim
that arbitrary law-carrying data describes the source heap. Concrete source
constructors are still necessary; neither work nor returned-value equality
implies that an annotation is a faithful allocation count.

## Stage 2: concrete retained point storage

`Array.ofFn` itself. Erasure is exactly the old materializer; the count equals
the returned array size plus one. Symbolic lower-work lemmas avoid evaluating
any array or field value. They compile independently.

`GSPointRetainedAllocationM10.spec` extends the existing point-stage interface.
It counts 29 initial arrays, 5 final arrays, the two outer tables and their

Every retained cell is paid by a proved lower bound on existing work. This
is an exact retained-storage subledger at the stated slot tariff, **not** the
cumulative allocator trace of field arithmetic or the entire extractor.
The positive theorem is about the point stage, not an accepted protocol run.

## Stage 3: nonzero public/cache subledger and adequacy obstruction

`PublicRetainedAllocationM10` counts 589,824 recovered-leaf list cells and
2,359,302 typed array/capture cells: 2,949,126 retained cells in total.
The same extended stage interface proves that every cell is paid by existing
public-side work. `RetainedHeapSubledgerM10` fixes a concrete subledger,
`retainedHeap`, to those source-site counts. It proves, on every run and tape,

```
retainedHeap.bits run coins = 3019905024
retainedHeap.bits run coins ≤ 1024 * (completeCostedExtractor run coins).work
retainedHeap.bits run coins ≤ (1024*workConstant)*(run.1.length+1)
```

`acceptedView pub proof := ([],((pub,proof),true))` supplies an explicit
accepted-flag view with that exact positive count. This is the domain used by
AllocationBound; no claim is made that a protocol experiment produces this
view. The count is nonzero even when parsing fails, because the eager public
cache construction precedes the public parser. This result covers retained
public caches alone, not all allocations of an accepted extractor execution.

Public attempt 1 passed: exit 0, wall 20.936540208756924 s, peak RSS
3404906496 bytes, zero swaps. Retained heap attempt 2 passed: exit 0, wall
3.5680444170720875 s, peak RSS 3422863360 bytes, zero swaps. All thirteen
new theorem audits are standard. The retained-heap first diagnostic had a

inequalities before rewriting avoids transporting an allocation projection.

`AllocationAdequacyObstructionM10` formalizes the lead's warning. The zero
annotation satisfies AllocationBound and even the original full Resources
ledger. Any two HeapMirrors have equal returned values, including a mirror
that violates AllocationBound on every nonempty accepted domain. A positive
actual cell count cannot be bounded by the diagnostic zero mirror. These
five theorems passed with standard axioms (attempt 1, exit 0, wall
4.995158832985908 s, peak RSS 3421667328 bytes, zero swaps).
This is not a proof that a faithful full heap mirror cannot exist. It shows
exactly why a retained-only subledger, a reservation proportional to work,
or equality of eager returned values cannot discharge source allocation
adequacy.

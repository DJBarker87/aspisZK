# J5 word-message protocol interface inventory

Inspected at repository revision `c7b5a949e2274b15ac91a6299fbbc3da691aeb3c`. This is a reuse map of existing message and protocol types, not a proposed classifier or soundness proof. The relevant lead decision requires a separate idealised-commitment protocol `prA` whose words are messages, followed by a Merkle-to-`prA` compiler argument using causal recovery. It explicitly rules out satisfying arbitrary-table D2 with a raw `UnifiedProtocol` table adapter. This note therefore does not use table availability as an ideal-protocol message source.

The older `R0P.SemView` parser reads C2 from semantic message row 2 as `SemMsg.h1 h g`; the masked view first applies `unmaskSem` and obtains that base message. The R0Z idealized variant instead exposes a commitment handle/slot there. These are different representations, so the handle projection must not be described as a literal C2 word disclosure.

The R0Z opening payload offers indexed symbols, not one whole folded word `V`: `opened` is indexed by query, child, and column. Its `finalCoeff : Fin 256 → K` is a coefficient payload, while R0FS names the final object abstractly as `FinalMessage E`. Existing declarations thus offer reusable indexed carriers for final/query material, but no single existing constructor with the requested literal tuple `(C1, C2, folded V, final f, queries)`.

## Sampler and terminal interfaces

The old soundness protocol `R0P.SemD3Glue.combinedProtocol` has 31 rounds and uses `combinedSampler`; `combinedDecision` is the concrete old decision wrapper around `SemSource.decision B (valuePrefix P) m`. The masked `R0P.Mask.combinedProtocolZ` has 32 rounds and a parameterized `combinedSamplerAt`; the schedule and query/opening interaction are not the current 33-row R1 schedule. Separately, `R0FS.Protocol` is a five-round opening layer: values → γ, scalar → κ, unit → τ, polynomial → α, final message → query set, then opening response. Its `decision` checks the complete five-message shape and `Accept` predicate.

R1 has a smaller, explicit hosting interface but no built-in acceptance relation. `TranscriptView.Message` is `.initial c1 | .payload m`; `TranscriptView.Value` is `.ordinary v | .queries result`. `UnifiedSampler.samp` fixes 33 sampler rows: row 0 is the initial C1 frame, row 26 is reseeded, row 31 runs q22, and other valid payload rows use the ordinary duplex sampler. `UnifiedRun.transcript` and `UnifiedProtocol.protocol` preserve that chronology. `UnifiedProtocol.protocol` takes an explicit `extract`, totalizes its decode field to `none`, and makes no acceptance claim. `UnifiedVerifier.verifier` takes a separate decision function `Prefix → Message M → Bool`; the oracle wrapper instead accepts an oracle `Program` decision. Thus a future message sum type can syntactically hold additional word constructors while retaining the fixed sampler, but these existing declarations do not assign the desired word semantics or implement a classifier.

## Reuse boundary

The lead decision at [`LEAD-DECISIONS-20261015.md`](LEAD-DECISIONS-20261015.md), SHA-256 `46a6502de8deafae774a62a589c91dcfbe0791e186e8db36651078b80c81c8e4`, specifies `prA` as the word-message idealized protocol and a separate causal Merkle compiler theorem. It says the raw-table adapter does not meet arbitrary-table D2. The interfaces above are candidates for reusing message/prefix and sampler structure only; they do not establish the J5 classifier, its round checks, or a compiler/source correspondence.

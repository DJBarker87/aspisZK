# Merkle path geometry reuse inventory

This is a source inventory only. The cited Lean arithmetic and path model are not a proof that the Rust tree/path code refines that model.

## Existing Lean geometry and APIs

[`MerkleIndexGeometry.lean`](lean/MerkleIndexGeometry.lean) (SHA-256 `0e683666023ff93f40fa19d3ff4799e754e98521b4795f587f1769ac01cb5b3e`) defines `AspisR1.MerkleIndexGeometry.slots depth i` by prepending `i % 8` and recursing on `i / 8` (lines 12–19). Thus the list is least-significant base-8 digit first. `length_slots` proves list length equals depth; `index` and `index_slots` prove the inverse mixed-radix formula when `i < 8^depth` (lines 21–42). `slots6_injective` proves distinct `Fin 262144` indices yield distinct six-slot lists using `8^6 = 262144` (lines 53–60). `foldedIndex` is `u.val / 4 : Fin 65536`; `foldedIndex_decompose` proves `u = 4 * foldedIndex(u) + u % 4` (lines 44–51). These lemmas establish index arithmetic but do not mention a Merkle tree or Rust path array.

[`Merkle32Path.lean`](lean/Merkle32Path.lean) (SHA-256 `93ef63727b5fc596eec0084ec737e921d54719e8a87d276cc151b3e8b2c28270`) has the generic `Path slots` inductive family for `List (Fin 8)`, `nodeInput`, `foldPath`, and `inputTrace` (lines 9–20, 63–80). `foldPath` consumes the list head first, combining the current digest with the selected child slot and then recursing on the tail. `foldPath_cross_trace_collision` and `foldPath_injective_of_collisionFreeOn` are reusable path-binding results (lines 89–143); they assume corresponding literal input-trace collision facts and do not encode a numeric index.

[`MerkleTable.lean`](lean/MerkleTable.lean) (SHA-256 `3f474e66fced7516aef8732d2311f62be2228c34b697974172429198ad67a422`) defines a finite node-list lookup and `walk nodes : List (Fin 8) → Digest → Option Digest` (lines 22–27, 75–79). `walk` recursively walks the slot-list tail from the given root, then looks up that parent and selects the head slot; for a least-significant-digit-first list this consumes the root-side slots in reverse list order, ending at the queried leaf. `walk_mem_targets` shows a successful result is among the root or recorded child digests (lines 81–104). It does not assert a fixed path length or any index conversion.

[`MerkleLeafRecovery.lean`](lean/MerkleLeafRecovery.lean) (SHA-256 `ee5096e704e5ccc3f601f7efd93c686af812fe633d8765af209d47aa3c94e395`) defines `recover nodes leaves slots root` as `walk` followed by `lookupLeaf` (lines 17–20, 45–47). `recover_or_bad` provides a collision/missing-hit alternative for a supplied `Path slots`, with consistency, leaf-width, and root-equality premises (lines 49–64). It accepts `slots` directly; it does not derive them from an integer index.

There is no existing theorem found that identifies `MerkleIndexGeometry.slots 6 u` with the slot sequence returned by the Rust `Tree.path(u)`, nor a Lean theorem connecting the current Rust `verify` path loop to `MerkleTable.walk`. `NaturalProjection.parentIndex`, `slotIndex`, `childIndex_parentIndex_slotIndex`, and associated old `FirstFoldRestoration` results are 4-way FRI/fibre-coordinate facts (`NaturalProjection.lean`, SHA-256 `add9c506d5cbf5c55447c9df156a52eb2298fe5ecf53faff2ea6a9654152726a`); they are not the eight-way Merkle path codec.

## Rust source shape

The R0 shared source defines `FIBRE_COUNT = 1 << 18` (`crates/aspis-core/src/r0/mod.rs`, SHA-256 `709f1d0d9be9d3ee74e2b63e13065f5a91c878ba77ed2d2e97a414fbbc646aca`, lines 30–35). [`r0/merkle.rs`](../../../crates/aspis-core/src/r0/merkle.rs) (SHA-256 `6df6b25bf5b29dd2744af9db645e3c5818fa9256a454f175db4b750919ce7224`) declares a six-level `Tree` over exactly `FIBRE_COUNT` leaves (lines 39–59). `Tree::path` starts with the queried index, computes `skip = index % 8`, emits seven siblings in ascending child-slot order with the selected child omitted, then divides the index by 8 at each level (lines 64–75). `verify_pair` uses the same `% 8` selection and `/ 8` update for six levels (lines 77–103).

The R1 cost-probe prover has the same initial C1/C2 tree shape through the shared commitment backend. In [`host_commitment.rs`](../../../crates/aspis-r1-cost-probe/src/host_commitment.rs) (SHA-256 `551c4f8a0df50e0b53ab7e79d4e71b8c6afe417043c55caa1c377da3388f890c`), it allocates `FIBRE_COUNT` leaves, serializes each leaf's four slots, and constructs a `Tree` (lines 167–195); openings attach `tree.path(u)` (lines 206–217). Its folded commitment is more specific: [`prover.rs`](../../../crates/aspis-r1-cost-probe/src/prover.rs), SHA-256 `a7e20e5eb2fb706f2bdb51371466d4ee02c6fcabc67a427495a3b9276d9495fd`, builds a vector of `1 << 18` leaves but fills only indices `u < 1 << 16` from four folded-word entries and puts a zero 128-byte payload in the remaining leaves (lines 207–223). A query for the folded commitment uses `u.get() / 4` both to select the folded word and to request that tree path (lines 239–255). So the query-addressed active range is 65,536 indices, while the concrete complete tree supplied to `Tree::new` still has 262,144 leaves including the padded suffix.

The current verifier's `merkle_path` applies the same six rounds of `index % 8` followed by `index /= 8`, reconstructing each eight-child node from the current value and seven siblings ([`verifier.rs`](../../../crates/aspis-r1-cost-probe/src/verifier.rs), SHA-256 `2cab573be46ca69b5d82837e5221a9a499d3b6dc1f89b801e388b4e8b1fe01cd`, lines 120–128). `query_with_geometry` verifies the initial trees at `u` and the folded tree at `u / 4` (lines 242–263). This is a structural source match to the base-8 and `/4` arithmetic above; no source-refinement theorem was found.

[`TypedRecoveredWords.lean`](lean/TypedRecoveredWords.lean) (SHA-256 `85243ca24d3e9fc6272847244b77796cd3f7ea98397fc563783a212c6b8e1350`) has a separate finite-vector projection: `queryLeaf i = i.val / 4 : Fin 262144`, `querySlot i = i.val % 4 : Fin 4` for `i : Fin 1048576` (lines 25–29). This models mapping four evaluations into one leaf and selecting a slot. It is not a path-digit theorem.

## Reuse boundary

The reusable formal components are the generic six-slot/index bijection arithmetic (`length_slots`, `index_slots`, `slots6_injective`), the abstract eight-way path/collision model (`foldPath`, `inputTrace` and their binding theorems), and the finite list-table recovery (`walk`, `recover`). The missing bridge is an explicit statement that the index-derived six slots give exactly the slot sequence used by the concrete `Tree.path`/`merkle_path`, including the folded `/4` index and the padded suffix convention. The present source inspection supports the correspondence description only; it is not a compiled Lean result or a source-semantics proof.

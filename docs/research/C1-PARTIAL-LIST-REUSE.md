## List-decoder algorithm and complexity boundary

The exact multiplicity-three GS development is `docs/research/v8-wide-reference-20261005/lean/Wide/MultiplicityThreeGS.lean` (also mirrored under `AspisFormal/AspisFormal/K1/V7Tag73ExactMultiplicityThreeGS.lean`). It proves mathematical interpolation/root/list facts for the initial circle code. The parameters are `multiplicity=3`, `yDegree=112`, `initialWeightedDegree=114689`; the initial interpolation budget is 6,480,098 monomials versus 6×1,048,576 constraints, with degree `< 3×38,230` (`:54-90`). `exactInitialInterpolationCoefficients` is `noncomputable` and uses `Classical.choose` from `exists_exactInitialInterpolation` (`:1006-1022`). `exactInitialDecodedCandidates` filters `Finset.univ` of all messages by root-substitution and 38,230 agreement predicates; `exactInitialGSDecode` is its `.toList` (`:1051-1065`). `exactInitialGSDecode_mem_iff`, `exactInitialGSDecode_nodup`, and `exactInitialGSDecode_length_le_100` prove the exact mathematical list specification and cap (`:1083-1106`, `:1172-1185`). The boundary structure `ExactMultiplicityThreeGSBoundary` records interpolation coefficients/kernel, roots, decoder completeness/soundness and list cap, but no runtime field (`:1187-1221`).

The operational interface is `AspisFormal/AspisFormal/Pool/AlgorithmicCircleDecoderV7.lean`: `ExactDecoderInstantiation` takes `initialDecode`, completeness, soundness, cap and an `initialDeterministicPolynomialTime : Prop` field (`:191-219`); `initialAlgorithm` transfers that proposition to `AlgorithmicListDecoder.deterministicPolynomialTime` (`:261-274`). The generic `AlgorithmicListDecoder` itself has `deterministicPolynomialTime : Prop`, not executable code or a complexity witness (`AspisFormal/AspisFormal/Pool/KnowledgeExtractorInterface.lean:104-115`). The GS source does not instantiate that complexity proposition with an implementation. The audit explicitly records that deterministic polynomial-time interpolation/factorization is not proved ([v7-exact-correlated-agreement-audit-20260827.md:216-224](</Users/dominic/ZK/.worktrees/100bit-spend-path/docs/research/v7-exact-correlated-agreement-audit-20260827.md:216>); see also `v7-exact-multiplicity-three-gs-audit-20260827.md:187-199`). The C1 list construction additionally takes each supplied decoder output and filters a finite Cartesian product. I found no repository theorem implementing standard GS interpolation/factorization with an execution or complexity bound; the formal result is an exact finite mathematical list, whose displayed Lean construction includes a full finite filter.

## 1. Bytes, from the code

Every Aspis row uses `Transcript` in `crates/aspis-r1-cost-probe/src/transcript.rs`:

- `absorb(row, payload)` (lines 19–21): `state ← H(state ‖ 0x00 ‖ 0xa0+row ‖ u32le(len) ‖ payload)`.
  `Digest32::digest(&[..])` hashes the concatenation of the parts.
- `block(row, payload)` (lines 22–27): absorb, then `block = H(state ‖ 0x01)`,
  then `state ← H(state ‖ 0x02)`.
- `scalar_k(row, payload)` (lines 36–39): `qm31_sample(block(row, payload))`.
- `resume(hash, state)` (line 18): sets the state, hashes nothing.

`sampler.rs` lines 20–51: `qm31_sample` reads the 32-byte block as a
little-endian 256-bit integer and takes its four low base-P digits
(P = 2^31 − 1), `c0 = (d0, d1)`, `c1 = (d2, d3)`.

The final sumcheck (`fused.rs`, `summed_final_checks`, lines 520–534;
`ROW_CLAIMS = 33`, `ROW_ROUND = 34`, lines 480–481) starts with
`Transcript::resume(hash, p.state)` (line 522). `p.state` is `t.state` after
`scalar_k(row+1, &[])` in `Prepared::new` (`verifier.rs` lines 96–101), with
`row = 31` because `parse_shape` forces variant S2 (`fused.rs` lines 40–48;
S2 folds twice, `transport.rs` line 8). So row 33 continues from row 32's
advance output, with no start frame and no reseed.

Field encodings (`aspis-core/src/field/wide_exact.rs`): `to_le_bytes`
(lines 273–279) writes the eight limbs of `to_limbs` (lines 238–249), each as
four little-endian bytes. `from_le_bytes` (lines 255–271) requires exactly 32
bytes and, through `from_limbs` (lines 207–211), every limb below P. Otherwise
it returns `None`.

Here `sN` is the state after row N (row N's advance output), `s` in the
squeeze and advance columns is the state just absorbed, and the label bytes are
`0xc0 = 0xa0+32`, `0xc1 .. 0xc7 = 0xa0+33 .. 0xa0+39`. `0x40 = 64`.

Canonicality. On row 33, `claim` and `rhs2` are values the verifier computed,
so `to_le_bytes` is canonical by construction. On rows 34 to 39 the absorbed
bytes are the certificate bytes verbatim. Both halves are parsed with
`from_le_bytes` before the absorb (lines 528–529), and the verifier rejects with
`Error::Parse` before `scalar_k` if a limb is non-canonical. So every absorbed
round payload is `wideBytes(c0) ‖ wideBytes(c2)` with all sixteen limbs below
P. The Lean model writes this as `Protocol.roundPayload`. The Lean model does
not prove that `from_le_bytes` is the inverse of `wideBytes`. That is a Rust
fact read from the code above.

Bytes I could not confirm from the code: none for rows 33 to 39. One
dependency: that R1's model of row 32 (Lean `semChal`, i.e.
`algebraMap (qm31Sample s)`) refines the Rust `qm31_sample` is R1's own claim.
Rows 33 to 39 call the same Rust function `scalar_k` with the same sampler,
so they inherit exactly R1's row-32 correspondence and nothing more.

## 3. The byte-level decoder: a deliberate deviation from "same construction"

Re-running R1's chain `RawUnifiedDecoder → RawLiteralDecoderDensity →
RawAdaptiveLiteralDecoder` over the 40-row dispatcher would mean re-proving
`UnifiedDecoderCanonical.decode_good` (own and pending addresses canonical)
for all of R1's components as well as the new one. I did not do that.
Instead:

```
decAspis fin a T := match dec a T with
  | some r => some r
  | none   => match finalRow a with | some n => fin n a T | none => none
```

`finalRow a` is the dispatch row of `a` read as an absorb frame, kept only
when that row is in 33..39. Proved: `decAspis_of_r1` (equal to R1's `dec`
wherever `dec` decodes), `dec_none_of_finalRow` (R1's `dec` is `none` on every
frame of a new row, through public selection, canonical decoding,
`atCanonical_none` and `Decoder.r1_none_of_final`), and `decAspis_final` (on
such a frame `decAspis fin = fin n`). So `decAspis` is the disjoint union of
R1's decoder and the new component, and R1's density and law facts about
`dec` apply unchanged on its part. The concrete `fin` should be built from an
Addr-level component through `CanonicalRawTrace.decode` and the
canonical-address lemma, for the new component only.

### 4.2 Context parser for rows 33 to 39

`Context.parse p pubBytes tag n c T` parses the row-n absorb frame `c` into
the endpoint state `x` and the message (read at index n, canonical encodings
only). It then walks back `n − 33` plain rows with `DuplexSeek.seek p T 2`
(advance edge, then absorb frame) to row 32's absorb frame, reads the
messages of rows 33..n−1 at their indices, and parses row 32's context with
R1's `JointContext.parse … 27 4`, requiring 31 records as R1's
`JointUnifiedDecoder` does. `parse_sound` records the label, the 31 records,
R1's row-32 parse and `tail.length = n − 33`. `parse_row33` gives the honest
row-33 case, with the table-walk facts as hypotheses in the same form as R1's
`JointContext.parse_encoded`.

### 4.3 Not built

- The completing component `fin n` for rows 33–39: own reads
  `QueryNextLaw.own p c`; pending answers are R1's
  `JointPrefixAnswers.missing` plus the squeeze cells of rows 32..n−1 absent
  from the table; the output prefix is R1's 32-record completion, row 32,
  rows 33..n−1 and row n's message. Its law (a copy of `JointUnifiedBound` /
  `JointNextLaw.background_law`) and its canonical-address lemma are also not
  built. These are the remaining obligations of this piece. The density agent
  needs them to turn its fixed-prefix densities into the decoded-start bound.
- Exactly one decoded start per new row in an honest run. What is proved is
  exact: row n's decoded first reads equal `[T a = none ∧ fin n a T ≠ none]`
  for its absorb frame `a` (`final_row_starts`, `final_row_weight`). The
  count is 1 when the frame is fresh and the component succeeds. The second
  condition depends on the concrete `fin`. A start count needs only the upper
  bound and the charge row, and both are proved.

## 6. Decoded starts of an honest Aspis verifier run

At most **41**, proved as `AspisRows40.Starts.verifier_starts`. This
confirms 34 + 7 as an upper bound, not an equality. Rows 0 to 39 each
contribute at most their absorb frame (row 0: its initialization frame; the
row-0 absorb, every squeeze and every advance never decode). Row 26 can add
its reseed frame, the `+1`, as in R1. Row 31's query chain adds nothing. Rows
33 to 39 each contribute exactly their absorb frame's indicator. There is no
new start frame or reseed, because of `resume`. The reseed frame of row 26
(`openingDomain ‖ tag ‖ state`) can parse as an absorb frame of any label,
including 33 to 39, when state bytes 2 and 3 are `00` and `c1..c7`. It is
covered by the same `+1`, and its charge must stay the largest cap, as in R1.
The count covers transcript oracle calls only. Merkle hashing is outside the
verifier program here, as in R1's `verifier_starts`.

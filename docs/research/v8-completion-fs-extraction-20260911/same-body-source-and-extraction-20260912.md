# Same-body source authentication and extraction bridge — 2026-09-12

## Scope

This checkpoint connects more of the selected V8 functional verifier to one
submitted body and records the exact remaining extraction seam.  It is not a
global soundness theorem, a literal Rust refinement, a Fiat--Shamir theorem or
a release claim.

The research branch still uses the 40,282-byte q22 body and gives no security
credit to grinding.

## Constructed functional path

The new `FSV7*Script` leaves model the source-shaped, chronological Merkle
execution rather than accepting a completed answer log as an unexplained
input:

1. `FSV7ParentScript` asks the current C1 and C2 parent inputs in source order.
2. `FSV7PassScript` implements the pair/single pass and constructs the older
   pure `Pass` witness and its exact query trace.
3. `FSV7LevelsScript` iterates the depth-18 levels and preserves prior answers
   through arbitrary later calls.
4. `FSV7LeavesScript` asks both leaf inputs for each selected record.
5. `FSV7NodeVerifierScript` checks both roots and exact frontier exhaustion.
6. `FSV7SelectedBodyScript` parses the submitted body once and constructs the
   existing `SuccessfulMerkleRun` from the effectful execution.
7. `FSV7SourceAuthentication.source_authentication_inputs` constructs the C1
   and C2 chronological prefixes, their nesting and answer consistency, both
   root equalities, and inclusion of the actual leaf/node calls in the same
   final log.

This is a functional source-shaped construction.  The literal Rust-to-Lean
refinement and the intervening semantic/OOD/challenge transcript remain open.

## Literal q22 sampler control flow

`FSQuerySampler` models
`transcript.rs::challenge_queries_without_replacement(22, 2^18, 64)` on the
existing cached full-answer oracle interpreter.  Its Script/reference theorem
preserves duplicate candidates, the 64-draw cap, abort output and final
transcript state.  In particular it retains the source's block-boundary
behaviour: when the 22nd distinct position is accepted on the final word of a
block before draw 64, the outer loop performs one additional squeeze before
the inner loop notices completion.  A per-word abstraction would return the
same positions but the wrong final transcript state.

The focused local build passed under Lean 4.33.1 (`-j1 -M2048`): the final leaf
took 0.589 seconds wall time with sampled peak process-tree RSS 717,472 KiB and
zero swap.  `run_queries`, `scan_unstopped_draws`, `query_words_bounded` and
`queries_valid` use only `propext` and `Quot.sound`.  The preceding failed
attempt is retained in the results directory and showed `sorryAx`; the repaired
run does not.

This establishes control-flow/state equality, not the uniform-without-
replacement probability law.  Fuel adequacy for the exact production call and
literal Rust `u32` assembly/bitmask refinement remain named source obligations.

## Remaining global implication

The next mathematical/executable endpoint is:

```text
same source-coupled accepted execution
AND RecoveredHigh
  -> permitted-access bounded candidate production
  -> the same canonical C1 table satisfies the selected residual predicates
  -> the literal payment decoder/validator returns a checked witness
OR an explicitly defined and charged authentication/access/resource failure.
```

The candidate generator may not receive the analysis-only `pStar`, quotient,
family membership oracle, unrestricted committed word or original witness.
The existing q22 proof reveals too few symbols to reconstruct an arbitrary C1
column without a justified recorded-access or rewind strategy.  The current
finite family bound is mathematical and does not establish efficient list
enumeration.

After that seam is closed, the complete accepted-event partition, actual
source sampler laws, resource-bounded ROM Fiat--Shamir lift and full-view
adaptive zero-knowledge simulation remain separate gates.

## Stage 2: programmed-oracle replay and compiled size obstruction

`SimCostReplay` recursively mirrors the actual `List.lookup` and `runLog`.
It charges `|query|+|stored key|+3` per visited table row, a fallback oracle
call, a recorded-log insert and a control step. Programming plus insertion
costs two per programmed row. The final append is charged by the ideal wrapper.
For table length T and all stored/reached key lengths at most L, replay plus
programming costs at most

```
((T+1)*(2*L+3)+2*T+3)*(q+1).
```

Value erasure is exact, including duplicate keys (first lookup wins), misses,
query truncation, and the failure branch. This is simulator overhead in an
oracle-machine model: adversary evaluation/continuations are external work.
It does not bound arbitrary computations in an adversary's Lean functions.

## Stage 3: exact view and ideal-game composition, with residuals

`SimCostView.run` composes five independently certified stages: public
reference payload; mask linear map after tape reindexing; payload addition;
shift; public metadata. It proves value equality with actual `simE` and
cost ≤ R+M+A+S+D without unfolding the large reference formulas. This is the
M10 abstract stage pattern. **The five concrete stage implementations and
budgets are not supplied here.** This interface cannot by itself establish
executable uniform algorithms.

`SimCostIdeal.prepare` names exactly the eight-try model prelude and selected
verifier log. `run` binds a certified preparation to the implemented replay.
`run_erase` proves pointwise equality with `fsR1P.ideal`; `run_linear` proves

```
c = C+(T+1)*(2*L+3)+3*T+4
cost ≤ c*(q+1)
```

where C bounds preparation, T bounds its table length and L bounds stored
and reached address lengths. This is degree one in q **when C,L,T are fixed
protocol constants**. The table is immutable after preparation; no claim
about arbitrary allocation-bit cost or dynamic hash-table efficiency is made.
`prepare` is a mathematical reference, not an executable source certificate.
It includes arbitrary wire callbacks; merely assigning it cost C would be
unsound, so `Preparation` explicitly requires separate value/work laws.

## Sampling: exact primitive versus binary-word implementation

No unbounded retry appears in `fsR1P.ideal`: firstGood selects from Fin 8;
QueryScan uses eight blocks; runLog is bounded by q. Its input coins/tape
are mathematical uniform coordinates. Turning uniform M31 coordinates into
binary-word code introduces a separate issue: 31-bit words reject the one
all-ones value, so retry-until-success has no deterministic worst-case cap.
`SimCostSampling.all_reject` compiles the counterexample for every finite
budget. `truncate_bound` proves the bounded implementation costs at most B
and `truncate_erase` identifies its first-success/failure value.

Under the independent-trial geometric model with rejection rate 2^-31,
`m31_expected` proves expected draws ≤2, and `m31_tail` proves B-draw failure
probability 2^(-31B). These are model results; uniform binary-word source
coupling and independence are not proved here. Four independent M31
coordinates give QM31; a union bound would charge at most 4·2^(-31B) for one
truncated QM31 sample, and all simulator samples would need their total
union budget. Truncation therefore requires an extra statistical error term;
it is not silently installed in the unchanged <2^-100 headline. Expected
polynomial time is a separate possible interface. The current headline's
WideExact tower and all its field algorithms still need concrete primitive
refinements; the M31/QM31 tariffs alone do not certify them.

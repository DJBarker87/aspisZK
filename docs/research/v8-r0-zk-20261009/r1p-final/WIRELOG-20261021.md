## Finding

Neither requested premise follows by construction. `PrivacyR1AcctModel.base`
installs arbitrary `log` as `comLog`; `PhaseProtocolInstanceBin.wire` preserves it.
`PrivacyR1AcctModel.seed` retains arbitrary `fib` and `opens`;
`PhaseLeafConstructionBin.prover` changes only `leafVal`, and
`R1PhaseProver.toProver` changes only `caddr` and `ord`.
D88's message and leaf encoding therefore does not supply a log/opening join.
There is no binder identifying these data with Rust in either D106 premise.
The source interpretation is an additional release boundary, not a consequence
of the model constructors.

## Symbolic counterexamples

* `empty_openings_no_batches`: for every supplied challenge, empty `opens`
  contradicts the root-coverage consequence of `RWireBatches`, regardless of
  `fib`, decoder, log, witness or tape. `openedQ fib (.inl 0)` is always true.
* `empty_log_singleton_opening`: choose `log := fun _ _ _ _ => []` and
  `opens := fun _ => [.inl 0]`. For every witness, secret, digest, full tape,
  root vector, rest vector and challenge, the required equality is `[] = [entry]`,
  which is false. No concrete tape or grammar address is evaluated.
* `log_retained` and `openings_retained` expose the retained parameters directly.

These are parameterized counterexamples in the actual accounting-specialized
model, not claims about an executed Rust prover. They need no new axioms,
resource overrides, finite-universe enumeration or recurrence evaluation.

## Narrow remaining joins

`R_wire_D80_batches` is precisely a logical opening-layout contract: there
exist two per-challenge lists and fibre maps such that (1) their concatenation
is `opens ch`, (2) each list is duplicate-free, (3) each covers exactly
`openedQ` for its fibre map, and (4) the union of their fibres is `fib ch T`.
It does not mention `comLog` or serialization bytes. Applying it to Rust
requires instantiating `opens` and `fib` from the pinned normalized batch
schedule and proving exactly these fields. Calling it an already-constructed
wire identity would hide this independent layout obligation.

`R_wire_D80_ordered_log` is precisely the ordered serialization/read-log join:
for all its existing binders, `log rest roots (view h B outputs x w ch τ) ch`
must equal `List.map` of the constructed `gram`/`ansC` entry over `opens ch`.
Only `log`, `opens`, and the constructed public bytes/tag/leaves participate;
tape decoding, quotient uniformity and runtime retries need no additional
premise here. In a Rust instantiation, bind `log` to the pinned verifier's
ordered commitment reads and `opens` to the pinned normalized opening
schedule, then prove that exact equation, including address bytes and answers.
A mere set or length equality is insufficient. All full tapes and challenges
remain quantified, including those not produced by successful decoding.

## Endpoint decision

No deletion-only privacy endpoint is soundly obtained from these constructors.
`PrivacyR1HeadlineWire` contains the compiled obstructions, not a theorem that
silently adds canonical-data restrictions. `privacy_headline_acct` remains the
privacy endpoint. Its two D80 binders and conclusion remain verbatim unchanged.
The headline report receives this audit; no before/after deletion is claimed.

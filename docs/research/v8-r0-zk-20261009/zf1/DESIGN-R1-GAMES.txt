§1  What the R1 proof publishes (G-root check)  (SOURCE)
----------------------------------------------------------------------

R1 is variant S2 (two folds, 33 rows).  verifier.rs View::parse_shape and
r1_semantic.rs: the proof bytes are
  header (magic "R1P3COST", variant tag) ‖ semantic prefix (the C1 root
  `prefix.c1_root`, the 27 framed semantic records, row 2's record = the C2
  root) ‖ y1 (29·32) ‖ inactive (32) ‖ round0 (7·32) ‖ folded root (32) ‖
  round1 (7·32) ‖ final message ‖ 22 × query blocks.
A query block (P3 build, INITIAL_QUERY_BYTES + SECOND_QUERY_BYTES) holds the
opened C1 values (480 bytes), C2 values (128), the two opened leaf salts
(2·32), two C1/C2 Merkle paths (2·6·7·32), the folded values (128), the
folded salt (32) and the folded path (6·7·32).

The verifier's hash reads on these bytes are exactly
  (a) the 115 transcript reads of §2 (it recomputes every one, including all
      eight query pairs: transcript.rs `queries` always computes 8 blocks);
  (b) per query and tree: the leaf read H(0x10 ‖ T ‖ value ‖ salt) and six
      8-ary node reads whose inputs are the path siblings and the running
      digest (verifier.rs merkle_path, state_only_private_merkle).
So the D41.5 G-root proposal matches the proof: every root, opened salt and
path digest is either inside the INPUT of a verifier read (c1_root trails the
`init` address; the C2 root is inside row 2's framed record; the folded root
inside row 30's payload; opened salts trail the leaf inputs; siblings are
node inputs) or is the ANSWER of one (roots and path digests).  Hence
  proof bytes = serialize(View, VerLog)  and  VerLog = verifier(proof, H),
with VerLog := (a) ++ (b) as an ordered (input, answer) list.  The Lean
`abR1.extend` publishes ROMView ⟨V, VerLog ++ adversary log⟩: G-root is
closed in the game definitions, with the serialisation identity as REF item
R-ser (§6.4).

Two further verifier reads (checked, not in VerLog): the two-transaction
checkpoint stores H(proof) and H(public) (verifier.rs checkpoint).  Both
inputs are functions of published data, so they are ordinary adversary
queries (each costs one of the q reads) and need no programming.  The
on-chain checkpoint itself is a deterministic function of (proof, public,
H) and adds nothing to the view.

§2  The transcript layout: 115 reads, fields, coordinates  (PROVED, R1Z/TranscriptR1)
----------------------------------------------------------------------

2.1 Reads (`TRead`, 14 constructors; `card_TRead : card TRead = 115`):
  init; absS i, sqS i, advS i (rows 0..26); reseed; absO i, sqO i, advO i
  (rows 27..30); absQ (row 31 absorb), qb k, qa k (k < 8); absR, sqR, advR
  (row 32, ρ).  `schedule` lists them in the verifier's order
  (`mem_schedule`).  Squeeze reads (`IsSq`: sqS, sqO, qb, sqR) are the 40
  challenge blocks; the other 75 answers are chain coordinates.

2.2 Addresses (`addrWith`, from the source byte layout):
  init   = DOMAIN ‖ 0 ‖ le32|pub| ‖ pub ‖ c1_root            field: C1 root, trailing
  absS i = st ‖ 0 ‖ 0xa0+i ‖ framed_i                         field: st, offset 0
  absO i = st ‖ 0 ‖ 0xa0+27+i ‖ le32|payload| ‖ payload
  absQ   = st ‖ 0 ‖ 0xa0+31 ‖ le32|final| ‖ final
  absR   = a_{k*} ‖ 0 ‖ 0xc0 ‖ le32 0      (38 bytes)
  sq*/qb = st ‖ 1,  adv*/qa = st ‖ 2       (33 bytes)
  reseed = DOMAIN2 ‖ vtag ‖ adv_26                           field: trailing
  `fc` gives each read's designated field (Coord = root | sel | ans j):
  absS 0 ← init, absS (i+1) ← advS i, sq/adv ← their absorb, reseed ←
  advS 26, absO 0 ← reseed, …, qb/qa 0 ← absQ, qb/qa (k+1) ← qa k, absR ←
  sel (the answer of qa k*), sqR/advR ← absR.  `chain_fc`: no field is a
  squeeze answer (the D41 §1.1 "no squeeze answer is a field of any later
  address", now a theorem).  `extract_addrWith`: the field reader recovers
  the field from the address.

2.3 Records.  `Rec` = (all 115 answers, C1 root, k*, Rest), Rest = framed
  records, payloads, final message, public bytes, variant tag.  `setC c`
  moves one coordinate; `Dep` says which coordinates an address reads (its
  field; absR reads every qa answer through k*; reads with a qa field read
  `sel`).  `addr_setC_of_not_dep`: an address is unchanged by every
  coordinate it does not read.

2.4 The pair table (`table`): two distinct reads of one attempt either have
  a field the other does not read, or their addresses differ for EVERY
  record: same field ⇒ squeeze/advance siblings (last byte 1 vs 2,
  `sib_addr_ne`); absR against qb/qa (k+1) ⇒ length 38 vs 33.  The proof is
  symbolic (`back_fc`, `rep_cases`); nothing is enumerated.

2.5 Lifting (`TranscriptFrame`): per-attempt records on any finite space
  with a lawful lens per (attempt, chain coordinate) whose move is `setC`
  on that attempt and the identity on the others.  Then
  `pairFresh_transcript`: PairFresh (either orientation, Umin = 2^255,
  |answers| = 2^256 by `card_ans`) for EVERY pair of distinct transcript
  positions of all N attempts; `hitFresh_transcript`: HitFresh for a
  position whose charging event and adversary read are lens-invariant.
  `card_positions`: N · 115 positions.  A lens gives the HitFresh/PairFresh
  coordinate split S ≃ R × U (R1Z/LensR1 `hitFresh_of_lens`,
  `pairFresh_of_lens`), so the designated-field table of D41 §1.4 is no
  longer a hypothesis for the transcript reads.

§3  The abort bridge ab_R1 and the middle games  (Lean: R1Z/GamesR1 `abR1`)
----------------------------------------------------------------------

Coins (per attempt) R1Coins = (TRead → Ans) × (Fin 3 → Ans) × Cm × Tab:
the 115 transcript answers, the roots (C1, C2, folded), the commitment
answers Cm (salts, leaf and node digests; abstract finite type) and a table
Tab with `look : Tab → Bytes → Ans` (the shared oracle; attempt 0's table is
used).  N attempts, `hN : 0 < N`.
  draw c      = dec(squeeze answers of c)          (`drawW`; ρ dropped by dec)
  extend c k V = ⟨V, VerLog_k ++ runLog(adv.prog V VerLog_k, prog_k, qmax)⟩
               VerLog_k = tLog (the 115 reads with addresses from V's
               records and c k's chain answers) ++ comLog(c k) (opening reads)
               prog_k a = the VerLog_k answer at a if a is published, else
               look (tab of attempt 0) a
  fail c      = ⟨failView, runLog(adv.prog failView [], look tab_0, qmax)⟩
Discarded attempts are read only through draw; their tapes never.

Adversary (`R1Adv`): a query program `prog : View → VerLog → OProg`
(adaptive, at most qmax reads, `runLog`) and a decision `decide : ROMView →
Bool` (observe := decide).  Any post-proof adversary whose output is a
function of what it saw is of this form.

The middle games are FsAbort/HvzkV/HvzkS's `middleRealAbortV`,
`middleIdealAbortS` on this bridge; no new middle game is defined.

§4  fs.real: the retrying honest prover  (Lean: `realAttempt`, `realGame`)
----------------------------------------------------------------------

RealRand = Tab × (Fin N → Secrets); H := look tab.  Attempt k
(`realAttempt`, with secrets k):
  1. commit phase (`R1Prover.commit`, REF): from H, the attempt's fresh
     secrets and the instance — the mask tape t (rejection decode of the
     expander answers), the three roots, the opening reads as a function of
     the challenges, the exhaustion flag;
  2. transcript: the reads of `schedule` in order, each address built from
     the answers so far and the records of view(w, ch_so_far, t), each
     answer H(address);
  3. ch := dec(squeeze answers), V := view(w, ch, t), log := the verifier's
     recomputation (115 reads from V's records, answers H) ++ opening reads.
Game (`realGame`): accept the first k with P ch ∧ Vp ch w ∧ ¬exh (P = P_R1,
Vp = VR1, the no-pole set: D38/D40); publish ⟨V_k, log_k ++ adversary log
against H⟩; if none, publish ⟨failView, adversary log⟩.  Discarded attempts
publish nothing (A-erase holds by construction); the cap is N (A-cap);
attempts use independent secrets (A-sec as the product RealRand).
This closes G-retry at the model level; the Rust prover still lacks the loop
(D38.3) — the refinement item R-retry.

----------------------------------------------------------------------
§5  fs.ideal: the simulator game  (Lean: `fsR1.ideal`)
----------------------------------------------------------------------

IdealRand = (Fin N → R1Coins) × (Fin N → Tape).  Given a simulator sim
(primary: ZF2's `simE h.transport B outputs x`, D44; secondary: `simV`):
the same capped loop on draw and P alone; on acceptance at k publish
extend(c, k, sim(draw c_k, t_k)) — VerLog computed from the simulated view
and fresh coins, and the adversary answered by the table programmed at the
published addresses; failure publishes fail(c).  It reads no witness.
`ideal_agree_S` proves it equals `middleIdealAbortS` pointwise, for every
simulator; the collision cost of programming is carried by the REAL side's
CollEv (two transcript or opening positions with one address), where it was
already counted (D41 ε_coll).  Consequently Mi = 0 and ε_prog = 0.

      ZkStatement.messages x (JointView.payload h B x w ch t) i =
      ZkStatement.messages x (JointView.payload h B x w ch' t) i
  and the program-level consequence
    theorem proverProg_view : (eval H (realProg …)).2.1 =
      JointView.view h B outputs x w (drawH H) t
  where drawH reads the challenge record off the trace. By inspection of
  HonestView.run/payloadAffine the dependency pattern is causal (rows 15+j use
  alpha_<j via roundPoint; row 25/26 use alpha and circle 0; rows 27–31 use the
  preceding circle/opening scalars), but this is not proved anywhere.

(2) ROMBridge
-------------
  Coins := (Fin 31 → State × State × State)        -- rows 0..30: (absorb s'_i, squeeze b_i, advance x_i)
         × (State × (Fin 8 → State × State))        -- row 31: absorb s'_31, chain (b_k, x_k)
         × (Addr L → State)                         -- fresh table for all other adversary reads
      (finite, nonempty; no dependence on h, w or the tapes.)

  draw adv x c : Challenges K :=
      toChallenges (fun i => if i < 31 then p.σ i (b_i) else .opening (out4 s'_31 bs xs).1)
      -- with [A2]: sem i = semChal b_i (i<25); circle j = circleSample_j b_{25+j};
      --   opening 0 = gamma b_27; opening k = ordinary b_{27+k} (k=1..3);
      --   queries = chalSet of the q22 scan of the 8 chain pairs from s'_31.
      -- Uses no instance, no messages: absorb answers s'_i do not enter σ.
      --   (In the one-block rows σ reads the squeeze answer only, samp :146.)

  extend adv x c v : ROMView :=
      let m_i := ZkStatement.messages x v.2 i                         -- recomputed from the view
      let st_0 := p.iv ; st_{i+1} := x_i                              -- stateOf along the coin chain
      let T_P : Table (Addr L) State :=
        put* [ (absorbA p st_i (p.lbl i) (p.enc m_i) (p.encLen m_i), s'_i),
               (squeezeA p s'_i, b_i), (advanceA p s'_i, x_i)  for i < 31,
               (absorbA p x_30 (p.lbl 31) (p.enc m_31) _, s'_31),
               (squeezeA p y_k, b_k), (advanceA p y_k, x_k) for k < 8, y_0 = s'_31, y_{k+1} = x_k ]
      ⟨v, logOf adv v (complete T_P Hfresh)⟩
      -- i.e. the adversary's oracle is MemoizedProgramLaw.complete T_P Hfresh:
      -- recorded prover states at prover addresses, the fresh table elsewhere.
  The absorb address uses stateOf (previous advance coin, or p.iv), the label
  p.lbl i and p.enc m_i, exactly as Duplex.samp :144. With FreshFrom on the
  prover's reads (no address repeat), T_P is the table left by the real
  prover's trace.

  Bridge-to-middle identity to prove (no instance read): for every coin c,
  middleReal at (c, t) = bit(observe adv (extend adv x c (JointView.view … (draw c) t))),
  which is the definition; the work is in (3).

(3) ε_real, ε_ideal
-------------------
  Shape. Write the prover program as P_w (real) or P_sim (ideal); both have
  exactly N_P = 31·3 + 1 + 8·2 = 110 reads on every path.
  realTest mean  = mean_H bit(observe (eval H (bind P_w (fun v => adv v.1))))   (after eval_bind)
                 = lazyMean (bind P_w …) ∅ …                                    (empty_oracle_law)
  middleReal mean = mean_{c,t} … = mean over prover coins of
                   lazyMean (adv v) T_P(c) …                                   (exact_oracle_law with t := T_P)
  On paths where every prover read is a first read, the lazy prover phase
  equals the independent-coin phase (lazyMean_eq_independentMean, path-wise),
  and the adversary phase is lazyMean from the same table T_P on both sides.
  Hence (proposed, unproved):
      |mean realTest − mean middleReal| ≤ Pr_lazy[some prover read is a repeat]
                                      ≤ mean_H indicator (Coll-type event on P_w)
                                      ≤ κ(N_P) = 2·N_P² / 256^32 = 2·110²/2^256 = 24200/2^256
  and the same for ideal vs middleIdeal (P_sim has the same read shape).
  So ε_real = ε_ideal = 24200/2^256, independent of the adversary's query
  count Q_A, under [A3] (post-proof adversary). If the lead wants an explicit
  pre-proof adversary phase (adaptive statement, or queries before the proof
  that are charged), the first-hit term appears: lemmaA with badColl density
  2·Qtot/|State| and Qtot = Q_A + N_P gives κ(Q_A + N_P) = 2(Q_A+N_P)²/2^256
  (the shape of FS2.Duplex.coll_mass), |State| = 256^32 (state_card).
  Collision event: FS2.Duplex.badColl (fresh state = iv, = an earlier output,
  or = the 32-byte prefix of an address read so far) is exactly the event
  whose absence makes every later squeeze/advance/absorb address fresh
  (via squeezeA/advanceA injectivity, cross-disjointness and toBytes_*), with
  absorb addresses of different rows distinguished by their 32-byte state
  prefix.

  Lemmas used: MemoizedProgramLaw.empty_oracle_law, exact_oracle_law;
  OracleProgramOps.eval_bind; AdaptiveFirstReadLaw.lazyMean_eq_independentMean,
  independentMean_bind; FS.lemmaA + FS.firstReadsBound_of_traces;
  FS2.Duplex.badColl_density (or coll_mass if the experiment is put in its
  `experiment P V x` shape); state_card; the Duplex address lemmas of 1.F.
  Missing: lazyMean_bind (G10), an identical-until-bad lemma (G10), a lemma
  that independentMean of the fixed-shape prover program is mean over Coins
  (G10), absorbA injectivity/prefix lemma for "different state ⇒ different
  absorb address" (G9; derivable from toBytes_absorbA).

  Which bridge lemma. complete_oracle_eq_independentMean is the wrong tool for
  the adversary phase: the adversary may re-read prover addresses, so
  FreshFrom fails there by design; that phase is handled by exact_oracle_law
  with t := T_P (no freshness needed). For the prover phase,
  FreshFrom P ∅ does NOT hold universally (some answer sequences make an
  absorb answer equal an earlier one), so empty_oracle_eq_independentMean /
  complete_oracle_eq_independentMean cannot be applied to the raw prover
  program. The right bridge is lazyMean_eq_independentMean applied to a
  collision-free variant of the prover program (e.g. P renamed onto
  round-tagged addresses with OracleProgramOps.rename, whose FreshFrom from
  the empty table is structural, transported back by lazy_rename), plus the
  identical-until-bad comparison with the raw program. squeezeProgram_fresh_iff
  is the one-step unfolding for each row's two-cell multi read.

(4) badMass Good identification
-------------------------------
  With the bridge of (2), badMass Good bridge adv x
    = mean_c [¬ GoodAlpha (fun j => semChal (b_{15+j}))]
    ≤ Σ_{j<9} mean_b [semChal b ∈ {0,1}] + mean_b [semChal b ∈ {0,1,1/2}]   (union bound over the 10 rows;
                                                                           coins independent by construction)
    ≤ (9·2 + 3) · m_σ = 21 · m_σ        via R0P.SemSource.semChal_event (SemD2.lean:225)
  with  m_σ = (1 + deltaQ) / P^4 = 1/P^4 + 1/256^32   (semChal_mass, qm31Sample_mass),
  deltaQ = P^4/256^32 ≤ 2^-131. Numerically 21·m_σ ≈ 21·2^-124.
  (Card bound: {0,1} has card 2 and {0,1,1/2} card ≤ 3; 1/2 lies in the M31
  image, so the row-9 term is genuinely 3·m_σ.)

  The requested route "through ordinary_mass/ordinary_mass_257" does not apply
  to alpha: those lemmas are for `ordinary`, which decodes opening rows 28–30
  only. Their numerical form is ordinary_mass_257 : ≤ 257/256^32 per point
  (≈ 1.004·2^-248) and ordinary_mass : ≤ 1/P^8 + 1/256^32. If (contrary to
  the soundness hypotheses) σ_i for alpha rows were `ordinary`, the bound would
  be 21·257/256^32.

  combinedOwn_law / samp_mean are not needed for badMass on bridge coins
  (independence is by construction); they are what identifies the per-row law
  of the REAL experiment's fresh reads with the bridge's coin law, i.e. they
  belong to (3): samp_mean says the round-i challenge under fresh answers is
  `(p.σ i a, b)` with a, b independent uniform — exactly draw's row i.

  GoodDensity.badAlpha_density (21/|K|) is the uniform-decoder idealisation:
  at K = SemE it would read 21/P^8, which is smaller than the true 21·(1+δQ)/P^4
  by a factor ≈ P^4; it is not a bound for the protocol's alpha law.
  The q22 row, circle rows and opening rows play no role in Good.

  Statement shape after G2 is repaired (proposal only):
    theorem zkfs_of_hvzk_on_bridge (hh : HVZK_on P h B outputs x)
      (bridge : ROMBridge …) (er ei eb : ℚ)
      (hreal : ∀ hx adv w, h.public w = x.1 → |mean realTest − mean middleReal| ≤ er)
      (hideal : ∀ hx adv w, h.public w = x.1 → |mean middleIdeal − mean idealTest| ≤ ei)
      (hmass : ∀ adv, badMass P bridge adv x ≤ eb) :
      ZK_FS h B outputs fs x (er + ei + eb)
  (or ROMReduction restated to expose its bridge and a badMass field).

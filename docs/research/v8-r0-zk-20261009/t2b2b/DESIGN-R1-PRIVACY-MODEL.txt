§0  Summary
-----------
S1  R1 differs from the proved R0Z model in exactly one place: the batched
    opening block.  Every per-lane disclosed cell has the same constructor
    and the same formula in R1 (pointClaim, extraClaim, ood, opened,
    inactiveSum; maskSum and semanticCoeff are the unchanged semantic layer).
    The R0 cells .openingCoeff (Fin 7) and .finalCoeff (Fin 256), built from
    the chord quotient, are replaced by four R1 groups: round0 (Fin 7),
    round1 (Fin 7), folded (query-gated, Fin 262144, 4 per distinct u/4) and
    final (Fin 64).  Source: verifier.rs View::parse_shape (:39-58),
    prover.rs prove_from_semantics (:190-236), R1-PAYLOAD-MAP §5.
S2  The transport π enters every proved theorem only as an argument
    `π : Fin 1024 ≃ Fin 1024`; D13Order (HonestView.lean:24) is defined but no
    proved theorem uses it.  D18 is therefore an instance choice, not a
    re-proof.
S3  Recommended model: one mechanical refactor of HonestView.PayloadCell into
    `PayloadCell (Bat : Type)` with a single batched constructor `.bat b`, and
    a class `BatchedLayer K Bat` supplying the batched read.  R0 is the
    instance Bat := R0Bat, R1 the instance Bat := R1Bat.  Every proved theorem
    of the T2a/ZF-A chain, T2b-1, T2b-2a and J3 keeps its statement (with
    Payload K replaced by Payload K Bat) and its proof modulo merging two
    `cases` branches into one.  Only HonestView's batched part and J3's
    batProj/payload_ext/mem_silentMasks_of branches are touched by hand.
S4  On R1 the honest-prover predicate is
       P_R1 := α₉ ≠ ½ ∧ sem ∈ K₄ ∧ QPrime ∧ BCondG_R1 ∧ (∀ c, C1Lift c) ∧
               H1Lift ∧ |queries| ≤ 22
    with BCondG_R1 := B0R1 ≤ V_G (the measured "V_G = B0", Z9 §1).  BCondG_R1
    implies both BCond (for (i′)) and BReach (for (ii′)) given J4-R1's
    bat_ker_own_le, so R1 needs ONE (B) conjunct for both clauses.  GoodCircle
    is not needed on R1: with no chord quotient, all 47 batched relations are
    identities for every challenge (the only nondegeneracy facts, nonzero
    fibre and line coordinates, are structural).
S5  Riskiest item: J4-R1's line-fold relations L_u, which need the
    line-domain encoder/fold commutation (2^18 → 2^16, 256 → 64
    coefficients).  On R1's soundness side this is obligation (B), open in
    R1_SOUNDNESS.md; partial material exists (§5).

§2.2  The refactor (one job, mechanical; PROPOSED)
  In HonestView.lean, before PayloadCell:

    /-- The batched opening block of a PCS: its cell type and its K-linear
    read of the prepared trace. -/
    class BatchedLayer (K : Type) [Field K] (Bat : Type) where
      read : (Fin 1024 ≃ Fin 1024) → Challenges K → Trace K →ₗ[K] (Bat → K)

    inductive PayloadCell (Bat : Type)
      | maskSum
      | semanticCoeff (round : Fin 10) (coefficient : Fin 28)
      | pointClaim (point : Fin 3) (column : Fin 29)
      | extraClaim (column : Fin 29)
      | ood (point : Fin 2) (column : Fin 29)
      | inactiveSum
      | opened (query : Fin 262144) (child : Fin 4) (column : Fin 29)
      | bat (cell : Bat)
      deriving DecidableEq

    abbrev Payload (K Bat : Type) := PayloadCell Bat → K

  linearPayload gains the branch
      | .bat b => (LinearMap.proj b).comp (BatchedLayer.read π ch)
  and loses .openingCoeff/.finalCoeff; payloadAffine and run likewise
  (`| .bat b => BatchedLayer.read π ch t b` in run).  run_bat replaces
  run_openingCoeff/run_finalCoeff and is `rfl`-level.

  Variable lines in all downstream modules gain
      {Bat : Type} [DecidableEq Bat] [BatchedLayer K Bat].
  `deriving Fintype` is dropped from PayloadCell (the R0 type derived it; no
  proved theorem in R0Z needs Fintype (PayloadCell) — a grep target for the
  refactor job: Finset.univ over PayloadCell must not appear, and does not
  today).  If some proof does need it, add [Fintype Bat] and derive.

  arguments of QPrime, BCond, MaskImageOn, HVZK_on, silentMasks: it occurs
  only inside A's codomain.  Those definitions therefore need Bat named
  explicitly at use sites: `QPrime (Bat := R1Bat) π B hB ch`.  R1Z.Model
  provides abbreviations (QPrime_R1 etc., §3) so that no R1 statement writes

Riskiest single item: line_identity in J4-R1(a), the commutation of the
second (line-domain) fold with the encoder,
    lineFoldValue α₁ inv (exactFinalLinear m at the four stored children of v)
      = secondLinear (coefficientFoldLayer 64 α₁ m) v,   v : Fin 65536.
Why: it is the only new algebraic fact about the PCS that the R1 privacy
proof needs and R0 never proved.  On the soundness side it is obligation (B)
of R1_SOUNDNESS.md ("domain commutation and the depth-two node
identification"), recorded open; the material that exists (LineFold.lean:
field recovery only, by its own header; SecondFoldRestoration: channel
identities conditional on agreement, compiled per its README;
Line18Geometry; RepeatedLift's quartet lemmas) has not been assembled into
this equation, and the Rust line fold (verifier.rs:154-169) uses its own
node and inverse conventions (x = line_node(4v), y = line_node(4v+3),
z = 2x² − 1) that must match storedFirstLineX18 / storedLine16X exactly.
Every L_u relation, hence B0R1, hence BCondG_R1 ⇒ BCond and BReach, rests
on it.
Mitigations, in order:
  1. Do it once for both tracks: it is the same lemma the R1 soundness
     ledger needs for rows α₁/q22; the lead can issue it as a shared job.
  2. Clause (i′) does not need it.  Define, for (i′) only,
       B0own := (LinearMap.ker ownMapR1).map batMapR1
     and put BCondG′ := B0own ≤ V_G in P.  bat_ker_own_le is then trivial
     and clause (i′) needs no relation at all; Z9 measured B0own = 952 = V_G.
  3. Clause (ii′) can avoid it the same way: put in P the check
       BReachTrace := batRead (L(ker own over all traces)) ≤
                       (ker ownMapR1 ⊓ ker roundMaskMapR1).map batMapR1,
     a public rank test over the ~38,900-dimensional F-space of 29-lane
     coefficient words (26·1,024 + 3·4,096) — heavier for the Rust check
     (minutes rather than seconds, unmeasured) but needing no J4-R1.
  With 2 and 3, J4-R1 leaves the critical path entirely, at the price of a
  larger prover-side check and a P that is less transparent to a reader.
  I recommend keeping J4-R1 as planned and holding 2/3 as the fallback if
  line_identity is not done within the J4-R1(a) budget.

Second risk (process, not mathematics): R1-0 re-sources every proved R0Z
module.  If the lead does not accept re-sourcing, the copy alternative of
§2.2 applies, roughly doubling R1-0 and every later Bat-generic job.

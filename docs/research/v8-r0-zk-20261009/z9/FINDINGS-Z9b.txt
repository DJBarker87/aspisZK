0. What is implemented (from the design and the Lean sources it names)
---------------------------------------------------------------------
relR1 (DESIGN-R1-PRIVACY-MODEL §2.4), written in the Z9 batched layout:
  s2a   = round0 0 + round0 4
  s2b   = round1 0 + round1 4 - quarter * sum_i alpha0^i round0 i
  s1    = sum_i alpha1^i round1 i - sum_e w2 e * final e,
          with w2 = RP.dualFold alpha1 (RP.dualFold alpha0 weightsR1)
          (RoundPairing.lean:42: quarter * sum_t w(4d+t) alpha^((4-t)%4)),
          weightsR1 = sum_k kappa^k ell_k(e_j) built from the R0 Lean-mirror
          functions (opening::inactive, row_eq_weight(points_from_alphas),
          h_weight, encoder::eval_message) at pi.symm j = row(j)
  circ u = folded u                                             (22)
  line u = lineFoldValue alpha1 (lineInverse (u/4)) (folded 4(u/4)+s)_s
           - secondLinear(final)(u/4), with secondLinear(m)(v) =
           sum_e m_e naturalLinePoly_e(storedLine16X v)
           (V5ComponentCConcreteFoldLinearity.lean:110-120 pairFoldValue and
           lineFoldValue, R1/RepeatedLift.lean:81, V5FriReleasedLineGeometry:64)
           (one relation per distinct parent u/4)
  plus ia = inactive.
The design does not pin the lineInverse table. It says only "the public M31
inverse table (x, y, z = 2x^2 - 1 of the stored line-18 fibre)". I check
three readings, with x = storedFirstLineX18(4v), y = storedFirstLineX18(4v+3)
and z = 2x^2 - 1:
  R0 literal  (1/x, 1/y, 1/z)
  R1          (1/(2x), -1/(2y), 1/(2z))
  R2          (1/(2x), 1/(2y), 1/(2z))
The probe also checks the Lean stored domains (storedFirstLineX18,
storedLine16X, naturalLinePoly) against the Rust domains of the Z9 port, and
weightsR1 against the Rust materialize.

C1Lift_c (§3.3 and DESIGN-ii-prime §2.1). V_c is the eligible words of
column c, balanced at 1023. W_c is the F-words with inactive sum 0. obs_c is
the 112 own limbs: claims 12, extra 4, ood 8, opened 88. C1Lift_c holds
exactly when rank obs(V_c) = rank obs(W_c). The probe reports it, and
separately the opened rank on V_c (against W_c) and the rest rank (24
limbs) on V_c ∩ ker opened. H1Lift is the same with P_26 = H1 padding words
(inactive rows, balanced at 0, K4) and W_26 = K4 words with inactive sum 0,
using 376 limbs (opened 352). These are independent of gamma, kappa, alpha0
and alpha1.

BCondG_R1 means B0R1 <= V_G. The probe tests it as: the reading's relations
annihilate bat(ker own), and rank V_G = dim B0R1 on the read support. The
fallback B0own <= V_G is tested as rank(V_G + bat(ker own)) = rank V_G.

Runs (each job evaluates both gamma limb sets in one process):
  actual:    structures A and J x vectors 0-4, the Z4c query set (10 jobs)
  named:     A vector 0 x {0..21, spaced 8192 i, paired} (3 jobs)
  random:    200 sets of 22 uniform distinct fibres, alternating A and J, vector k mod 5

4. Findings about the design (precise, for the R1-2/J4-R1 statements)
--------------------------------------------------------------------
F1 lineInverse (§2.4) is underspecified, and the literal reading is wrong.
   For lineFoldValue alpha1 inv (V5ComponentCConcreteFoldLinearity
   pairFoldValue form) to equal the Rust/R1 verifier line_fold, the table
   must be
     lineInverse v = (1/(2x), -1/(2y), 1/(2z)),
   with x = storedFirstLineX18(4v), y = storedFirstLineX18(4v+3) and
   z = 2x^2 - 1. Checked by expanding both forms, then exactly on every unit
   vector at every queried parent, and as the only reading under which relR1
   annihilates bat(ker own). The minus sign on the y entry is the same
   convention as circleFoldLinear (inv2y, -inv2y, inv2x).
F2 B0R1 is typed over all of R1Bat → K, but relR1 does not constrain the
   262,144 - 4P unopened folded cells, while V_G (an image of batRead) is
   zero on them. So `BCondG_R1 := B0R1 ≤ V_G` is false for every challenge as
   written. One fix is
     B0R1 := ker relR1 ⊓ {b | ∀ p, ¬ FoldedOpen ch p → b (.folded p) = 0}.
   The other is a relation `.unopened p` that forces those cells to 0. With
   the first fix, BCondG_R1 holds in all 506 evaluations.
F3 Everything else in §2.4 is confirmed as written in the numeric
   pre-check, so it is not a normalisation stop:
   - s2a, s2b, s1 with RoundPairing's quarter conventions (the quarter
     inside dualFold, so w1 and w2 need no explicit quarter);
   - circ;
   - secondLinear through storedLine16X;
   - the folded cells through storedFirstLineX18;
   - weightsR1 through the R0 Lean-mirror functions at pi.symm = row.
F4 Duplicate parents. When two queries share u/4, `line u` gives the same
   relation twice, so relR1 has rank 8(3 + 22 + P), not 8·47. Example: the
   coset sets have P = 8. dim B0R1 = 8(53 + 3P). The P_R1 check is a rank
   comparison, so this needs no change, but any count in the Lean statement
   must not assume 47 independent relations.
F5 C1Lift and H1Lift were measured on their own for the first time. On this
   evidence (253 query-set jobs, A and J, both gammas, since the lifts do not
   depend on gamma), the opened part is full even under D18. That was the
   part D24.4 flagged as non-structural, and the result is evidence, not a
   proof.

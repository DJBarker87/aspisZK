## Source results that must not be strengthened

R12's binary C1/folded theorems (`S/BinSourceCommitmentWords.lean:20,36,52,74`;
`S/BinSourceCommitmentOpening.lean:15,37`) assume one consistent log,
a first-read bound, a single collision exclusion, and actual frame/target
facts; accepted projection additionally needs a logged accepted strict
opening. The remaining folded payload/checkpoint join and leaf backend are
explicit in R12. These results preserve words at cuts of a successful
recorded execution. `RCausal` instead compares arbitrary answer vectors,
including inconsistent ones, and has no collision-exclusion hypothesis.
No implication between these two different statements is asserted here.

The C2 result in `S/RawSourceC2WordBinding.lean:39,70` and
`S/RawSourceC2CutBinding.lean:52` still uses the **eight-way** recovery and
`RawByteCollisionTargets.pred` (reader 8). It cannot be imported as the
binary privacy theorem unchanged. The actual C2 frame at row 2 remains a
useful source fact; a binary consumer must instantiate the Bin recovery
with its five readers and transport the source log. R12 does this for C1
and folded only. This packet stops that import-dependent C2 item rather
than copying the proof or treating arity as definitional equality.

R13's `S/R13ConditionalOpening.lean:15` consumes `modelAccept`; it does not
derive it from accepted source execution. Required source facts remain
sorted/in-range keys, conflict rejection, mutable-array/18-level simulation,
parity and sibling order, checked counters and exact node consumption,
whole-tail padding scan, read coverage and caller composition. Batch A
still needs the stage-1 re-pin; an arbitrary batch parameter in stage 2
does not prove reachability from the frozen stage-1 entrypoint.

The tx1 and tx2 inventories are consistent with the D79 **extended** list:
compact proof 57,607, ASF8 1,880, checkpoint checksum input 1,758, in
addition to transcript and commitment records. They do not prove a source
execution belongs to that list. The raw API can hash arbitrary public bytes
(the rejected-prefix empty-slice counterexample in WIRE-TX2); the deployed
caller must supply the ASF8 width. The three resume/checkpoint hashes are
outside the opening-only `W.comLog` and need R10/R15/R19 accounting.

## Stopped false interpretation: raw calls as ROpen batches

Take distinct queries 0 and 1 in one batch. Both folded indices are 0,
since `0/4 = 1/4`. `candidate.rs:96` uses this quotient and
`:185–190` hashes each leaf **before** deduplication. For equal opening
bytes/salts the two leaf inputs and answers coincide. The resulting raw
position sequence contains the same `qLeaf 2 0` twice; it cannot satisfy
`ROpen.batches`' Nodup requirement. The tiny kernel proof is
`PremisesR1PBin.repeated_folded_leaf_not_nodup` (P`:104`). This proves the
position-list obstruction, not a complete accepted source-run fixture.

Stop the proposed raw-log identification. The minimal replacement is an
explicit normalization of repeated calls, justified by a single consistent
oracle, with its position/address/answer preservation and first-read
accounting proved separately. Normalization must preserve the ordered
normalized list used by `RComLog`; finite-set equality is insufficient.
This does **not** refute the abstract `ROpen` definition or require changing
the frozen verifier. It refutes treating raw repeated source calls as its
Nodup lists. Checkpoint binding calls also need separate accounting, not
insertion into the opening-only list.

Names in this excerpt are opened exactly as in SCK_Residuals. `R1` binds saved,
post and final to the actual first-wrapper reply in this H; its second entry is
then selected by `a.second` on that same tuple. Its cuts use the ideal SDK for
this H and those exact entries. The missing conclusion is checkpoint **bytes**
identity, not length, common key, digest equality or equality of dictionaries.
Requiring the first reply prevents choosing some unrelated successful pair to
satisfy the existential. The pointwise native-to-ideal bridge is already
`SCJ_NativeLoaded.ideal_cut`: for ANY ideal dictionary's cuts, it transfers
native CPH equality provided e1/e2/saved are those same indices. Dictionary
inequality is therefore not the remaining R1 problem.

A sufficient native route would produce the native accepted pair and approved
CPH game on those exact per-H entries and saved value, under the same installed
extraction/key/SDK/std/runtime laws, then apply `ideal_cut`. That route is not
currently instantiated. A fixed supplied `game p t u e1 e2 saved ...` and fixed
native acceptances at the root's supplied H do not constitute that all-world
factory. In particular `P1 sha256 H` entails sha256=H; `SCH_OracleQuantifier`
checks that fixed sha256 cannot satisfy P1 for every H. The ideal account's
success cannot be inverted to native success from RuntimeSyscall alone:
`SCG_PartialOracle.not_reverse` gives an actual tiny-code counterexample while
retaining the returning-value syscall law. An ideal proof can avoid that
inversion, but must still construct the same-world bank/game association.

`R2` is an acceptance-guarded implication in the direction actually consumed:
projected collision implies full-account collision (equivalently, full-account
cleanliness implies projected cleanliness). Both events use the exact release
iv and Q0+Q1+2965; the predicates, oracle and budget are identical, while the
programs and output selectors differ. `sourceSelect` must specialize to the
endpoint's actual selector, not an existentially convenient audit selection.
`project` and `select` likewise require construction on the actual account
outcome; quantifying over arbitrary selectors is not a proof of their instance.
Read/first-order preservation is a sufficient condition from
`SCJ_AccountProjection.event_implies`, not an already established property of
these two programs. No equality of whole logs or of the two events is needed.

## 2. Root cause and the account-first alternative

F3X_Join's `accepted_raw_join_or_collision` is universally quantified over
byte submissions and H, but its acceptance guard is the standalone
`F3T_Installed.source`. Its collision disjunct is evaluated on
`Hiq_RecordedJoint.program (F3X_AccountPrior.program ... prior s)` with
`F3X_Projection.project`. Despite the name Account, this program runs the
installed standalone driver and a cached preparation pass. With adaptive P,
`F3X_Account.program` adds P's first-submission queries. It has no intervening
`a.second i saved post final` choice program.

The physical observer used by SCE/SCF instead records the account experiment:
first adversary queries, first wrapper, response-driven second-choice queries,
then the actual second wrapper on the chosen Entry. Its outcome also retains
heap/state and both wrapper results. `SCE_Execution.accepted_eval` spells out
that chronology; `SCE_Experiment.runtime_eval` observes it without replay.
The two Hiq recorders share a generic wrapper, but have different base programs,
output projections and selected physical audit inputs. The mismatch is bridged
only after F3X's proof, forcing R1/R2 and recovery joins to relate programs that
were never constructed as the same world-indexed run.

A direct replacement should start from that account outcome, derive its actual
ideal cuts, bind its submitted bytes and saved checkpoint in the approved bank
game, and prove accepted raw/model behavior **or the collision event on this
very account recorder**. Feed the SAME account source, project and select to
`F3U_AccountEvent.charged`; use `SCF_Charge.charged` for the full Q0+Q1+1921 /
Q0+Q1+2965 budgets. This avoids the source-recorder-to-account-recorder R2
projection implication entirely. It does not avoid first-read recovery, per-H
bank support, source acceptance/refinement, or existing finish owners.

One cannot simply retain the current unconstrained SCE adversary and claim its
every accepted world is a deployed bank game. A bank-backed generative account
experiment (or a proved game-support filter with rejection/log accounting) must
produce the Entries, saved value and history in each H. Derive that support
from the approved game semantics; do not add an attacker promise or silently
condition the probability distribution. The fixed root game is not such a
factory. If a filter is used, prove that it implements the same deployed game,
that outside-support runs contribute zero deployed failure, and that all
query costs/prefixes remain charged. This is model-to-execution work under the
already approved contract, with explicit endpoint statement review.

## Contract and observable boundary

For identical public statement, compiled witness, variant, hash/oracle answers,
ordered attempt coins and ledger initial state, the rewritten selected 64-byte
proof-account caller must return identical status (including error precedence),
proof bytes, audit and attempt count. It must consume the same entropy callbacks
and reserve the same nonces in the same order, including rejected attempts and
fatal exits. Durable reservations survive rejection; duplicate nonces fail closed.
The caller handles public proof-account keys only and never destroys account keys.

Preserve the complete ordered oracle history, query duplicates and rejection
suffixes, not just the final roots. Preserve the L1 record: public work stages,
fixed ranges, callback counts, transcript rows, observable retry/error events and
absence of secret-valued tracing. Functional equality alone does not establish
D166 joint trace transport or L2/L3. Test-only TLS injection is outside the
extracted executable; the production CT path must contain no TLS/RefCell control.
OS entropy and atomic ledger persistence remain explicitly named external effects
(E1/E2), not axioms asserting prover correctness. Allocation failure follows the
existing runtime contract; no claim of allocator instruction equivalence is made.

The endpoint is conjunct 1 of `ProverCommitDeployedFuel22.RustProverRefinement`,
which requires a `RunJoin` for every admitted adversary and witness, with the
complete public view, observer decision, fixed bad event and source seed queries
(`ProverCommitDeployedFuel22.lean:121`). Per-attempt equality is a component of
that obligation, not its whole statement. The premise is consumed by
`PrivacyR1HeadlineDeployedReal.privacy_headline_deployed` (D185–186).
No native simulator binding or stronger deployed privacy conclusion is claimed.

## Owned execution plan

Each phase consumes an owned state and returns a new state or the original error.
Use named small functions and `while i < public_bound` loops; explicit index and
accumulator state; no iterator adapters, callback closures that capture mutable
state, trait-object backends, or loans carried between phases. Short-lived borrows
inside leaf calls are allowed; no borrow guard survives a call boundary. Keep
large vectors heap-resident; move ownership rather than cloning them per phase.

| Phase | Owned state / ordered transition | Leaf boundary |
|---|---|---|
| 64-byte caller | obtain proof-account nonce, then two private OS seeds; zero-seed rejection and sixteen-step byte assembly | OS read and atomic ledger effect |
| Retry owner | public S2 guard; index 0 through 7; fresh callback; attempt; publish first success; retry only Rejected; other errors abort; exhaustion fixed | per-attempt function, never the entire loop opaque |
| Reservation and material | context/public-byte binding, durable reservation before derivation, scalar rejection counters, exhaustion mapping | hash, scalar candidate decoder, M31/QM31 arithmetic |
| Mask application | clone semantic foundation once; counted column/row writes and inactive balances; D, G, H1 padding shape guards | CT arithmetic and one mask candidate step |
| Private salts | C1, C2, folded tags in original order; index 0 through FIBRE_COUNT; first error retained | one framed hash/derivation |
| Semantic build | canonicality, C1 commitment, rows 0–1, no-pole/helper, H1 padding/sum, C2, rows 2–14 | tuple compression, CT pole scan, arithmetic |
| Semantic sumcheck | ten public rounds; fixed public sample/assignment range, deterministic ordered reduction, boundary guard then rows 15–24 | optimized parallel evaluation over fixed public ranges, interpolation kernels |
| Claims and circle points | three statement points, lanes in ascending order, row 25 extras then z0; row 26 endpoints then z1; equality rejection | MLE cell, coefficients, encoder cell, sampler |
| Commitments | populate 29 lanes with exact C1/C2 mapping; fixed lane encoding ranges; salt leaves; binary-tree levels | CT field/FFT/hash cells; deterministic parallel encoding |
| Opening rounds | gamma row 27, ascending lane batching, inactive claim row 28, weights, round/fold 0, folded commitment, round/fold 1 | field kernels, existing weights arithmetic with separate caller binding |
| Query scan and P_R1 | row 31 scan with exact consumed state and dedup policy; rho row 32; P_R1 before publication | query candidate step; blocked/parallel exact P_R1 internals |
| Compact publication | magic/header; semantic compaction; claims; ordered openings/salts; batch/tree multiproof slots; fixed zero padding and final length | scalar byte encoder/hash; explicit sorting/dedup transition |

`prover.rs`, `host_semantic.rs`, `host_sumcheck.rs`, `host_commitment.rs`,
`transcript.rs` and their selected entropy/material callees are the implementation
surface. Shared verifier modules (`compact`, wire, query scanner, multiproof) must
not be edited casually: prefer host-owned callers around unchanged pure helpers.
The verifier's compile-time dependency closure must remain identical.

Opaque leaves need actual contracts: canonical input/output representations,
length/domain bounds, result/error equality, memory effects, ordered oracle calls
and public work schedule where relevant. Kani stubs may compose only contracts
already checked against their pinned body. An opaque whole semantic builder,
mask generator, tree builder or retry owner would recreate the missing premise;
it is not an acceptable extraction workaround. Parallel evaluation is the
explicitly permitted fixed-range leaf, with deterministic ordered results and
first-error selection; thread creation and merge remain named runtime obligations.

## Gates, speed budget and receipts

1. Commit this design before source changes. Pin baseline source and release
   features `optimized-terminal,ct-host-prover`, toolchain, binary SHA/size and
   all path dependencies. Use a private build-host workspace and retained caches.
2. Implement phase boundaries incrementally. Extract a small changed function
   first to reject unsupported ownership/loop shapes before expanding the cone.
   A type-check or successful extraction alone is not a refinement theorem.
3. Differential gate: identical fixture coins on transfer and withdrawal, then
   at least 1,000 recorded paired runs with varied statement/coins, including
   rejected attempts, exhaustion, fatal entropy/ledger errors and duplicate nonce
   handling. Record actual coverage and full-byte comparison, not only hashes.
   Do not replace full pipeline differential coverage with a leaf-only corpus.
4. Timing gate: optimized binary, five runs per fixture, fixed recorded thread
   count (v2 uses 16 workers), wall measured over the complete prove call including
   P_R1. Candidate median must be <15 s AND <=1.10 times the corresponding v2
   median. Existing D172 medians (13.63/13.98 s) leave about 1.37/1.02 s gross
   headroom; target ownership/caller overhead <=0.3 s, avoid extra arithmetic or
   full-word copies. Fixture timing is not a formal worst-case cost proof. Record
   contention and compare coherent baselines. **STOP and report on gate failure;
   do not relax it or proceed to adoption/proof campaign.**
5. Verifier ELF gate: compare complete SHA-256 and sizes with the retained
   default `d7d42f77…`, devnet `2b2a9f0e…`, Pool `121f3e29…` pins. Full pins
   must be read from existing receipts; prefixes alone are not evidence. No ELFs
   or other build binaries committed. Distinguish unchanged-closure evidence from
   an actual rebuilt byte-identity check.
6. Each opaque leaf requires a passing Kani contract against the selected source.
   Reuse unchanged receipts only after hash/domain audit; record missing contracts
   as open. Commit Stage 2 only with a truthful gate ledger, and label incomplete
   implementation explicitly if an obstruction stops it.
7. Stage 3: extract actual selected source; prove one attempt output (including
   errors, oracle reads and state effects) equals the model `source.real`
   components, compose the retry owner and selected caller, audit axioms, then
   one final dependency replay. State exactly what remains for conjunct 1.

Resource/budget: 100 Lean compiles and 60 Kani runs maximum. Lean only on host
via existing launchers and assigned attempt IDs; no range has yet been assigned
in the task. Do independent source/extraction work first rather than borrowing
another worker's range. Rust/Kani/extraction scopes: MemoryHigh=6G, MemoryMax=8G,
MemorySwapMax=0, TasksMax<=64, cargo -j4. Retain the stricter existing Lean launcher
cap when required by common rules. Before every heavy launch record populated

No unchanged retry after a memory kill or unchanged regression replay.

# Candidate-only `from_fn` shared-reborrow peephole

This isolated LLBC experiment addresses the Aeneas rejection on the retained Rust 1.98 LLBC at `core::array::try_from_fn_erased`, source span `array/mod.rs:912:30–45`. In the pinned v2 LLBC, stmt 230 copies `Guard.array_mut : &mut [MaybeUninit<T>]` into Local25, and immediately following stmt 231 creates a shared reference through Local25 and reads its pointer metadata. Local25 has exactly three body occurrences: the assignment destination and those two parts of stmt 231. Its type carries Body14; the source field reference carries Body16; the resulting shared reference keeps Body6.

`transform_llbc.py` recognizes only this pinned function and adjacent pair. It removes stmt 230 and rewrites the place bases in stmt 231 to the original `Guard.array_mut` projection. It retains the shared Ref node, its region, kind, metadata and source positions. The type guard expands hash-cons IDs without erasing any nested type or region data; it requires all three outer types to be mutable references and compares their exact referent types. Only the outer reference region is deliberately ignored to admit the Body16-to-Body14 reborrow. The CLI pins the exact LLBC SHA and rejects other inputs unless the explicitly dangerous `--allow-nonpinned-input` switch is supplied; that switch is for local experiments and is not an accepted release mode.

`test_transform.py` passes the pinned positive case and rejects extra Local25 uses, a changed referent type variable, and changed outer mutability. FS also reviewed the matcher against adversarial extra Copy, Move, `len` unwind Copy, Drop, nonadjacent-statement, and mismatched pointer-metadata-base cases; each was rejected. A direct call to the Python structural transform is not a proof of general lifetime validity: an unrelated outer-region mutation is rejected by the CLI input hash pin, not by a general region-validity theorem.

It emitted no Lean files.

The previous same-binary run on unmodified v2 LLBC (input SHA `0186f6da6d3f44d77f49b5abd76b48507635e7a545a54ad63494a0492f1e490e`) failed at the original `Can't copy a mutable borrow` error. This remains a candidate lowering only. It does not alter Rust source, the frozen LLBC, the Aeneas binary/source tree, or any production toolchain.

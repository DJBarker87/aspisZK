# Copy-control quality review

Earlier arbitrary-value assert_ne controls are retained as failed diagnostics but are insufficient by themselves to distinguish a missing/zeroing copy. Forced-nonzero controls replace them before native credit. Positive data proofs are retained.

K056 forces nonzero source/zero destination on every fixed header branch, but Rust assert_eq routes all thirteen through ONE shared core::panicking::assert_failed_inner property. Its single failed property does not certify thirteen independent negative controls. The replacement K059 uses distinct static assert! sites/messages, requiring all13 to fail independently. This is a strengthened control source, not an unchanged proof rerun.

K057 forces row2's final payload byte1 against destination0 and runs the original whole row fission. K058 forces actual inactive=ONE and asserts the incorrect ZERO at the reached serializer receiver. Opening controls force a source root byte1 and old scratchONE, assert wrong zero values, and use distinct assert! sites for each alternative. Constructor control forces selected sem.roots byte1 and asserts wrong returned root0 on the successful-claim branch. All use the exact supplied KMX patch and unchanged dependency/cap/timeout configuration of their paired gates.

An aggregate control is accepted only when EVERY named wrong property fails; a shared panic failure, timeout, unwind error, missing definition or failed safety check supplies no per-case control credit. No whole native bridge is closed by a control alone.

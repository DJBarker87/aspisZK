# Persistent own-scratch module reset

K051 failed for an unqualified live return type. K052 then revealed an inherited NEC_prefix declaration in pair_forest_terminal.rs loading the new tree-profile helper under the old parent. Both are compiler rejections, receive no credit, and caused the serial plan to stop before another launch.

Repair: NEC_patch.py now resets every previously instrumented frozen entry file (terminal, tree, program adapter and program root) on every run before applying only the selected cfg(kani) overlays. This changes no shipped body and does not modify lead infrastructure. NEC_gate.py additionally saves the full source-pin manifest per new attempt, alongside its receipt-pinned hash. Validation remains stricter.

Earlier manifests were not lost: NEC_source_history.py starts from NEC_NATIVE_SOURCE.json's7983 original source hashes, reconstructs every per-attempt patch on frozen4bb3b3f5, updates source entries in the receipt's exact source order, and checks the SHA256 of the complete serialized persistent manifest against that attempt's receipt. NEC_SOURCE_HISTORY.json matches all52 pre-repair native manifests exactly. It explicitly lists inherited instrumented sources and their last-updating attempt. The K001 retained snapshot patch has a different file order, so the receipt's source order (not patch order) is used; every reconstructed Rust byte hash independently matches.

The earlier credited afterstate/static targets and helper bodies are unchanged; the inherited terminal-binding harness is outside their call cone and contains no function-pointer data. The earlier terminal prefix attempts each replaced their own parent, so the stale cross-parent declaration first causes K051/K052's rejected build. No target is renamed, no function-pointer-dependent pass is promoted, and no failing/timed-out result is removed. Reproducible full source histories supplement, rather than replace, exact selected target/tool/GOTO/source/lock/feature pins and intended controls.

# Native scope interpretation

Thirty scopes, all at 6G/8G/swap-zero/64 tasks; native builds use release optimization. Receipt-index values, tool pins, resolved dependency features/profile, input file hashes and binary hashes are retained. All exits are classified and checked in verify_resume13.py.

- Seventeen pinned extraction scopes: exact missing wrappers / root adapters, plus equality isolation. Success does not mean that a requested declaration was emitted: terminal-only extraction is empty and earns no credit. The final scalar root emits semantic at its original owned span; the root that also exports transition is refused for escaping reference output.
- Three matrix scopes: initial own-harness type-inference failure; changed-source positive gate; matched failing store control. The positive gate is arithmetic-prefix instrumentation with an owned prepared-component adapter, plus comparison of final deployed results, not observation inside the deployed function. See matrix-instrumentation.json.
- Six equality/mask scopes: source/value-copy/unrolled equality comparison and failing perturbation; zero-mask source and owned behavior; seventy frozen-mask comparisons and matched failing perturbation.
- One raw-claim terminal scope: forty complete Results, canonical retained points/challenges and raw-u32 claims; finite validation only.
- Three D188/selector scopes: sixteen new owned-emission/native observations; matched failing stored-limb perturbation; the 49-versus-57 selector counterexample. The latter compares the actual native library constructor with the candidate target and is not an op227 counterexample.

There are eighteen zero exits and twelve nonzero exits. Four are matched negative controls; one is the intentionally observed owned-mask panic; seven are extraction/refusal or initial own-harness failures. No failed gate was rerun with an unchanged target/input. Every Lean failed source SHA is separately guarded against resubmission irrespective of dependency changes.

Some copied wrapper `scope`/`purpose` strings retain generic equality/mask wording. The exact command, input hashes, fixture source and assertions determine the scope; these historical metadata strings are retained rather than rewritten. D188 observations check OWNED Rust against its emitted model. Actual shipped-to-owned association and the full D188 cone remain open.

Original target bodies in final D188 fixture copies remain byte-identical prefixes at their original source lines; see fixture-prefix-check.json. Added fixture/root functions are suffixes. Historical input hashes and binary hashes refer to the version actually run; later suffix additions are not retroactively attributed to those binaries.

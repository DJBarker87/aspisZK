# Exact native hypotheses and non-vacuity

The new NativeAssociations10 candidate checks the two exact native predicate
types on their explicit reference dictionaries. These are reference
inhabitation claims, not source-to-native installation laws. It also transports
the inherited primitive false/true carriers to the dynamic reference dictionary.

NativePublic10 uses a Bool → Compiled family. A single compiled argument for
both compiler-call equations could require the same returned public payload
for distinct transfer/withdrawal requests; this design risk was corrected in
the uncompiled draft before any formal credit or attempt. No checked shipped
counterexample is asserted. The reference primitive carriers may keep their
arbitrary compiled parameter because their claims do not include compile_call.

The exact retained types are compile_call (∀ withdrawal, nativeInput.run ... =
ok (.Ok (inputs withdrawal).compiled)), PublicDeploymentAssociation.Association
records inputs, ExternalAssociation.Associated external, and
RecordAssociation.Associated external records. Full words, publicCorr,
admission and row_call remain P. No whole-client success is assumed as a
success witness. Conditional prefix hypotheses still have not been jointly
instantiated on actual native transfer/withdrawal executions.

No endpoint premise, trust field, deployment condition, quantifier or failure
model is weakened. The selected outer dictionary remains explicit; these
source equations do not establish arbitrary ExternalFuns native association.
All seven actual universal exclusions and complete minimal reached sets remain
open unless later receipts and a source invocation certificate establish them.

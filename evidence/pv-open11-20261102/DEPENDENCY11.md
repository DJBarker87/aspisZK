## Meaning of the map

The unit counted is restoration of the existing ledger row at its recorded scope, not an arbitrary helper lemma. Tags name necessary shared interfaces, not sufficient proofs. Row-specific work remains in the last column. Tags are not inferred merely because every row eventually feeds the same release: for example a local callback can be bound before final replay, whereas V397 itself requires that replay. Conversely a full native joint-law row cannot be restored by proving only its local arithmetic.

- **a**: pv-evh native event world: actual carriers/ownership, stateful answers, ordered failure/abort/Drop/resource prefixes and the same full observer. This includes the missing native frame needed to install I/O leaves; evh does not by itself supply each leaf's decoder.
- **b**: pv-uc full user-client extraction, bindings, entry/caller/upload association, adopted configuration and gates (including whole-client measurement).
- **c**: op227 / V244: complete `DeployedWrapper557`, not merely its 36 local associations.
- **d**: op257 / V263: actual selected host_work map, stateful thread/resource answers, complete returned values and ordered merge/failure behavior.
- **e**: runjoin publication links and fixed actual-domain `Nonempty P`. Publication still needs CommonSample, BackendInput, FinishContext, QueryAppend, NodeAppend and PublishOrder; a model product carrier or op227 alone is insufficient.
- **f**: Stream A coherent NER_ replacement of the D565 NDR cohort, followed by the appropriate dependency replay/NEP audit. Successful imports of the incoherent cohort are not evidence.
- **g**: V370 compiler-cohort/intrinsic transfer or a K-3 suspension. This does not include V371's separate CPU latency trust.
- **h**: row-specific only, with no shared a–g prerequisite at that row's scope.

For rows tagged e, c and d are also counted: restoring the actual conjunction/non-emptiness cannot use the D564 counterexample where op257 diverges, nor assume the missing deployed op227 wrapper. This is a dependency closure, not a claim that every local source helper directly calls both operations. The source-only work in those rows can still proceed separately, without ledger-restoration credit. Counts overlap.

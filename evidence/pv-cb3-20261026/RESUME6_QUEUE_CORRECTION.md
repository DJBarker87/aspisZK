# Native queue status correction

The first native queue read GNU-time exit statuses as strings (`"0"`), then compared them with integer0. It therefore advanced to the next op after successful Charon instead of entering Aeneas. No failed compiler was rerun and no extraction result was credited as a source law. Successful Charon receipts for op253-owned,219,216,212,133 are retained and reused.

op132 was admitted at the preliminary snapshot but refused by the inside-scope barrier after another reservation appeared. Its GNU-time/compiler exit is null, attempt_charged=false. The queue now classifies this as an uncharged reservation refusal (orchestration78), observes the recorded180s cooldown, and uses a fresh run suffix. The original null exit and full barrier output remain retained.

The corrected queue converts actual charged exit strings to integers and tests attempt_charged before deciding whether a compiler ran. No scope, cap, source target, or shared barrier was modified.

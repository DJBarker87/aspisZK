## Specialization or restriction?

Mathematically this is universal elimination on the implementation configuration: a specialization of a more general theorem. It restricts the range of implementation dictionaries to the constructor's image. It imposes **no additional restriction on the adversary, input bytes, game or oracle schedules**. Thus choosing source code is the appropriate kind of specialization for a deployment theorem, rather than a weakened attack model.

However, the constructor still has six unresolved data inputs. Its name does not prove that the live deployed system uses those choices, and some fixed components are explicit reference/value models rather than a newly certified native implementation. Calling this a completely determined deployed configuration would overstate the evidence. It is a **partially installed source configuration family** whose connection to actual deployment remains conditional on extraction and the D188/P6/P7 obligations.

Unlike the already adopted ARX move to an induced prover/runtime image, this packet changes neither headline ownership nor experiment construction; it instantiates one remaining implementation parameter. It cannot use ARX's adoption as authorization to claim new source/binary correspondence or remove FIp_GlobalOwners. The six residual records/outcome must be identified with the runtime/extracted implementation (or proved irrelevant field by field), and their dependent extraction certificates must apply to this same installation.

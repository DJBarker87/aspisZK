## Boundary and proposal

The [inventory](../evidence/pv-n7-20261027/INVENTORY.md) lists all request
fields and their encoding. Contrary to the initial task description, private
witnesses are not supplied as request JSON integers. `plan::note` constructs
public fixture witnesses internally. Only the signing route loads secret
key bytes from decimal JSON files. `Client64_proof_accounts.py` passes public
addresses, snapshots and metadata, and retains its key files.

The proposed patch changes the Python writer and standalone Rust host binary.
Python keeps the Solana JSON files intact, parses them locally and sends each
64-byte keypair as a raw fixed-width record over one inherited pipe, in the
public `keys` path order. Existing request fields remain unchanged; a public
`key_bytes_fd` integer identifies the separate channel. Neither entropy nor
private witness fields are added to request JSON. There is no decimal-parser
fallback in patched Rust. Action=prove remains unchanged.

Raw bytes are the task's permitted alternative to lowercase hex. Consequently
there is no hex alphabet validation or hex-decoder content branch. Rust reads
exactly 64 bytes per public key count, then checks public EOF/length shape.
The named raw decoder is a fixed copy of all 64 bytes. Keypair consistency
validation still runs afterwards and is a separate obligation.

### Disassembly classification

[Actual decoder instructions](../evidence/pv-n7-20261027/host/decoder-disassembly.txt)
at `0x92f80–0x92f9e`: four MOVUPS loads from `[rsi+0/16/32/48]`, four MOVUPS
stores to `[rdi+0/16/32/48]`, RET. The following INT3 is alignment padding after
RET. No Jcc, CALL, table, DIV/IDIV, secret-indexed address, or content-validation
predicate occurs in this body. RET uses the caller's return address, independent
of key bytes. **L3 classification: clean fixed schedule/addresses for this slice;
V371 CPU latency retained.**

The [real caller](../evidence/pv-n7-20261027/host/decoder-callsite.txt) invokes
`default_read_exact` with public length `0x40` at `0x9344d`, branches on its I/O
result at `0x93455`, and calls the decoder at `0x93461`. Keypair validation
follows at `0x93476`. Those I/O/validation outcomes are not reclassified as a
whole-loader constant-time theorem. The decoder's public pointer/length
provenance follows directly from the fixed stack array and public key-count loop.
Display excerpts trim trailing whitespace; raw full objdump bytes are unchanged.
Full objdump SHA/size and executable binding are in
[decoder.json](../evidence/pv-n7-20261027/host/decoder.json); the full dump remains
on the host. Historical L3 audit PCs are not reused for this new binary.

## Ruling (l): release reachability and ELF gate

The modified Rust file is `tools/r1-cost-probe/src/bin/devnet_spend.rs`, a binary
of the standalone `[workspace]` package `aspis-r1-cu-probe`. It is not a module
in `crates/aspis-r1-cost-probe/src/lib.rs`; that library has no import/path edge
to this binary. Dependency direction is host binary → library, with `prover`
enabled; it is not library → host binary. The Python file is not a Rust input.
No shared library module is changed, gated or ungated.

This matters because the default/devnet ELF is built from
`programs/r1-cost-probe`, whose dependency on the cost-probe **library** enables
`optimized-terminal,program-build`; it does compile the library's ungated
modules. The proposed patch touches none of them. The CT/prover modules in
lib.rs are separately guarded, and `ct-host-prover + program-build` is rejected
by compile_error. Pool and registry depend on statement/core, not the standalone
host binary. The [gate source excerpts](../evidence/pv-n7-20261027/host/ruling-l-source.txt)
retain both manifests and the actual lib.rs gates. Source comparison confirms
zero changes under crates/ or programs/, before and after fixtures. No dependency
edge from a release program into the standalone host tool exists; this claim
uses the standalone binary/module location and dependency direction, not merely
the library crate's name.

## Residuals and obligations

Python still parses variable-width decimal secret integers, creates bytes,
buffers the pipe and retains secret-bearing JSON files. Its parser, allocation,
threading, memory lifetime, storage and OS I/O traces need observer treatment;
this proposal moves that handling before the Rust boundary. Python records and
Rust stack buffers/copies are not newly guaranteed to be zeroized. Public path/count,
channel scheduling, partial reads, interruption/error paths and process failures
remain observable. The proposal is Linux-specific (`/proc/self/fd`).

Keypair validation and Ed25519 signing retain their existing audit obligations.
The fixed copy's CPU instruction latency remains V371; branch-free does not
establish whole-program constant-time behavior. No broader L1/L2/L3 closure,
OS witness-independent failure theorem, or same-public experiment theorem is
claimed. No premise of `PrivacyR1HeadlineDeployedReal.privacy_headline_deployed`
is removed, added, weakened or moved into T. V360/V373/V396 remain P obligations.
No new Lean statement is needed for this native preparation (0/20 Lean, 0/0 Kani).

Next deliverable: lead/owner review of this exact patch and boundary policy,
followed only after adoption by integration into the pinned client recipe and
complete client/signing/storage observer validation. Target not yet established.
